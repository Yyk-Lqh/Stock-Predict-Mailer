# 办公室对话栏（2026-11-13）

参考用户提供的 Codex 截图，对话栏分为输入区和底部工具栏。保留全屏办公室、浅深主题和已有对话记录。

- 左侧加号打开资料菜单，可以填写预测与客观事实，或调用现有 JSON 导入入口。
- 盾牌显示「仅分析」或「授权邮件」。菜单与原有通知开关、收件地址同步；服务端邮箱授权清单继续生效，不新增自动批准工具的权限。
- 模型菜单只列出已启用的实际模型配置。用户选择后更新工作台默认模型，供后续分析使用，保留各角色的独立配置；未配置模型时提供管理入口。
- 推理滑杆支持轻度、中、高、极高、Ultra，写入本轮 `task-effort`。恢复默认会沿用设置中的默认档位；原生模型参数仍取决于配置的强度映射。
  拖动时滑块连续移动，预览按动画帧合并刷新；松手或收起面板时才提交一次档位，避免每次移动触发表单重算和输入框布局。方向键、Home/End仍按实际档位选择。
- 麦克风使用浏览器的 `SpeechRecognition` 或 `webkitSpeechRecognition`，由用户点击后启动，识别文本进入原输入框。不支持时按钮禁用并说明原因；麦克风授权、识别服务可用性由浏览器决定。语音识别不在本机后端实现。
- 蓝色上箭头仍为原表单的提交按钮；Enter 发送、Shift+Enter 换行和中文输入法保护继续生效。任务进行时保留停止任务入口。

实现位于 `web/modules/composer-controls.js`，使用原有模型设置、推理控制、通知授权和任务 API。`scripts/build_console.py` 将其放在对话栏模块之后加载。启动等待 DOM 解析完成，避免本地 API 提前返回时漏掉工作台初始化。

验证：在 `tests/browser_console_fixture.py --port 8768` 隔离服务中，通过 gstack `/browse` 运行 `tests/browser_composer_controls.js` 和 `tests/browser_analysis_input.js`。前者覆盖模型落库、保留角色配置、强度同步、邮件权限及资料菜单；后者完成真实 Mock 分析并检查消息和结构化参数。另检查 1440px 桌面与 390px 手机布局。未测试真实麦克风录音，未调用外部模型或真实 SMTP。

控制台单元回归 `test_control.py` 共44项通过；JS语法、Ruff、bundle一致性与仓库卫生检查通过。
