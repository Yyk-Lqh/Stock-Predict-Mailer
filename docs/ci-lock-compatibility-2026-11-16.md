# Linux 迁移检查的锁兼容修复

最终发布提交 7e989b8 的 CI 在 Ubuntu 基础环境及 Python 3.11/3.13 完整测试中失败。前两批提交对应运行被后续推送的并发策略取消，不能把取消当作最终版本验证成功。

根因是只读 lock_state 对所有零字节锁文件直接返回 unknown。Linux 采集 workspace_lock 使用 flock，合法锁文件可以是零字节；首次备份的停写屏障创建该文件后，后续迁移预检将其误报为 BACKUP_WRITER_BUSY，因此 23 项迁移测试和 5 项预检测试失败。Windows 采集锁会写入一个锁字节，本地未覆盖到 Linux 的这个路径。

修复仅对 Windows 保留零字节锁的 unknown 判定；POSIX 始终实际执行非阻塞共享 flock 探测。空闲时 available，写入者持有排他锁时 busy，未知错误仍保守拒绝，不创建或改写锁文件。

补充跨平台模拟 POSIX 的回归用例，先证实旧实现失败，再验证空闲/占用两种结果和文件字节不变；已有空文件断言改为平台对应语义。最终效果以修复提交的 GitHub CI 矩阵结果为准，不重写原提交或篡改历史检查状态。未执行真实迁移或重启用户服务。
