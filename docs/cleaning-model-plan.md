# 清洗模型实施计划

本迭代只做后端，沿用私有访问密钥；不改股票预测模型、行情训练快照、邮件或前端。

1. 清洗模型配置独立于 Embedding 与分析角色。支持 OpenAI 兼容 /chat/completions 和 Ollama /api/chat，默认关闭。凭据加密且不回显；远程请求需 HTTPS 和单独外发许可。限制文档调用数、输入长度、输出 token、总时长与费用预留；服务配置变更需防止旧凭据被带到新地址。
2. 模型只能返回严格结构化候选：实体、关系、事件、财务指标；每个候选必须含片段编号、逐字引文、精确字符区间、原始数值/单位/周期及明确的肯定/否定/不确定状态。程序检查原文定位、主体及数值是否确实存在；日期不能冒充文档发布日期，单位不自动换算。结构正确不等于事实已证实。
3. 模型候选、验证错误、模型身份与提示词版本持久化，保留原始文件和规则清洗结果。默认全部需人工批准；模型没有权限直接覆盖片段、定义已验证事实或运行工具。无依据候选不可批准；修正原件应生成新版本。
4. 复核接口按用户隔离，提交候选 ID 与审阅批次摘要，防止过期批准。批准后由 worker 发布；拒绝的候选不进入关系检索。否定与不确定关系作为有来源声明保存，不能用于肯定的供应链推断。失败、中断、待复核均保留旧活动版本；重试不重复已完成的模型步骤。
5. 关系/事件携带来源、发布日期、数据周期、事件发生时间与有效期，不自动变成行情训练数据。默认回答优先保留证据摘录，条件性风险推断只使用已批准、肯定且日期明确的关系与事件。
6. stdlib unittest 覆盖协议、配额、格式错误、伪造引文/数字、否定/传闻、日期与单位、审批隔离、版本保留、取消/失败、重试与删除。建立小型人工标注的合成验收集；它只验证工程约束，不能替代真实公告与实际模型准确率评估。

完成以上闭环后，再以真实资料评估是否增加 OCR/布局识别、重排序或图数据库。本轮不自动下载模型，也不调用未配置的外部服务。
