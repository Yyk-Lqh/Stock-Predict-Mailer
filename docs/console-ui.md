# 控制台界面说明（2026-11 改版）

本文描述 `src/stock_predict_mailer/control/web/` 当前界面。字段与接口契约见 [control-api.md](control-api.md)，
业务边界见 [frontend-handoff.md](frontend-handoff.md)。改版只动前端三个文件，未改任何后端行为。

## 改版要解决的问题

旧版把五个配置页平铺在导航里，用户点进来第一眼是「模型服务」表单；
而 `orchestrator.py` 在无默认模型时直接返回 `MODEL_REQUIRED`，所以新用户按直觉提交必然失败。
现在把顺序改成：**先看懂 → 先跑通 → 再配置**。

## 导航

```
概览    ← 默认页：这个工具做什么、不做什么、三步进度清单、当前环境
分析    ← 填一份预测，读一份报告（90% 的操作在这里）
记录    ← 跑过的任务，按时间倒序；点一行回到那份报告
设置    ← 模型服务 / 外部工具 / 协作与邮件（三个子页）
记忆    ← 访问密钥、会话、长期记忆
```

- 概览页的「三步」是可勾选的清单，不是说明文字：

  | 步骤 | 完成判据 | 未完成时的下一步 |
  |---|---|---|
  | 有一个默认模型 | `settings.default_model_id` 指向一个 `enabled` 的模型 | 「去配置模型」→ 设置 / 模型服务 |
  | 填一份预测 | 表单里标的非空、有效期可解析且晚于现在 | 「去填写」→ 分析页 |
  | 拿到一份报告 | `GET /api/tasks?order=desc&limit=1` 最近一条为 `completed` | 「去跑一次」→ 分析页；已完成时「查看报告」 |

  三个状态全部从真实数据派生，**没有手动勾选、也没有本地存储的完成标记**：删掉模型后第一步会自己变回未完成。
  第一个未完成的步骤用实心按钮突出，其余是描边按钮；计数（`2 / 3 已完成`）跟着变。
  表单里若还是内置的 `DEMO.SZ` 示例值，第二步会写「示例值，可以直接提交」，免得用户以为系统替他填了什么。
- 概览页的「当前环境」四行由 `GET /api/settings` + `GET /api/models` + `GET /api/mcp` 派生，不写死。

- 「用示例预测试一遍」会按需自动创建 Mock 模型并设为默认（`POST /api/models` + `PUT /api/settings`），
  然后填入示例预测、两条事实和一个 `chart_data`，把用户送到「提交分析」按钮前。
- 切换视图会把名字写进 hash（`replaceState`），刷新后停在原页面；也支持 `#analysis`、`#records`、`#models`、`#mcp`、`#collab` 深链。

## 分析页

表单优先，收敛成三个区块，必填项只有标的、方向、周期、有效期：

| 区块 | 内容 |
|---|---|
| 预测 | 标的、模型版本、方向（三段控件）、周期长度 + 单位、置信度（可留空）、有效期、synthetic |
| 客观事实 | 可增删的行：编号自动生成，名称 / 数值 / 单位 / 来源 / 观测时间 |
| 运行与通知 | 复杂度、分析目标、推理强度、通知开关、收件人 |

- 置信度留空时提交 `null`，报告写「上游未提供」，不估算、不折算胜率。
- 事实的 `available_at` 与 `observed_at` 同步取「观测时间」，避免出现「尚不可用」的自我矛盾。
- 原始 JSON 收进「高级」折叠区，与表单双向同步；提交时以 JSON 为准（与旧版行为一致，
  `记忆` 页的「沿用上轮输入」仍依赖把 JSON 置为 `{}`）。
- 表单任何字段改变都会重算 JSON，并保留已存在的 `chart_data`，避免编辑表单后图表消失。
- **草稿**：表单输入会以 400ms 防抖写进 `localStorage`（键 `spm.console.draft.v1`），刷新或切页后自动回填，
  顶部出现一条浅绿提示「已恢复 … 的输入」，右侧可「清空，从头填」。草稿里存的是提交用的 JSON 加上通知/收件人/复杂度等运行选项。
  恢复时会检查 `valid_until`：已经过期的按当前时间顺延两天，否则提交必然被上一级校验直接拒绝。
  提交成功后再写一次草稿（作为下次的起点），但提示条不再出现——它已经不是「未提交」状态。
  隐私模式下 `localStorage` 写不进去时静默降级，不影响提交。

## 失败任务

失败时不再只给一个错误码。`ERROR_HELP` 表把服务端返回的 code 翻译成「人话标题 + 原因 + 下一步能点的按钮」，
原始 `CODE · message` 以等宽小字留在下面供排查：

| 错误码 | 界面说法 | 给的出口 |
|---|---|---|
| `MODEL_REQUIRED` | 还没选默认模型 | 去设置模型 / 用示例跑一遍 |
| `INVALID_INPUT` | 提交的内容没通过校验 | 回到表单检查 |
| `TASK_TIMEOUT` / `CALL_TIMEOUT` | 超过任务时限 / 上游调用超时 | 重新提交 |
| `BUDGET_EXHAUSTED` / `STEP_LIMIT` / `DEPTH_LIMIT` | 触到费用、步数或深度上限 | 去调整限制 |
| `PERMISSION_DENIED` | 这一步没有权限（多半是收件人不在授权清单） | 去检查授权 |
| `SECRET_CONFIG` / `INVALID_CONFIG` / `PARAMETER_UNSUPPORTED` | 模型的密钥、配置或参数不被接受 | 去设置模型 |
| `INTERRUPTED` / `INTERNAL_ERROR` | 进程重启打断 / 内部错误 | 重新提交 |

表里没有的 code 退回「任务失败 + 原始错误 + 回到表单」，不编造原因。

## 记录页

`GET /api/tasks?order=desc&limit=30` 分页，首屏 30 条，底部「载入更早的记录」用返回的 `next_before` 续取。
每行六列：提交时间、标的 + 方向（涨红跌绿）、周期、状态、邮件、查看。

- 顶部一排筛选：全部 / 进行中 / 已完成 / 失败（含已取消），右侧按标的或错误码搜索。
  筛选与搜索都在**已载入的记录**上做，因此计数写「筛出 3 条 · 已载入 30 条」；没命中时提示可以继续载入更早的记录。
- 标的与方向优先取 `metadata.request`（提交时的回显），旧任务退回到产物里的 `analysis.prediction`。
- 失败任务在周期列显示错误码（如 `MODEL_REQUIRED`），悬停给出完整原因；点进去是上文的失败说明与出口。
- 有 `submitted`/`working` 的任务时每 3 秒自动重取一次；点击某行会把任务载回分析页并继续轮询。
- 不带 `X-Memory-Key` 时列表只含独立任务，会话任务仍从「记忆」页进入。

## 运行图（生成分析时的实时反馈）

任务一旦提交，`#task-progress` 先出现一块运行图，然后才是执行计划与事件流：

| 元素 | 回答的问题 | 数据来源 |
| --- | --- | --- |
| 状态点 + 文案 | 现在是什么状态 | `task.status.state`（`submitted` / `working` / 完成 / 失败 / 取消） |
| 已运行 | 跑了多久 | 首个事件时间戳起算；回看历史任务时没有可信起点，显示 `—` |
| 事件 / 阶段 | 收到多少条事件、几步已完成 | `/events` 累计条数与 `status=completed` 的步数 |
| 分段轨 | 跑到哪一步 | `event.steps` 的顺序，每步一段；待执行灰、运行中黄铜扫过、完成实心、失败红 |
| 事件节律 | 还在动，还是卡住了 | 每次轮询新增事件数，最近 60 个采样（约 30 秒）的柱状图 |

- 全部数据来自已有的轮询与事件流，**不新增请求**；结束（完成 / 失败 / 取消）后停止动画并定格，供回看。
- 运行中只更新已有的 DOM 节点（`dataset.status`），不重绘分段轨，避免每 700ms 闪一下。
- 窄屏下统计行换行到第二行，分段轨与阶段名保持等分，不横向滚动。

## 报告

按固定顺序渲染，不再把产物丢进 `<pre>`：

1. 抬头：标的 + 方向（涨红跌绿）、周期、模型版本、有效期、是否 synthetic
2. 上游预测：方向 / 置信度（空值用虚线槽）/ 预测值
3. 客观事实：编号、名称与数值、来源 + 观测时间；注明「来源是上游声明，系统未核实」
4. Agent 推断：左侧编号列，正文里的 `F-01` 可点击回跳对应事实
5. 建议 / 风险 / 限制与未知
6. 降级说明（仅 `analysis.status=degraded` 时出现）
7. 已排除的冲突（独立成块，不并入结论）
8. 协作与用量：参与角色与各自状态、调用次数、费用预留（标注「非账单」）
9. 邮件回执：状态中文名 + 原始状态码 + 下一步说明

抬头下方是一行章节导航（上游预测 / 客观事实 / Agent 推断 / 建议 / 风险 / 限制与未知 / 协作与用量 / 邮件回执）。
按钮用 `scrollIntoView` 跳转，不改 URL，也不与「静默刷新报告」的轮询冲突；跳到的区块短暂加深底色便于定位。

三组状态在报告顶部用一行文字表达（任务 / 分析 / 邮件），不合并成一枚胶囊：

| 状态 | 含义 |
|---|---|
| `simulated` | 写入本地文件，**不代表对方收到** |
| `submitted` | 服务器或工具已接受，不保证最终送达 |
| `uncertain` | 可能已产生外部效果，**不提供自动重发** |
| `degraded` | 已完成但部分角色失败，结论由主 Agent 补写 |

邮件状态为 `uncertain` 时，回执块直接给出「确认已送达 / 确认未送达」两个按钮（`POST /api/tasks/{id}/mail/resolve`）。
确认只更新回执状态，不重发、不改报告正文；要重发必须重新提交一次任务。

## 视觉约束

高黑（石墨）方向：深色底 + 发丝级描边 + 单一黄铜强调色。不用发光、不用彩虹渐变、不用彩色胶囊。

| 层 | 值 | 说明 |
| --- | --- | --- |
| 页面底 `--void` | `#07080a` | 顶部有一层极轻的冷光，强度低到不构成渐变特效 |
| 卡片 `--surface` | `#0d0f12` | 卡片用 `inset 0 1px 0 rgba(255,255,255,.04)` 做一条顶边高光，代替投影 |
| 输入 / 内嵌块 `--surface-2` | `#12151a` | 与卡片区分，聚焦时升到 `--surface-3` |
| 文字 | `#e9e7e2` / `#a6a7a4` / `#787b80` | 主 / 次 / 辅助三级，辅助色对深底仍保持 ~4.4:1 |
| 描边 | `rgba(255,255,255,.075)` / `.16` | 分隔线 / 控件边框 |
| 强调 `--brass` | `#c3a97a` | 只用于主按钮、当前步骤、当前导航、链接与运行中状态 |

- 涨跌按 A 股惯例：涨 `--up` 红、跌 `--down` 绿，深底上提亮一档（`#d3594d` / `#55a37c`）。
- 层次靠明度差与 1px 线，不靠阴影堆叠；`--rule` 只有一档，避免“卡片雨”。
- 视图切换用 4px 位移 + 55%→100% 的淡入，200ms；起点不设 0 透明度，动画被节流时内容仍可读。
- 真实控制台 CSP 为 `style-src 'self'`，**禁止内联 `style` 属性**，所有间距走 `style.css` 里的 `.mt-*` 等工具类；
  JS 里只用 `el.style.foo = …`（CSSOM 不受 CSP 限制）。
- 静态白名单仍是 `/`、`/app.js`、`/memory.js`、`/style.css`，没有新增资源路径。
- `prefers-reduced-motion` 下关闭全部过渡与动画（含运行图）。

## 不连后端预览

```powershell
python scripts/console_preview.py --port 8790
# 打开 http://127.0.0.1:8790
```

`scripts/console_preview.py` 用内存假数据应答 `/api/*`，不需要 `STOCK_PREDICT_MAILER_MASTER_KEY`、不读写工作区，
用于核对布局与状态语义。附加参数：

- `?demo=1` 自动点「用示例预测试一遍」并提交，用来查看完整报告；
- `?demo=1&focus=1` 额外隐藏表单，只留报告；
- `?demo=1&unc=1` 把收件人换成 `DEMO.UNC`，查看邮件「结果未知」的回执与确认按钮；
- `?fresh=1` 模拟全新安装：没有模型、没有外部工具、没有历史任务，用来看首屏三步清单的 1/3 状态
  （开关记在进程里，请求 `?fresh=0` 复位）；
- `?allow=ok|bad|empty` 直接打开设置页并填好收件人清单，用来核对清单复述的三种语气；
- `?demo=1&hold=1` 让任务永远停在「运行中」（前三个阶段完成、风险分析进行中），用来看运行图的动画；
- `/__frame?w=390&q=…` 用同源 iframe 把页面压到任意宽度（Windows 无头窗口有最小宽度，`--window-size` 压不下去）。

它**不是**验收环境：真实任务的失败分支、邮件 uncertain、预算耗尽等仍以真实后端与测试为准。

## 设置页的未保存保护

任何一次保存（模型、MCP、外部 Agent）都会 `refresh()` 重绘角色行与下拉，此前逐字敲进去但没保存的编辑会被覆盖。
现在 `#settings-form` 上的输入会记进快照，重绘后按元素 id 原样放回，并在提交栏显示琥珀色「有未保存的修改」；
保存成功、点「恢复默认温度」或离开页面确认后才清空。外部 Agent 小表单不参与快照（它本身不随渲染重绘）。

## 邮件授权清单的复述

`mail.recipient_allowlist` 是一个按行填写的纯文本域，光看内容看不出「现在到底谁能收」。所以在文本域下方
用一句话复述当前规则（`#allowlist-summary`），并紧跟一句 synthetic 开关的后果：

| 状态 | 复述 | 语气 |
| --- | --- | --- |
| 清单为空 + 本地文件投递 | 清单为空：本地文件投递不限制收件人，信只落在工作目录里，不会寄出。 | 中性 |
| 清单为空 + SMTP / MCP | 清单为空：这里不限制，任何地址都能收到报告。换成真实通道后建议逐行填上。 | 琥珀 |
| 1–2 个地址 | 只寄给 a@…、b@…。 | 中性 |
| 3 个以上 | 只寄给 N 个地址：a@…、b@… 等，其余一律拦下。 | 中性 |
| 有不符合邮箱格式的行 | bad.example.invalid 不像邮箱地址，这样的地址一个都收不到信。 | 红 |

句式由 `allowlistSentence()` 统一生成，概览页「邮件通道」那一行的说明也调用它，两处不会各说一套。
格式规则与服务端 `delivery.address()` 一致；保存前会拦下不合规的行并点名，避免「填了清单却静默发不出」。
复述只报地址原文、不报行号：文本域的空行会被忽略，行号与实际行不一致反而误导。
复述只是说明，不改变权限：权限始终以服务端的 `recipient_allowlist` 精确匹配为准。

## 已知未做

- 子 Agent 的中间任务与主任务同表（`contextId` 指向父任务），记录页与概览的「最近一次任务」都只认
  `contextId === id` 的主任务；否则每跑一次分析会多出三条没有标的的空行。
- 记录页的筛选只在已载入的页内生效，服务端没有 `state` / `subject` 过滤参数；记录也没有删除与导出。
- 草稿只有一个槽位，不区分标的；换一只股票填到一半时，上一条草稿会被覆盖。
