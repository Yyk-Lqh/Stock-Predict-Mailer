# 模型、MCP、A2A 与配置控制台开发计划

## 架构与默认决策

继续使用 Python，新增仅监听 127.0.0.1 的原生 HTML/JS 控制台和 JSON API，不将旧上传页面改成管理入口。配置存在独立 SQLite；凭据以 Fernet 加密，主密钥仅从 SPM_MASTER_KEY 环境读取，缺失时拒绝启动，不生成与数据库放在一起的明文密钥。GET 永不返回密钥，更新时空值表示保留，显式清除用独立操作。控制台具有 Host/Origin 验证、会话 Cookie 与 CSRF 保护。

模型服务使用兼容 OpenAI Chat Completions 适配器，提供 Mock 和真实请求；配置明确声明模型支持的温度范围与生成参数，不从服务商名称猜测能力。连接测试实际执行小请求，不把列模型成功当作推理成功。默认温度 0.2，可按主/预测/风险/建议 Agent 覆盖；不支持时不发送 temperature，错误覆盖拒绝。参数兼容性以服务能力声明及实际测试共同判断。

MCP 优先使用官方 Python SDK，支持 stdio 与 Streamable HTTP；发现工具和资源，工具输入/输出验证，默认无调用权限，逐工具/资源白名单。stdio 不使用 shell，命令参数独立配置，进程由 SDK 上下文回收，环境变量最小化。HTTP Bearer token 加密保存。不把普通 HTTP API 假装为 MCP；普通行情/邮件 API 继续经普通适配器接入。

A2A 实现明确版本的 JSON-RPC 非流式 message/send、tasks/get、tasks/cancel 及 Agent Card，支持本机角色 Agent 与外部端点。编排层决定创建、调用、取消和回收，不由 A2A 协议代替调度。子任务只收到所需预测、事实和工具引用，不获得凭据；MCP 执行仍由后端权限层控制。默认至多 3 个子 Agent、委派深度 1、有限超时/调用次数/美元预算；简单任务直接完成。真实模型调用按配置价格与最大 token 预留费用，未知价格禁止计费调用；重试也计入预算。不是计费服务实际账单保证。

输出仍采用有依据的代码与证据 ID；主 Agent 验证子结果的状态、角色、证据、预测方向和不确定性，冲突或失败明确降级，不直接拼接自由文本。邮件始终经过确定的收件人授权、内容校验和既有 outbox；MCP 邮件仅能调用预先授权的特定工具和收件人，发送结果不确定不自动重发。

## 实施顺序与验收

1. 配置模型、加密凭据、温度覆盖和预算契约，提供 CRUD、默认恢复和连接测试。
2. MCP SDK 连接、发现、调用、资源读取及工具/授权验证。
3. A2A 协议、受限编排、持久化状态、结构化结果与冲突处理。
4. 本机控制台与配置/任务 API；Mock 模型 + 真正 MCP Mock 服务 + A2A 子任务 + 本地邮件投递闭环。
5. 测试无效凭据、服务不可用、参数不兼容、超时、预算耗尽、越权邮件、提示注入、密钥脱敏；回归旧功能，浏览器验收控制台。

本阶段不增加公网部署、多租户、自动收费或无限自治；模型、工具和邮件授权由用户配置界面明确控制。现有数据、模型、凭据均不迁移或删除。
