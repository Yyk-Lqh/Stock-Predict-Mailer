# 第四阶段 A：持久化采集任务（2026-11-15）

用户授权继续规划并实施下一步。第四阶段拆为 A（采集长任务）和 B（MailCore 提取及显式迁移），本轮完成 A。B 沿用 mail-core-plan.md，仍未实施，也不自动迁移/发送邮件。

## 步骤与验收

1. 标准库 SQLite 保存任务、参数、状态、尝试次数、进度、事件和股票检查点。提交只入队，不联网；读取状态不创建文件。可选 request_key 去重，同 key 不同参数拒绝。
2. 通过独立 Worker 进程执行两类已有采集器。Worker 需要显式启动，不随 MCP 服务启动。提供 --once 与连续轮询；一次只领取一个任务。采集依赖只在执行时加载。
3. 所有正式采集入口共用同一数据目录的 OS 文件锁，包括旧同步函数。Worker 在取得锁后才能恢复/领取任务，进程退出由 OS 释放锁；不能凭 PID 或超时抢占仍在运行的采集器。
4. 任务状态 queued/running/cancelling/completed/partial/failed/cancelled/interrupted。取消是持久请求，在每次请求/季度/股票边界及等待期间检查；在途请求仍受原网络超时约束。取消保留已提交文件，不承诺撤销已发出的网络请求。
5. 基本面首轮冻结股票池 SHA256、截止日、选定股票、增量季度及原有股票集合；每只成功股票在文件保存后记录检查点。恢复重用冻结计划，跳过确认完成股票，只补失败/未处理股票。目录来源是动态分页，恢复重新取整个快照，不复用旧的半页结果。
6. 检查点绑定最新输出 CSV 摘要。资料缺失、损坏或被其他任务改写时，恢复明确停止，不能把存在检查点理解为数据已存在。文件与 SQLite 没有分布式事务：在两者间精确崩溃可能需要人工核对，保持拒绝不一致数据的原则。
7. Worker 持锁时发现遗留 running/cancelling，改为 interrupted/cancelled，不能自动重新采集。显式 resume 才重新入队；成功任务不可重启为同一次任务，需新建任务。恢复不会自动重新授权过期来源，冻结计划且输入哈希相同才可沿用原股票选择。
8. CLI 与 MCP 增加 submit/list/status/events/cancel/resume 管理能力；保留旧同步工具。测试使用合成采集器、临时目录与本机子进程，覆盖重启、互斥、取消、检查点、去重和协议，执行全量回归及基础 wheel 验证。

## 范围与实现约束

- 不引入外部消息队列、服务框架或后台系统服务；独立 Worker 隔离 baostock 全局 socket 配置与采集日志，不让新任务路径在 MCP 线程内执行采集。旧同步入口仍保留其原依赖行为，但加入互斥。
- OS 锁取得后才执行 SQLite 领取/恢复，随机 ownership token 防止旧执行者写回新尝试。状态查询不杀进程；取消不会根据可复用的 PID 终止其他程序。
- 原始质量、出处、路由和 run_complete 限制继续生效；部分结果不能被任务状态包装成完整成功。无真实采集/模型调用/SMTP 验收。
- CLI 复用 stock-predict-mailer-crawler 的 jobs/worker 子命令，不新增发行名或脚本别名。工作区仍由 STOCK_PREDICT_MAILER_CRAWLER_WORKSPACE 指定。
