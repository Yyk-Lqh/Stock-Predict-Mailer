# 第二阶段：数据时间与完整性（2026-11-15）

用户已授权规划下一步并开始实施。本阶段延续优化路线第二步，保持主控制台与现有数据不受自动迁移影响。

## 实施步骤

1. 增加纯标准库质量契约：上海时区当天、明确 ISO 日期、带时区时间戳、结构化错误、有限数值、代码校验与原子写入。
2. 目录缓存改为版本化快照，保留来源、抓取时间、来源时间（未知留空）、预期/实际数量、分页完整性。默认缓存有效期 300 秒；过期/旧版未知时间仅显式 allow_stale 可读取，并标记 unsuitable for analysis。过期不自动强刷，避免意外触发限流。
3. 分页按唯一代码计数，总量变化、重复导致缺口、空页和后续页失败一律不能发布完整股票池；异常数值、缺字段和错误证券代码拒绝。失败不得覆盖已有 CSV/缓存。CSV 与元数据用哈希绑定，单文件原子替换，中断导致不匹配时下游拒绝使用。
4. 默认基本面截止日期采用上海当天；显式 end_date 只代表截止日。按季度末和披露日期过滤导出独立截止日视图，不删除主 CSV 中更晚记录；未知披露日期不进入视图。合并多张表时任一含数值的表缺披露日期，不将该行视为可验证披露。
5. 增量读取损坏旧文件不再静默从头开始；保留数值缺失与无效数值的区别。采集被限量/中断/失败时明示部分完成，已有数据存在不等于本轮完整。
6. 更新状态工具、离线验证、手册及 CI；合成响应覆盖时间边界、缓存、分页、数值、旧数据保护、披露日期和 MCP 错误码。执行完整回归。

## 时间与输出语义

- `as_of`/`crawl_date` 是请求截止日；`fetched_at` 是本机抓取时刻；`source_as_of` 是上游明确提供的行情时刻，未知必须为 null，不用抓取时间替代。
- 目录端点仅提供当前快照。本阶段不为其提供虚构的历史行情查询；目录不接受过去日期参数。历史截止日仅用于基本面视图，元数据标明 `historical_cutoff`。
- `cache_state` 区分 fresh/stale/unverified；`completeness` 区分 complete/partial/unknown。`analysis_eligible` 只表示目录结构、缓存年龄和分页通过本阶段检查，不表示具备已核验的行情时效或投资价值。
- CSV 保持原字段；目录 sidecar 为 `<csv>.metadata.json`，包含 CSV SHA256。旧版 CSV 无 sidecar 时可显式允许作为未验证股票池，状态和基本面结果继承未验证标记。
- 基本面另行输出 `fundamental_as_of_<date>.csv` 及元数据；`point_in_time_verified=false`，因为当前接口可能返回事后修订值，尚无不可变历史版本归档。
- 行情价格暂沿用原适配器 /100 转换，明确记录该转换；成交量单位标为来源原生单位，不虚构“股/手”。本阶段不改变来源接口或宣称验证了其最新字段定义。

## 边界

不自动发起真实采集、模型请求或邮件；不新增前端。长任务持久化、跨进程锁和历史版本仓库属于后续阶段。基于只读状态检查的哈希核验不引入采集依赖。
