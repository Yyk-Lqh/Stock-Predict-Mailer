# D2B：单库事务迁移设计（2026-11-16）

沿用已授权路线，在 D2A 就绪检查之上提供显式 `db migrate`。一次只处理一个既有已知库；不自动升级真实数据、启动组件、采集或发送。本批保留此前未提交的 D2A 内容。

1. 校验 store、结构计划、预检摘要与授权确认参数；调用只读预检。认证备份必须匹配当前完整来源清单；所选库缺失、未知、错误摘要及未确认授权变化均在取写锁前拒绝。
2. 单独锁住组件启动/运行和业务入口，重新验证完整来源、结构计划及认证备份。预检不在自持锁时再次调用，以免把自己的锁当活动写入者。
3. 首版只接受没有 WAL/SHM、且头部读写版本均为 1 的 DELETE 日志数据库。SQLite 使用 mode=rw，缺失不创建；连接启用 trusted_schema=OFF、foreign_keys=ON、synchronous=FULL 和有界查询时间。
4. BEGIN IMMEDIATE 后再次核对来源指纹和实际结构，逐条执行目录白名单语句，不用 executescript。目标结构、foreign_key_check、quick_check 通过后，在同一事务写 application_id=0x53504D31、user_version=1。这里是登记版本，不是应用版本；未来登记版本需要显式扩充目录。
5. 提交前核对数据库文件身份和所有已知其他来源文件摘要；其他不遵守锁的外部程序不能被完全阻止，也不承诺跨文件/跨库原子一致。失败回滚本库事务；提交阶段异常标为结果待核对，已提交后清理异常不得声称“没有修改”。不自动覆盖恢复原库。
6. 版本标记不豁免完整结构比较；已登记而缺少目标结构或出现未知对象仍阻断。重复旧摘要会过期；使用新备份、新计划和新预检检查已登记库时不再写入。
7. 每次成功改变一个库后，原备份与完整来源不再匹配；迁移下一个库须重新创建/审阅备份与计划，不复用旧预检。进程崩溃的回滚日志交由单独恢复流程处理；只读结构报告仍拒绝恢复日志。

测试均使用临时合成数据库：提交/版本识别、授权变化、错误摘要、源漂移、外部锁、WAL、DDL/校验/提交失败、重复操作、恢复副本和 CLI。完成后进行完整及基础 wheel 回归，真实工作区只读验证。

已实施并验收：23 项新增/基础 wheel 通过，34 项基础结构识别通过；完整 682 项中 681 通过、1 项已有 OS 权限跳过。源码外实际命令迁移合成库成功。真实 42 个文件只读检查前后一致，未真实迁移；详见[操作手册](database-migration.md)。
