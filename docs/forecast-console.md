# 控制台预测归档与评价定义

阶段 6C 将[分析任务归档](forecast-tasks.md)接入网页。设计见[本轮计划](forecast-console-plan.md)。

已有控制台进程需要正常重启以加载新接口，随后刷新网页。本轮在独立临时控制台验收，没有重启真实工作区的服务。

## 为本轮填写定义

1. 在分析工作台打开“添加分析资料”→“填写预测与客观事实”，导入或填写本轮完整预测。
2. 勾选“本轮先归档预测，再进行分析”。开关默认关闭。填写目标时点、IANA 时区、评价指标、单位、平盘阈值及基准值/来源/观测和可用时点，也可导入完整的 v1 定义 JSON。
3. 交易日周期还需声明日历来源及与周期长度等长的后续交易日；小时和自然日不能附带交易日清单。目标不能从预测有效期推断，基准在预测生成时必须已经可用。具体契约见[归档手册](forecast-evaluation.md)。
4. 发送本轮问题。服务端检查预测与定义并归档，然后才分析和按原授权处理邮件。归档失败会停止本次流程；成功后的报告可点击“查看预测归档与到期状态”。

仅修改评价字段不会改写预测 ID、生成时间、数值或图表。导入定义声明的基准合成标记会保留，若与预测不同会拒绝提交，不会在编辑时悄悄改成一致。手工新建的基准按页面所示沿用本轮预测的合成标记，操作者须核对来源声明。

成功提交后清除归档开关与定义；下一轮需再次明确提供。替换预测、使用新示例或新建/切换会话也会清除旧定义。未提交的同一草稿可在刷新后恢复，不修改已过期时点；过期或不匹配定义须修正。沿用会话预测时，如需归档，请先导入该轮完整预测，再填写定义。

## 查看状态与回执

“任务记录”下方的“预测归档”提供全部、待到期、已到期待观测、已评估筛选，及刷新、载入更早任务、详情。

列表仅展示当前可访问任务所关联的预测：独立任务以及当前访问密钥对应的私有任务。其他所有者的私有预测不可见；只通过 CLI 注册、没有任务关联的档案继续使用 CLI 查询。失败或取消的任务，只要已经记录归档事件，仍可查阅其预测。

列表按任务提交游标分页，每页扫描最多 50 个任务（页面使用 20）。某页可能没有符合条件的预测但仍有更早任务；此时继续载入。页面合并重复 forecast_id，显示已载入的不同预测数，不把它当作工作区全量统计。不同分页的查询时点可能不同；刷新清除已载入分页，从最新任务重新读取。

详情显示目标、单位、指标、事前基准、平盘阈值和声明日历；已有回执时显示匹配观测、方向及可用的数值误差，保留合成标记和来源声明。“已到期”不代表已经验证；没有匹配观测时不显示评分。来源文本按纯文本展示，不执行其中 HTML。

已保存的档案和回执只读。6D 已增加[观测导入与评估预览](observation-preview.md)，支持显式 JSON/单行 CSV 与时点匹配校验；预览始终不保存回执。正式评估仍通过显式 CLI，未来观测不会改变原分析报告。页面不提供定时观测或邮件发送。损坏记录、超出预算或读取失败会明确显示错误，修复来源后刷新/重试；页面不会跳过损坏记录后声称统计完整。

## 接口

- `GET /api/forecasts?limit=20&before=ROWID&state=all`：接受单个 limit/before/state。limit 为 1..50，before 为 0..2^63-1，state 为 all/pending/due/evaluated。返回 items/as_of/scanned_tasks/next_before；无游标时从最新任务开始。
- `GET /api/tasks/{task_id}/forecast`：沿用该任务的 owner 访问检查，返回 task_id、完整 record、as_of、state、evaluations。不接受查询参数，不支持任意 forecast_id 查档案。
- 两者均要求既有同源本机会话；私有任务还需正确的 X-Memory-Key。不提供写方法。单条关联任务读取 2 MiB，事件仅检查最前 100 条，单次任务/归档累计读取预算 16 MiB，单次响应 2 MiB，超限明确拒绝。

6D 的 `POST /api/tasks/{id}/forecast/preview` 仅计算预览，额外要求 CSRF；不会调用正式评估或写入。其请求/响应及 256 KiB 导入限制见[预览手册](observation-preview.md)。
