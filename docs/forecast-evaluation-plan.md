## 选择与顺序

沿用 analysis JSON 只做即时评估会允许事后调整口径；自动猜测行情字段/交易日又无法从 v1 合同确定目标含义。因此先显式注册预测及评价定义，绑定内容后再接受观测。后续再接入日常 run/控制台和观测适配器。

1. 预测按现有严格 v1 契约校验且注册时必须仍有效。注册固定 model_version、prediction_id、subject、synthetic 和原始预测；不调用模型。旧预测到期后不能补注册冒充事前记录。
2. 注册前提供评价定义：目标时点 target_at、IANA 时区、metric、unit、基准观测 reference 和 flat_tolerance。基准观测/可用时点均不晚于预测生成时间，合成标记一致；数值预测的单位须匹配定义。
3. target_at 必须晚于注册时间。hours 精确按生成时点加小时数；calendar_days 按所声明时区的日期增量；trading_days 必须提供带来源声明、严格递增的后续交易日清单，数量等于 horizon.value，目标日等于清单末日。不自行验证交易所休市安排；valid_until 不作为目标时点。
4. 同一 subject/model_version/prediction_id 只接受一个固定预测与定义；新口径须新预测 ID。文件原子、不可覆盖发布，内容摘要检测意外损坏，不声称数字签名或阻止本机用户重写文件与摘要。
5. 查询只读、缺目录不初始化；返回 pending/due/evaluated。历史 as_of 不得晚于现在，不展示当时尚未注册的记录或后来产生的评估。
6. 评估观测必须匹配 subject/metric/unit/synthetic，observed_at 精确为 target_at，available_at>=observed_at 且不晚于 as_of。未到期/无观测/观测未可用时不计分、不写结果。
7. 方向按 actual-reference 与事前 flat_tolerance 比较；数值只计算同单位 signed_error/absolute_error。confidence 不作为已校准概率，不推断收益、胜率置信区间或交易表现。有限输入计算溢出时拒绝输出非有限指标。
8. 评估保存完整观测与摘要、事前记录摘要、首次 as_of、实际评估时间和指标；同一标准化观测复用首次回执，不随后来请求的 as_of 改写旧结果。修订观测追加新结果，不擦除先前证据。不做总体排行榜或跨合成/真实样本混合统计。
9. 文件仅位于 workspace/forecasts；拒绝路径穿越、链接/重解析点和损坏记录，限制单文件1MiB、记录1000项、每预测32份评估及每次读取16MiB。既有备份自动包含这些普通文件，恢复后只是记录，不触发执行。
