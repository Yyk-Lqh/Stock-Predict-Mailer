# 阶段 6B：分析任务绑定事前评价定义

2026-11-16，承接 6A 和“规划好下一步，然后开始实施”的授权。

## 选择与范围

采用显式任务参数：CLI `run --evaluation-definition definition.json`，任务 API `evaluation_definition` 对象。相比配置全局默认或从模型输出推断，此方式能让每个预测单独声明目标、口径、基准与交易日历，避免多轮会话沿用旧定义。没有参数时保持原来的报告内容和身份计算。

归档必须使用本次分析经过 v1 校验的同一预测。在上下文工具、知识检索、分析模型和邮件交付之前注册；无效定义、写锁占用和身份冲突直接失败。API 在接收时纯校验，在执行时重新检查时效并注册；未通过收件人权限检查的请求不注册。成功注册后，即使分析失败或取消，记录仍保留；注册、报告和邮件不是一个原子事务。

分析结果增加可选 `forecast_evidence`：保存注册记录除 prediction 外的字段。验证时与分析自身的 prediction 重新组成完整记录，校验内容摘要、注册摘要、时间及定义。报告和冻结邮件携带同一证据；摘要用于检测一致性，不表示来源认证。本阶段不读取观测或评估回执，也不把事后信息带进分析。

控制台本轮接入任务 API 和任务进度。表单编辑、到期列表页面、自动观测适配器及自动评估后续单独实施。评价定义不从会话或记忆继承。

## 实施与验收

1. 抽取纯注册记录/报告绑定校验，复用 6A 契约；为 AnalysisAgent 和报告增加可选证据。
2. 接入 CLI 和任务编排，在外部分析操作前固定预测，并展示归档步骤。
3. 验证精确绑定、摘要重算攻击、冲突/过期/锁失败、默认兼容、多轮不继承、后续失败保留证据，以及报告/邮件一致。
4. 执行完整回归、基础 wheel 和源码目录外 CLI 验证；仅用临时合成数据，不操作真实预测、模型、采集、SMTP 或数据库迁移。
