# 前端改造提案：让人第一次打开就知道怎么用

> **状态（2026-11-10）**：第 1～4 节与 5.1～5.5 已在 `control/web/` 落地，实际结构见 [控制台界面说明](console-ui.md)。
> 第 6 节「以浅色为主」的判断已被推翻：控制台最终采用高黑（石墨）主题，理由与色板见 `console-ui.md` 的「视觉约束」。
> 本文以下保留当时的判断依据作为记录，**不要**据此把界面改回浅色。

文档日期：2026-11-09。对照基线：`62ed724`，包版本 `0.5.0`。
适用范围：`src/stock_predict_mailer/control/web/`（真实控制台）与 `prototype/`（设计原型）。
本文只提设计与实施建议，不改后端契约；所有接口以 [control-api.md](control-api.md) 为准。

## 1. 结论

三句话：

1. **这个产品真正的门槛不是功能，是"它到底替用户做了什么"。** 报告里事实、推断、建议、降级、投递五种东西混在一起，用户分不清哪句能信、哪句是猜的，就永远不敢用。
2. **所以页面第一屏应该是"一次跑通的示例 + 一份可核查的报告"，而不是配置表单。** 现在的控制台把 5 个配置页排在前面，用户要先做 7 步配置才见到第一份报告。
3. **配置不该前置，应该按需出现。** 当系统说"我做不到"（缺模型、缺授权、数据过期），就地给出跳转与预填，让用户在解决问题时顺便学会系统。

## 2. 现状诊断

| 问题 | 证据 | 后果 |
|---|---|---|
| 首屏是配置，不是任务 | `control/web/index.html` 导航第一项是「模型服务」，默认展示模型表单 | 新用户不知道从哪开始，容易以为这是个 API 管理后台 |
| 冷启动必然失败一次 | `orchestrator.py` 无默认模型时 `raise ServiceError("MODEL_REQUIRED")` | 第一次点「提交分析」得到的是报错，不是报告 |
| 报告被降级成一段 JSON | 页面里 `结构化任务结果` 是一个 `<pre>` | 最有价值的产物变成开发者调试视图 |
| 状态语义词缺失 | `simulated` / `submitted` / `uncertain` 只出现在胶囊文字里 | 用户会以为"已发送"= 对方收到了 |
| 配置没有影响面说明 | 温度、预算、工具白名单都是裸字段 | 用户不知道改它会影响哪一步，只能全填默认 |
| 深色原型与阅读场景不匹配 | `prototype/css/tokens.css` 全局深空色 | 长报告阅读、另存 HTML、打印都不友好 |

原型（`prototype/`）已经把**报告分层、三态胶囊、证据互高亮、真实进度**做对了，这一版的问题是它把「办公区」这个解释性视图放到了与「分析台」平级的位置——那是加分项，不是入口。

## 3. 四条设计原则

1. **示例优先于说明。** 任何"这个系统能干什么"的文字，都不如让用户点一下、30 秒后看到一份真报告。示例必须是真跑出来的（Mock 模型、Mock 预测），不是静态截图。
2. **分层披露，不平铺。** 90% 的用户只需要「填 6 个字段 → 看报告 → 看回执」。剩下 10% 的配置能力保留，但折叠。
3. **状态必须自解释。** 每个状态词后面跟一句人话和一句"你该做什么"，不允许只靠颜色或英文枚举值。
4. **不美化不确定性。** 缺失的置信度用空槽位，降级用琥珀块，模拟投递用灰色，都不能染成绿色。

## 4. 信息架构

主导航从「配置分类」改为「使用阶段」：

```
分析台        ← 默认页，左输入右报告，90% 的操作在这里完成
记录          ← 任务列表（GET /api/tasks?after=），回看历史报告
会话          ← 多轮追问（已有 memory.js 能力）
──────────
设置          ← 页面内再分四组，默认全部折叠
  模型服务 · 外部工具 MCP · 协作与预算 · 邮件与授权 · 记忆
```

要点：

- **「设置」是一个页面，不是五个 tab。** 五组用可折叠分区（`<details>` 语义）纵向排列，每行标题右侧写影响面，例如「模型服务 · 影响：每一次分析的推理质量」。
- **首次进入时设置是收起的**，并在分析台顶部放一条体检条：`Mock 模型 就绪 · 默认模型 已设 · 邮件 本地文件 · 上游数据 未接入`。体检条的数据全部来自 `GET /api/settings` + `GET /api/models`，不伪造。
- **办公区保留，但降级**：只在任务 `working` 状态可进入，作为"谁在做什么"的解释视图；任务结束后自动回到报告。它是锦上添花，不是导航第一屏。

## 5. 页面级设计

### 5.1 首屏（分析台 · 空态）

用户此刻要回答的问题是：**"我拿它干什么？"**

- 一行定位：接收上游预测 + 客观事实，生成可核查的解读，并按授权发邮件。
- 三张动作卡（不是三段说明文字）：
  - **看一份示例报告** → 打开内置快照，标注「示例数据」，可滚动阅读完整报告。
  - **跑一次 Mock 分析** → 一键创建 Mock 模型 + 设为默认（两次 API 调用，`POST /api/models` + `PUT /api/settings`），然后载入动态 Mock 预测并提交。
  - **接入我的预测** → 跳到 5.3。
- 首次访问的记忆用 `localStorage` 存"引导进度"（**只存进度，绝不存任何凭据**）。

### 5.2 分析台（核心页）

左输入、右结果，一屏内完成。左侧只暴露严格契约的必填项：

| 区块 | 字段 | 说明 |
|---|---|---|
| 预测对象 | subject、model_version、generated_at、valid_until | 时间控件带时区后缀，默认 Asia/Shanghai |
| 预测内容 | direction（分段控件）、horizon（值 + 单位）、confidence | 置信度留空 = `null`，控件旁写「留空即上游未提供」 |
| 客观事实 | facts 列表（id/name/value/unit/source/observed_at） | 行内增删；每行强制 source |
| 通知 | notify、recipient | 默认关；开启时校验白名单 |
| 高级 | 原始 JSON | 与表单双向同步，提交前以 JSON 为准 |

右侧从上到下：**三组状态胶囊 → 执行时间线 → 报告**。

- 执行时间线用 `GET /api/tasks/{id}/events?after=N` 的游标循环排空，事件里的 `step` 决定阶段名，**不编造百分比和剩余时间**。没有事件就显示"等待第一个阶段事件"，不要画假进度条。
- 任务结束后执行计划自动收起，报告顶到视野里；任务失败时保持展开，标出断在哪一步。

### 5.3 接入我的预测（向导，不是表单）

用户此刻要回答：**"我的数据格式对不对？"**

- 一个粘贴框 + 一个「校验」按钮。校验结果按字段逐条给结论：`prediction.horizon.unit` 不是 `trading_days/calendar_days/hours` → 指出具体值和允许值。
- 校验通过后展示"这份预测将被这样解读"的预览（标的、方向、周期、有效期倒计时），再允许提交。
- 明确写出当前**不支持**的接入方式：HTTP 预测接口、任意权重、上游训练。不要画一个灰按钮假装即将支持。

### 5.4 报告阅读页

阅读顺序固定，不允许重排：

1. **预测对象条**：标的 / 生成时间 / 周期 / 模型版本 / 是否 synthetic。
2. **上游预测**：方向 + 置信度。置信度为 `null` 时是**虚线空槽**，写「上游未提供」，不填 0、不折算胜率。
3. **客观事实**：卡片式，每张带 `source` 与 `observed_at`，明确写"来源是上游声明，系统未独立核实"。
4. **Agent 推断与建议**：每条带证据引用 `F-01`，点击可与事实卡双向高亮（原型已验证）。
5. **限制与风险**：独立区块。
6. **降级说明**：仅当 `analysis.status=degraded` 时出现，写清哪个角色、什么错误码、结论由谁补写。
7. **已排除的冲突**：单独成块，绝不并入结论。
8. **协作与用量**：参与角色、调用次数、费用预留（写"预留"不写"账单"）。
9. **投递回执**：见 5.5。
10. **底部动作**：另存 HTML（`GET /report`）、看 analysis JSON（`GET /analysis`）、复制纯文本摘要。

顶部常驻三个胶囊，语义固定：

| 胶囊 | 取值 | 颜色 | 人话 |
|---|---|---|---|
| 任务 | submitted/working/completed/failed/canceled | 蓝/蓝/绿/红/灰 | 执行是否结束 |
| 分析 | ok/degraded | 绿/琥珀 | 结论是否完整 |
| 邮件 | null/not_requested/simulated/submitted/retry/failed/uncertain | 灰/灰/灰/蓝/琥珀/红/琥珀 | 是否送出去了 |

`simulated` 必须用灰色：它只表示写进了本地 `sent/` 目录。

### 5.5 邮件：授权与发送必须分两处

- **设置页 = 授权**：transport、sender、recipient_allowlist、allow_synthetic、SMTP 环境变量名。文案写"授权清单决定**谁能收**，不代表现在要发"。
- **分析台 = 发送**：本次 notify 开关 + 收件人。文案写"保存授权时不会发信"。
- `uncertain` 状态**不提供"重发"按钮**，只给「前往确认」→ `POST /api/tasks/{id}/mail/resolve`，并解释"可能已经产生外部效果"。

### 5.6 跨页组件

- **状态词典**（抽屉，任何页面右下角可呼出）：列出全部枚举 → 人话 → 该做什么。这是本产品最高性价比的一个组件，因为它把文档搬进了界面。
- **术语卡**：`上游预测模型` / `大模型服务` / `Agent 角色` 三者容易混，在出现的位置给 hover 说明，写清"换模型不会重新训练预测模型"。
- **禁用即解释**：任何灰掉的控件必须带原因（"子 Agent 本阶段不开放工具"），不许静默禁用。
- **错误可执行**：`AUTH_FAILED` → 检查凭据；`STALE_RESULT` → 重新取数；`CONFIG_IN_USE` → 先解除引用。错误块直接给跳转链接。
- **空态即教学**：每个空列表给一个具体动作按钮（"添加 Mock 模型""载入示例预测"）。

## 6. 视觉建议

- **以浅色为主**：报告是长文档，浅底更耐读、可打印、另存 HTML 更干净。深空风保留给「办公区」这个运行态视图，形成"工作区浅、运行区深"的分工，而不是全局深色。
- **涨红跌绿**：原型 `prototype/css/tokens.css` 现在用的是涨绿跌红（美股惯例），接真实控制台前必须改为 A 股惯例，否则方向会被读反。
- **数字优先于形容词**：`12.40 CNY`、`5 个交易日`、`7 次调用`、`$0.00 预留`，不要写"较强动能"。
- 字号不小于 12px，报告正文 13px/1.6；长 ID、URL、Schema 允许中部换行或局部横向滚动。

## 7. 技术实施

约束来自 `control/server.py`：静态白名单只有 `/`、`/app.js`、`/memory.js`、`/style.css`，CSP 禁内联脚本与外部 CDN，无 SPA 回退路由。因此：

- **零框架、零构建**。一个 `app.js`（可 1500~2000 行）+ 一个 `style.css`。用 `View` 对象做轻量渲染函数（`h(tag, props, children)` 或模板字符串 + `textContent` 赋值），禁止 `innerHTML` 拼接外部文本。
- **路由用 hash**：`#/desk`、`#/records`、`#/settings`。`#/` 不触发网络请求，白名单不变。
- **请求层**：`GET /` 建 Cookie → `GET /api/session` 取 `csrf_token` → 所有写操作带 `X-CSRF-Token`。错误统一成 `{code, message, retryable}` 并交给错误组件。
- **轮询**：任务提交后 1s 一次 `GET /api/tasks/{id}`，同时用 `events?after=` 补事件；终态停止；网络错误只提示"恢复查询"，**不自动重新 POST**。
- **图表**：优先直接渲染 `report_path` 同级返回的 SVG 字符串（来自 `agent_service/charts.py`），或在 `GET /report` 的 HTML 里用 `<iframe src="/api/tasks/{id}/report">` 承载完整报告，页面只做外壳与状态。后者能省掉一半渲染逻辑，推荐先走 iframe 方案。
- **体积**：合并后目标 < 150 KB，不需要新增任何静态路径。

## 8. 分阶段交付

| 阶段 | 内容 | 验收（不看截图，看行为） |
|---|---|---|
| 1 | 应用外壳 + hash 路由 + 请求层 + 错误组件 + 状态词典 | 无凭据、无 CDN 下能跑；断网时只有一处提示 |
| 2 | 分析台（表单 + 校验 + 提交 + 事件时间线） | 全新工作区点「跑一次 Mock」能在 30 秒内出现报告；无默认模型时自动引导而不是报错 |
| 3 | 报告页（分层 + 证据互高亮 + 三态胶囊 + 回执） | `degraded`、`uncertain`、无置信度、无 contexts 四种情况都不会显示成"完整可信" |
| 4 | 设置页（五组折叠 + 影响面说明 + 密钥留空语义） | PUT 不丢未展示字段；密钥不回显；清除意图明确 |
| 5 | 记录页 + 会话页 + 办公区接入 | 历史报告可下载；办公区只在 working 可进 |

阶段 2 结束后就应该能给团队看——它回答了"这东西怎么用"这个原始问题。

## 9. 不要做

- 不做登录、注册、多租户、公网部署（后端明确不支持）。
- 不做交易终端、K 线行情、自选股——本项目不采集行情，也不保证收益。
- 不把 Mock 数据渲染成看起来像真实行情的界面（会让人误判已完成验证）。
- 不用假进度条、假百分比、假预计耗时。
- 不为了开发方便关闭 Host/Origin/CSRF/CSP 校验，也不引入需要额外静态路由的前端框架。
- 不把"办公区"当主页。它是解释器，不是入口。
