# 第四阶段 B2：端点绑定与新写入口切换（2026-11-15）

用户授权按上一阶段建议规划并实施。本轮切换新建邮件的代码路径，历史数据不自动迁移或发送。

## 步骤

1. MailCore 增加绑定元数据与来源别名：冻结 transport、SMTP 主机/端口/TLS/凭据环境变量引用，或 MCP 服务/工具/公开路由及加密配置修订摘要。绑定同时关联信封、EML、分析/来源摘要，防止只改端点或正文后继续发送。明文凭据不入队。
2. 新消息入队即保存可用端点。未尝试过的旧/不完整 SMTP 消息可在显式首次投递前初始化绑定；已有尝试但缺绑定的历史消息必须走 plan/bind 审阅。修改端点需匹配绑定计划摘要且不得重置 uncertain 或 attempts，不自动发送。
3. MCP 新消息使用既有四元组 ID，与端点独立。冻结 EML 及 MCP 请求正文，MailCore 持锁 claim/发送/记录结果；授权与预算仍在控制台，在实际 MCP 会话启动前再次检查冻结端点，取消/未知结果保持 uncertain。
4. 旧 MCP marker 只读。匹配到历史 key 时直接返回原状态（sending 显示 uncertain），不补造信封或重发。未知历史 marker 阻止直接切换到可能重复的请求，提供显式历史审阅时间界限，只允许新于界限的预测进入新队列。
5. 旧版 CLI 新入队邮件使用 MailCore 状态与别名，保留 principal、report_id、旧 ID 与 EML Message-ID；兼容旧 outbox EML 文件位置。旧 outbox 表不再新增/更新邮件。历史已完成记录只读返回，未绑定历史待发记录需要明确计划确认才进入新存储。
6. legacy 投递继续校验报告权限、合成资料/过期许可；不能让通用 drain 绕过这些校验。MCP 也只经已授权控制台执行，不能由同步 send 冒充 SMTP。
7. 增加绑定预演/确认、旧记录绑定与 MCP 历史审阅命令。用合成资料验证端点漂移、凭据不落盘、取消、并发、跨 principal、历史不重复与恢复，再执行全量/基础安装验证。

## 边界

- 本轮不在真实工作区执行绑定、激活或投递，不把 B1 隔离归档自动变为待发邮件。
- MCP 路由配置的加密版本变化会要求重新审阅，宁可停止也不静默切换；SMTP 凭据值仍在执行时由冻结的环境变量引用读取，轮换值不改变目的端点。
- 用户配置授权可随时撤销，冻结路由不冻结授权；submitted 仍非收件箱确认。不能承诺跨外部邮件系统 exactly-once。
- 旧表保留只读用于核对/回退，不维护双向状态副本。应用代码中的新写入口切换不等于运行中的旧进程自动重载，部署前须停止旧写入者。
