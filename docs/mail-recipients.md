# 邮件小马与多个收件邮箱

桌面点击蓝色邮件小马、邮件工位或屏幕，弹出“邮箱投递”。可以添加和删除邮箱输入位（最多50个），开启或关闭“分析完成后投递”。保存会去重，更新本轮任务的收件配置与已有会话草稿；取消或按Escape不改动已保存配置。保存本身不会提交分析或发送邮件。

地址格式须有效，开启投递时至少有一个收件人。遇到新地址时，弹窗列出尚未授权的邮箱，提供“授权以上邮箱并保存”，无需另外前往设置。只有点击此按钮才会将地址合并到最新的授权清单，原有授权和其他邮件设置保留；这一步不发信。授权失败保留输入，允许重试。后端仍在整个任务开始前检查全部地址，并在每个实际投递前重新检查授权。现有任务预算仍生效，预算不足等错误会记录在对应地址回执中，未获预算的地址不会进入发送队列。

任务API增加可选的 `recipients` 字符串数组，保留旧的单地址 `recipient`。数组非空时优先使用数组；多个地址去重后按顺序逐个投递，使用各地址独立的幂等标识。只有一个地址时保持原有返回结构，多个地址的 `mail` 增加 `recipients` 和 `deliveries`。每项包含地址、状态及可用的消息ID或错误；状态不一致时总状态为 `partial`。一个地址失败或结果未知不妨碍其余地址处理，取消任务仍停止后续处理。

报告显示全部收件地址及逐邮箱回执。多个地址的未知结果不显示原有的单条回执确认按钮，避免误用整任务单邮件确认接口；可通过逐地址回执追查，不自动重发。

手机端保持原有入口和单邮箱表单。桌面现有权限菜单也兼容逗号分隔的多个地址。

验证使用本地文件模拟投递，没有发送真实SMTP邮件：

- 后端回归覆盖多地址去重与分别投递、整批授权预检、无效/空列表/超长列表、单地址旧接口、单地址未知后继续处理其余地址。
- gstack `tests/browser_mail_recipients.js` 检查点击小马打开弹窗、格式校验、增删、去重、取消保留配置、保存不提交任务；实际提交Mock分析后生成两个独立的模拟投递回执。

完整 `test_control.py` 的47个测试通过，Ruff、JS语法和打包一致性检查通过。后端Python增加了请求字段和批量投递逻辑，运行中的旧服务需要重启才能使用多邮箱接口；仅刷新网页不能加载后端更新。未生成视频，也未改动手机端布局。
