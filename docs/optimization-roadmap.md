# 项目优化路线（2026-11-15）

目标：在本机单用户定位下，建立可安装、可追溯、可恢复的真实数据分析与通知流程。用户已授权按业务闭环优先路线规划并开始实施。

## 实施顺序与验收

1. **采集服务可交付（本轮实施）**：声明独立 crawler 可选依赖、打包 MCP 模块、提供命令入口；修复 HTTP 监听配置；隔离数据输出路径；离线验证只使用临时合成资料。验收：基础环境能发现服务且不采集，安装采集依赖后验证通过；真实 stdio/HTTP 协议可发现并调用状态工具；wheel 包含服务模块；CI 覆盖。
2. **数据可信度**：明确抓取时间、来源时间、报告期、披露时间与缓存有效性；支持显式回放日期，标记分页不完整；校验数值、单位和证券代码。验收：旧缓存、部分结果和历史回放不能冒充当前完整数据。
3. **单标的分析闭环**：增加采集上下文适配器和输入快照；接收上游预测并关联模型版本；证据贯穿分析、HTML 报告和邮件。验收：一只标的从真实来源进入任务并能追溯原始输入；无预测时明确缺失，不生成虚构预测。
4. **长任务与通知可靠性**：采集任务持久化、互斥、取消、断点及失败项补采；按 mail-core-plan.md 分步收敛邮件队列、逐收件人状态与人工确认。验收：中断可恢复、不重复写入或盲目重发，迁移可预演且不触发发送。
5. **日常运行与数据保护**：一键启停、诊断、日志轮转、数据库迁移、备份与恢复演练。验收：端口冲突可解释、关键 Worker 不遗漏、密钥与数据库可配套恢复。
6. **质量与体验**：将完整用户流程纳入浏览器 CI；预测归档及到期评估；知识证据定位、自选标的、模板与明确授权的定时任务。验收：评价使用当时可见信息，日常操作可复现，动画展示与实际任务一致。

每阶段独立记录实施及验证结果。真实采集、模型调用和 SMTP 验收与离线测试分开；不自动触发全市场采集或发送邮件。阶段 1、2 已完成，阶段 2 的细化及验收见[数据质量计划](data-quality-plan.md)。阶段 3 已完成 CLI 输入、报告和本地邮件实现，范围与验证见[单标的计划](single-symbol-plan.md)；控制台自动接入及真实来源/SMTP 验收尚未完成。阶段 4A 持久化采集、4B1 MailCore 提取/预演和 B2 端点绑定/新写入口统一已完成；历史用户邮件未绑定或发送。阶段 5A 已增加[只读诊断](runtime-diagnostics.md)，5B 已增加[组件身份、启停与日志](runtime-lifecycle.md)，5C 已增加[加密备份与隔离恢复](workspace-backup.md)；实际用户数据没有执行备份/恢复。

第五阶段 D1 已增加[结构识别、迁移计划和副本演练](schema-planning.md)，设计见[本批计划](schema-planning-plan.md)。真实数据库未升级。下一步 D2 为已知版本实际迁移的备份、停写、事务和版本登记；完成后再推进阶段 6 的端到端流程及到期评价。

D1 验收：新增 32 项与基础 wheel 32 项通过；完整 553 项中 552 通过、1 项已有 Windows 权限跳过。真实检查发现邮件绑定组可升级，其余已有库匹配；38 个来源文件摘要保持一致。
