# 小马办公室动画与任务联动设计

日期：2026-11-11。状态：用户已确认并实施，验收与限制见 pony-office-validation.md。

## 现状与方案选择

现有实现使用 SVG，`pony-model.js` 管理寻路与动作，`pony-office.js` 管理渲染及真实任务事件，`scripts/build_console.py` 生成 `memory.js`。保留现有柔和配色、围巾角色标记、固定工位及主题。

推荐继续使用 SVG，拆清仿真、角色骨架、屏幕和事件适配职责。与仅补充关键帧相比，这能协调门口、坐姿和任务打断；与改用 Canvas/WebGL 相比，能保留现有主题、键盘操作及页面集成，避免引入新渲染依赖。

当前问题：单一 transit 串行控制全场移动；空闲仅限常驻角色；角色相位一致；步频与速度无关；出入在门口直接切换可见性；屏幕仅执行任务时亮起；任务显示主要消费 step，缺少工具与等待细分。

## 状态与角色

角色身份、名称、配色、外观特征和工位使用同一份定义。增加不同鬃毛、耳形细节、额毛与尾形，维持统一比例。头、口鼻、眼睛、耳朵、躯干、四肢、尾巴采用独立关节分组。

分开保存真实任务状态与场景状态。任务记录 taskId、childId、事件序号、阶段、结果、已完成步骤及后端提供的总量。场景记录位置、朝向、姿态过渡、活动、工位、门口队列及独立随机种子。空闲来访不创建 Subagent，也不调用模型。

动作流程：观察方向、转向、起步、行走、减速、对齐椅子、落座、操作电脑；离座反向执行。步态按实际位移累计，四肢交替，头、鬃毛、尾巴延迟跟随。各角色错开眨眼、呼吸、耳动与停顿。任务反馈立即更新；身体动作在安全衔接点切换。

## 导航与门

保留障碍感知寻路，增加角色各自动作流程和窄通道预约。工位入口仅允许所属角色靠近。空闲活动包含观察、散步、入座游戏或绘图、离开和延迟返回，停留与冷却按角色错开。

门口流程：靠近候门点、转向、伸前肢操作、门绕固定门轴打开、穿越门槛、全身离开门扇范围、关门。出入两侧均有连续路径与遮挡，禁止通过关闭的门。单个门口控制器分配通行权，后续角色等待；连续通行可以保持开门，最后一位通过后关闭。收到任务时，门槛内角色返回工位，穿越中的角色先完成安全通行，再排队返回。

## 工位与屏幕

桌椅、显示器、键盘和鼠标采用明确锚点。前肢操作与键盘、鼠标对应，操作周期包含输入、停顿、观察与点击。按场景深度绘制椅背、身体、桌面及设备，避免坐姿悬空和桌面穿模。

屏幕优先级：真实任务与结果反馈 > 在座空闲游戏或绘图 > 在室离座屏保 > 离室待机。角色在办公室时持续亮屏。屏保较长间隔交叉淡化；游戏至少包含贪吃蛇、扫雷、俄罗斯方块、打砖块，各有连续变化的局面及配套操作节奏。空闲动画仅为视觉模拟。任务到达立即接管画面，暂停空闲局面，完成、失败和取消保留明确短时反馈后恢复。

## 真实事件与资源

接入现有 step、tool、plan、adjustment、chart、mail 和任务终态，按真实 taskId/childId 绑定角色。没有确定总量时只显示阶段、步骤数和耗时，不推算百分比；工具执行与等待子 Agent 显示不同文案。恢复历史时重建状态，不重播已完成工作的身体动作。断线保留最后状态并明确提示，恢复后去重同步。

共用 requestAnimationFrame，逻辑和屏幕分频更新；缓存 SVG 关节引用，避免每帧重新查询或重建 DOM。离开分析页或页面隐藏暂停绘制，恢复时重置时间差。统一清理帧回调、监听器及资源；减少动态效果模式保留位置、任务语义和通行约束。

## 验收与交付

1. 确定性长时仿真：障碍、角色间距、门口队列、连续到达、空闲与任务打断、快速完成、失败、取消及减少动态效果。
2. 屏幕状态检查：在室亮屏、离座屏保、在座四款游戏及绘图、任务抢占、结果反馈与恢复。
3. 真实本地后端 Mock 任务事件验证，核对任务标识与步骤；仅用注入事件补测无法稳定触发的失败边界，并明确区分证据。
4. 使用 gstack browse 检查实际页面、动作遮挡、桌椅比例、主题和窄屏；提供截图及可运行地址，记录仍有的限制。
5. 构建产物同步，执行导航测试、相关后端/前端检查，确认无额外模型调用。

现有主密钥缺失；当前完整服务使用独立 `data/local-fresh` 工作区，原有工作区保持原样。验收沿用独立工作区及 Mock 配置。
