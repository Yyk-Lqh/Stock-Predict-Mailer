# 桌面专业模式工作流

专业模式有「编辑」「调试」和「运行记录」。继续使用左侧导航、小马大厅、会话历史、资料和报告。流程图使用控制台现有 DOM、SVG、画布坐标和颜色，蓝图中的节点库、端口、表单连线与键盘移动落在同一套画布上。

## 改版前的节点对照

| 旧节点 | 配置或输入 | 后端能力与状态来源 | 旧版执行状态 |
| --- | --- | --- | --- |
| 模型选择 | 默认模型、主角色覆盖、启用状态 | 模型配置页、运行限制和模型调用 | 配置入口，非独立运行步骤 |
| 预测资料 | 标的、预测时间与有效期、周期、上游模型版本、可选置信度 | 任务请求、会话沿用、预测契约 | 表单已接入任务 |
| 事实与证据校验 | 事实来源与观测时间、预测、图表序列 | 任务校验和 validate 事件 | 编排器执行 |
| 上下文 | 主角色工具名单和 MCP 配置 | tools 步骤和逐次工具事件；行情墙另有行情快照 | 编排器按授权执行，画布混合显示行情墙数据 |
| 主分析 | 主角色模型或 A2A、风险目标、预算 | main 事件及最终分析；必要时使用确定性降级 | 编排器执行 |
| 风险核对 | 子角色、复杂度、深度、委派预算 | risk 子任务或最终报告风险字段 | 实际风险子任务按需串行；旧卡片也可能仅从产物推断状态 |
| 图表 | 已校验的观测、预测和回测序列 | charts 步骤与 chart 事件、报告图表 | 编排器执行，缺数据时可能无图 |
| 报告 | 分析、限制、证据、图表及格式偏好 | report 事件和任务报告接口 | 编排器执行 |
| 邮件 | 通知开关、授权收件人、配置通道、幂等键 | mail 等事件及投递回执 | 已授权时执行 |
| 归档、知识、子 Agent 汇总 | 事前评价定义、私有查询及引用、结构化子任务 | 后端已有能力；旧图没有完整的独立节点 | 编排器按需执行 |
| 自定义与已训练模型卡片 | 名称、说明、旧条件、模型版本 | 本机浏览器图配置，已训练模型来自注册表 | 草稿 |

## 系统流程和实际运行

系统模板走现有编排器。资料入口完成后校验预测、上下文与来源。满足条件时依次归档预测、检索私有资料和调用授权 MCP，再交给主 Agent。子 Agent 仅在编排器作出委派决定时加入，并按预测、风险或建议的实际事件顺序串行显示。存在子任务结果才汇总，随后生成图表和报告。邮件是报告提交后的授权步骤。旧任务仍从原事件和产物回放，发生在版本化之前的任务显示「旧任务 · 无图版本」。

「校验计划」显示可运行、跳过、受阻和运行时才可判断的条件。「运行记录」保存快照的图版本和配置版本，并显示节点状态、上游路径、来源、输入输出摘要、耗时、错误和重试次数。运行中的图使用提交时的版本。模板复制后可以在「自定义流程」中另存为有名称的副本。

## 可执行节点

| 节点 | 输入 → 输出 | 执行条件与配置 | 单节点调试 |
| --- | --- | --- | --- |
| 资料输入 | 任务 → request | 唯一入口。预测可来自当前资料或原会话 | 支持 |
| 资料校验 | request → context | 校验预测、事实和序列的契约 | 支持 |
| 预测归档 | context → context | 有事前评价定义时写入归档 | 调试跳过写入 |
| 知识检索 | context → context | 私有会话、查询、预测时点；将证据交给模型还需任务勾选授权 | 支持 |
| MCP 上下文 | context → context | 显式工具或继承主角色授权列表，服务必须启用且副作用为 read | 支持，消耗正常调用预算 |
| 数据库 | context → context | 选择本机 SQLite 文件或项目任务库。可设置 1 至 30 条查询上限，并选择将返回条数作为事实传给下游 | 支持 |
| 内置工具 | context → context | 在专业模式「插件 → 可调用的工作流工具」添加。工具保存检查结果并传递原上下文，可在缺少所需数据时触发节点失败策略 | 支持 |
| 主分析 | context → analysis | 继承主角色，或选择本机已启用模型；可配置确定性降级 | 支持 |
| 结果汇总 | analysis → analysis | 复核模型结果，可汇合同一上下文的多条分析结果 | 支持 |
| 图表 | analysis → analysis | 使用校验时间序列；缺少序列时保留空状态 | 支持 |
| 报告 | analysis → report | 校验分析并渲染报告 | 仅渲染测试，不写报告 |
| 邮件交付 | report → receipt | 必须显式启用并通过实时授权；复用投递幂等规则 | 调试跳过投递 |

自定义图按实际连线顺序执行。可用的连线条件是始终、有事实、无事实、启用邮件、未启用邮件。只有已选中的上游才传递数据。普通汇合节点遇到多个不同结果会报错，结果汇总可合并来源于同一上下文的分析结果。服务端拒绝循环、自连、重复边、断链、端口类型不符、未知节点和缺少权限。只读 MCP 的可重试失败沿用预算内的既有重试逻辑。调试接受任务 JSON，沿所选节点的依赖运行，并读取同一次调试生成的上游输出。

## 连接本机 SQLite

选择「本机 SQLite 文件」后，节点会先查找项目目录、桌面、文档和下载目录。可将「扫描范围」切换为「指定目录」或「本机磁盘」后点击「重新扫描」，查找项目外的数据库。磁盘扫描有时间和结果数量上限。结果部分显示时，可缩小到数据库所在目录再扫描。

选择候选项会填入绝对路径并读取表列表。已知文件位置时，也可手动填写绝对路径，如 `D:\data\quotes.sqlite`，再点「测试连接」。文本 `.sql` 脚本需要先导入 SQLite 数据库。

选择要查询的数据表。标的列可选，用来匹配当前预测标的。留空时查询全表，仍受条数上限约束。运行记录显示表名、筛选条件、实际返回条数和是否还有匹配记录。启用下游事实时，模型只收到本次查询返回条数。

## 可调用的工作流工具

- **预测检查**显示上游模型、置信度、周期及有效期。
- **事实来源盘点**统计已校验事实并显示来源和最近观测时间。
- **时间序列盘点**显示序列来源、点数及覆盖时间。
- **历史归档查询**显示当前标的最近五条可访问的归档分析。
- **邮件交付检查**核对通知开关、当前收件人授权和合成数据投递策略。

在「调试」中可以单独调用工具，运行记录会保存检查结果。MCP 上下文节点的输入框可选择已启用且授权给主 Agent 的只读工具，留空则继承主 Agent 的已授权工具。

## 草稿迁移和修复

旧版本从原浏览器存储读取。已知步骤迁移到登记类型。无法识别的节点保留显示名、位置和旧版配置，可在详情中查看。旧自由文本条件不会作为执行表达式。按节点 ID 定位问题后，改选可执行类型或移除节点，再用类型化条件重连。已训练模型、独立预测推理和任意自定义动作仍是草稿。系统选用的 A2A 子角色可在系统运行中回放；自定义图当前可选择主角色分析与结果汇总。

草稿、流程导出和运行证据引用模型或工具 ID。连接凭据留在既有加密配置中。行情墙引用显示来源、观测时间、时区和实时性。任务图表说明序列来源和观测点。置信度仅取上游提供的值。合成预测和 Mock 测试保留原标记。

## 本地验收

使用测试工作区、Mock 模型、本机 stdio MCP 和文件邮件。服务端测试为 tests/test_workflow.py，桌面测试为 tests/browser_workflow_execution.js，通过 gstack browse 在端口 18768 的一次性控制台上执行。行为参考为 [RAGFlow 的可追溯引文](https://github.com/infiniflow/ragflow)、[Dify 的单节点调试](https://docs.dify.ai/en/use-dify/debug/step-run)和 [Coze Studio 的可视化执行与调试](https://github.com/coze-dev/coze-studio)。运行证据以任务 ID、节点事件和版本为准。
