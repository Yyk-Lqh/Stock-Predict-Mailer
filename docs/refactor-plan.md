# 预测分析 Agent + 邮件通知重构方案（2026-11-05）

## 检查结论与清理决定

当前为 Python 3.11+ / unittest / SQLite 项目，无需引入 Web 框架。旧 CLI 同时负责上传、训练、模型注册、研究报告和邮件，职责过宽。既有 core.atomic_write、时间校验、邮件地址检查、进程锁和 SMTP 不确定状态策略可以复用。

采取同包分层方案：新默认 CLI → 接入适配器 → v1 校验标准化 → AnalysisAgent → JSON/HTML 报告 → 独立邮件 outbox。保留旧 CLI 为 legacy 子命令。另一选择是直接改造旧研究契约，会强迫上游交付训练数据与固定股票池；拆成多个网络服务则增加部署成本，两者均不适合本阶段。

实际清理：默认依赖移除 numpy/scikit-learn/duckdb/pyarrow/openpyxl/cryptography，归入 research 可选组；默认入口移除训练、研究的直接导入；旧 README 归档，旧功能经 legacy 显式访问。未发现可确认无用的生产模块，因此不以“暂不负责”为理由删除旧代码或测试。缓存、日志没有业务依赖，但本轮不扫描或删除其内容，避免影响其他正在运行的工具。

保留清单：data/ 下 CSV/Parquet 原始与清洗数据，JSON/TXT/PKL 模型产物，ZIP 模型包，SQLite 元数据，HTML/EML 报告；secrets/ 下签名材料；config/ 现有配置；全部旧训练、模型管理、日历、上传、知识库模块及测试；.gstack/.workbuddy/.venv/.tmp 等本机状态。数据与模型价值及所有权未确认，不能删除。凭据、密钥、数据库内容不读取、不迁移、不输出。详细非敏感元数据清单见 inventory.md。

## 边界与默认值

成员负责采集、处理、训练及预测服务；本系统消费预测 JSON，不加载 pickle、不执行交付模型。未来模型文件交付必须在独立受信任的模型运行适配器中实现，再输出相同预测契约。

默认 deterministic Agent 明确标注无 LLM，可完全离线运行；HTTP Agent 为可替换的受约束策略服务，仅允许选择输入事实 ID 和预定义推断/建议代码，禁止任意文本结论进入报告。失败显示 degraded 与错误代码，保留有依据的确定性分析。未来接 LLM 时由上游策略服务负责调用模型，将其结果映射为同一受约束协议。

时间均要求带时区并标准化 UTC，展示默认 Asia/Shanghai；过期预测拒绝分析，过期上下文拒绝使用。置信度缺失保持 null；置信度不等于经校准的收益概率。报告区分模型预测、客观数据、规则/Agent 推断、建议及限制。没有上下文时显示限制，不生成原因解释。

邮件默认 file 本地投递（生成 .eml，并标记 simulated），真实 SMTP 需显式选择 smtp。独立 SQLite outbox + 进程锁；内容、收件人和发件人确定幂等 ID；安全失败指数退避、有次数上限；DATA 后网络异常或发送中崩溃标记 uncertain，不自动重发。SMTP 只能确认服务器接收，不能保证最终到达，也不能实现严格 exactly-once。
