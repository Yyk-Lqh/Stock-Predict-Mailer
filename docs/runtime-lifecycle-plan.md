# 第五阶段 B：组件归属、心跳和受控启停（2026-11-15）

用户继续授权下一步实施，沿用上一轮 5B 顺序。先用实例身份区分真实运行与遗留记录，再提供显式启动、协作停止及有界事件日志；不接管当前未登记服务，不在真实队列上演练启停。

## 设计与实施步骤

1. 为 console、knowledge_worker、crawler_worker 各维护工作区内 `.runtime/<component>/`。一组件一把独立终身 OS 锁；记录随机 instance、组件、规范工作区、进程 PID/创建标识、主机摘要、开始/心跳时间和 starting/idle/busy/running/stopping/stopped/failed 阶段。现有业务锁继续保护数据库，不混用。
2. 只读 status 不创建目录/文件，不构造业务服务。校验记录格式/大小、组件/路径归属、主机、OS 进程创建标识、锁和心跳；区分 verified、stale、stopped、dead、unknown。Windows 查询进程创建时间，Linux 使用 boot ID 和 /proc starttime；其他平台无法确认时明确 unknown，不据 PID 存在推断归属。
3. 心跳由独立线程更新，空闲轮询也可观测。故障或强制退出可留下记录，但 OS 锁释放；旧记录不能成为可停止新进程的凭据。运行配置只保存端口、vault 模式等白名单公开字段，不保存环境变量值、正文、命令行或服务凭据。
4. 停止通过实例匹配的 stop.json 请求，组件仅消费属于自身 instance 的请求；从不调用 kill/taskkill 或根据 PID 发信号。知识 Worker 在当前任务边界停止；采集在已有检查点检查中协作中断，保持显式 resume；控制台停止接受新请求并取消/等待活动任务收尾。无法即时退出时返回 stopping/timeout，不假报 stopped。
5. `runtime status/start/stop/logs` CLI。start 只支持三个固定组件，子进程使用当前解释器与绝对配置/工作区；Windows 隐藏窗口。每次 launch 有独立实例 ID，启动确认匹配实际子进程登记，不能把 venv redirector PID 或旧记录当作新服务。重复启动只返回已登记同配置实例，配置不同或锁/身份不明则拒绝；端口冲突不抢占或自动换端口。
6. 日志只记录白名单结构化生命周期事件，256 KiB × 当前文件加 3 份轮转。后台子进程原始 stdout/stderr 不采集入日志，避免把供应商正文/异常或凭据永久保存；前台原输出保留。logs 只返回校验过的有限事件，不输出任意文件文本。日志是生命周期记录，非完整业务调试日志。
7. 原前台 console/Worker 入口自动登记；管理启动也走相同函数，避免两套执行逻辑。run_once 作为库函数仍可直接调用，未登记调用只保留原业务锁证据，不冒认受管 Worker。doctor 增加身份/心跳检查，继续保持只读和 `--skip-port-check` 无套接字检查。
8. 使用合成临时工作区验证并发/旧 PID/跨工作区/心跳/崩溃/优雅停止/有界日志及真实子进程启动。不得执行真实采集、模型调用、SMTP 或迁移；保留已有优化改动。完成全量和基础 wheel 验证、更新操作手册。

## 授权和边界

- start 是显式动作，console 可初始化配置库，Worker 可立即执行已有任务并联网；不从 doctor/status 自动启动任何组件，不自动重启失败进程，不自动启动全部 Worker。
- 不杀未知进程，不自动接管当前 8767 的未登记监听者，不改变真实服务、主密钥模式或环境设置。
- 心跳证明进程登记仍在刷新，不代表业务任务一定有进展或外部服务健康；业务锁、任务计数和身份分别展示。
- 协作停止可能等待不可取消的第三方调用；无强制杀进程选项。实例请求防止误停其他实例，本机有工作区写权限的账户仍是信任边界。
- 本轮不是 OS 服务管理器，不自动开机启动；后续备份恢复仍在独立目录显式演练。

- 新增 36 项专项全部通过；涵盖真实 Windows 进程创建标识、独立租约、心跳、PID 复用/权限未知/主机及工作区不符、旧请求隔离、崩溃遗留、并发启动拒绝、停止等待边界、知识任务边界、采集检查点、控制台停止新任务与活动任务收尾、日志大小/内容校验和 CLI。
- 全量执行 481 项，480 通过、1 项因当前 Windows 账户无符号链接权限跳过，耗时 195.197 秒；该跳过与上一阶段一致。包括原采集 29 项、知识 Worker、控制台和 MailCore 回归。
- 最终代码 wheel 在独立 Python 3.12 基础环境（无 pandas/requests/baostock/numpy/sklearn）执行相同 36 项，全部通过。包含 7 个 operations 文件，无缓存/临时数据入包；从源码目录之外用已安装 CLI 完成空采集 Worker 的 start/status/logs/stop，未创建任务库或采集。
- Ruff、compileall、命名、仓库卫生及 diff 空白检查通过，基础 CI 增加生命周期专项。测试曾发现仅由心跳轮询停止请求会让快速任务继续领取，已增加任务边界同步检查；控制台也关闭新任务入口后再等待收尾。
- 显式空 Worker 新增登记文件的行为已明确文档化，旧契约改为验证任务库/采集目录仍不存在；状态查询仍不创建目录。补充测试时的 time 导入遗漏已修正，最终验证无错误。
- 对真实工作区仅执行只读 status/doctor：三个组件均为 not_registered，当前旧服务没有被接管或重启；6 个已知数据库/配套密钥/锁的文件集合及 SHA 不变，运行目录存在性不变，start/stop 操作为 0。记录为 `.tmp/runtime-lifecycle-workspace-check.json`。当前终端的 SMTP 缺凭据、正式库未选中及 8767 不可供新实例使用三项提示仍保留。
