# 第三阶段：单标的输入与证据闭环（2026-11-15）

用户已授权规划下一阶段并开始实施。基于已确认的优化路线，本轮完成 CLI 从第二阶段基本面视图到报告与本地邮件的闭环；不自动采集或联系真实模型/邮箱。

## 实施步骤与选择

1. **本地 crawler 上下文适配器**：复用现有 v1 预测输入，新增 context.adapter=crawler。path 指向第二阶段生成的基本面截止日 CSV；标准库读取 CSV/sidecar 各一次，对实际 CSV 字节和规范元数据内容计算摘要，拒绝残缺任务或未经验证披露的行。只选择预测标的对应的最新可用报告期。
2. **时间与单位**：observed_at 使用报告期末上海日终；available_at 使用披露日日终与原始 collected_at 的较晚者。明确日期精度转换，不用文件复制时间或分析时间刷新事实年龄。基本面需要显式较长 max_context_age_seconds，本阶段仅扩大该配置上限，其他超时上限保持原样。单位明确为“来源原生单位/字段名”，不虚构百分比、金额或行业可比性。
3. **冻结输入**：预测 ID/版本、标准化预测与上下文、原 CSV/sidecar 摘要、选中原始行及字段映射组成有内容摘要的 input_evidence。保存至工作区 input-snapshots/<snapshot_id>.json；相同输入复用快照，已有内容损坏时拒绝覆盖。快照包含选中记录及全文件哈希引用，不复制其他标的完整数据。
4. **报告与邮件**：AnalysisAgent 在 v1 context 外携带可选 input_evidence（与 chart_data 相同的扩展方式），严格校验其与预测/事实的绑定；analysis_id 包含证据。JSON、HTML、纯文本/HTML 邮件使用同一字段引用；报告和直接邮件入队均保存快照。
5. **验收**：合成真实来源格式的 CSV 与上游预测走实际 CLI/file transport；验证重复运行去重、资料变更追溯、缺少预测、对象不匹配、旧事实/未来披露、残缺任务、数据/快照篡改和 HTML 转义。基础安装无需 crawler/research 依赖。执行全量回归与 wheel 检查。

相比只新增 CSV 转换脚本，直接复用 run 可以覆盖报告与通知；相比同时改造控制台/MCP/界面，本轮先固定可验收的数据契约，降低对现有任务编排的影响。控制台自动接入留作后续集成，不宣称已完成。

## 明确边界

- 支持证券对象格式 `六位数字.SH/SZ/BJ`；代码与行内 provider_symbol 采集路由均须匹配。不从六位代码猜测缺失路由；路由仍属于来源声明，未经独立来源认证。
- 目录价格暂不进入事实：来源时刻未知，旧计价转换未独立核验。缺预测返回错误，不能以当前报价代替预测。
- 部分股票池的单标的任务可以接入，但必须有新增的 run_complete=true，表明选定采集任务完整；completeness=partial 只允许 scope_limited 的明确限量情形。整个历史数据集仍标 unknown。
- 事后修订、历史股票池、原生指标单位、来源声明和日期精度限制贯穿报告。此视图不是经过验证的历史回测输入。
- 输入与原始资料均为本机不可信材料，内容哈希用于追溯与损坏检测，不代表来源认证。输入快照最多 256 KiB；输入 CSV 最多 64 MiB，sidecar 最多 64 KiB。
- 不执行新数据库迁移、不修改前端、不自动采集或真实投递。先完成 CLI 单标的闭环，再推进路线中的长任务与 MailCore。

- 最终全量回归 324/324 通过，耗时 156.854 秒。最终交易所路由补强后重新执行，未以补强前结果替代最终验收。
- 最终 wheel 在独立 Python 3.12 基础安装环境执行 60 项：42 项通过，18 项按设计跳过可选采集依赖测试；单标的 CLI 全部可运行，不依赖 pandas/requests/baostock 或研究库。
- Ruff、compileall、命名、仓库卫生与 diff 空白检查通过。wheel 包含新适配器与证据模块，未包含本地构建缓存。基础 CI 新增单标的测试。
- 原始文件、数据库和用户设置未迁移；未发起真实采集、真实模型请求或 SMTP 邮件。合成输入的预测均明确 synthetic，file transport 只写临时本地 EML。真实来源字段/单位/模型质量及控制台接入仍待单独验收。
- 后续按优化路线推进长任务与 MailCore；本阶段保留并传播来源声明、历史修订和日期精度限制。
