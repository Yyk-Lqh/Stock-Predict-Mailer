# 桌面专业模式可视化工作流画布设计

## 目标

将桌面端专业模式改造成基于现有真实分析链路的可视、可编辑工作流画布。保留现有静态资源、API、任务接口、会话机制、权限校验、报告流程和移动端布局。

## 现状与真实链路

控制台由 Python `http.server` 提供四个静态资源。桌面专业模式由 `desktop-workbench.js` 在 `min-width: 761px` 时动态挂载，任务状态通过既有 `DesktopPoll` 从 `/api/tasks/{id}` 和 `/api/tasks/{id}/events` 读取。

编排器的固定步骤为 `validate → main → charts → report`，根据输入还会增加 `forecast` 归档、`tools` MCP 上下文补查、`prediction/risk/advice` 子 Agent、`merge` 汇总和 `mail` 投递。行情单独由 `/api/market/snapshot` 提供，包含来源、更新时间、时区和实时/延迟/过期/不可用状态。图表只来自任务事件或任务实际产物。

## 方案

复用现有 `#desktop-focus` 容器，用原生 DOM、SVG 和当前项目 CSS 绘制画布。节点数据、连线、编辑器和状态映射全部由 `desktop-workbench.js` 管理。右侧现有报告检查器继续作为节点详情面板的宿主，通过焦点和 `aria` 属性维持键盘可用性。`memory.js` 仍由 `scripts/build_console.py` 聚合，不引入 React Flow、Tailwind、TypeScript 或新的服务端路由。

## 默认节点

默认流程包含以下节点。

| ID | 名称 | 类型 | 真实来源 | 依赖 |
|---|---|---|---|---|
| model | 选择或校验分析模型 | model | 默认模型设置、角色配置、`MODEL_REQUIRED` | 无 |
| prediction | 读取预测资料 | input | 任务 JSON、预测有效期、synthetic 标记 | model |
| evidence | 校验事实与证据 | validation | `context`、事实来源时间、知识引用、`validate` 事件 | prediction |
| context | 获取行情或上下文 | retrieval | `tools` 事件、授权 MCP 工具、`/api/market/snapshot` | evidence |
| main | 执行主分析 | analysis | `main` step、主 Agent 或确定性降级说明 | context |
| risk | 风险核对 | review | `risk` 子 Agent、分析 `risks`/`limitations` | main |
| charts | 图表生成 | chart | `chart` 事件和分析 `charts` | main、context |
| report | 报告生成 | report | `report` 事件、analysis 产物、报告接口 | risk、charts |
| delivery | 邮件或其他交付 | delivery | `mail` 事件、授权名单和邮件状态 | report |

默认图上保留 `prediction → evidence → context → main` 主链，并从 `main` 分出 `risk` 与 `charts`，汇合到 `report` 再到 `delivery`。节点详情显示名称、类型、说明、当前状态、输入、输出、来源、可执行条件、失败原因和下一步操作。

## 状态模型

节点支持 `idle`（未开始）、`waiting`（等待前置节点）、`running`（执行中）、`completed`（已完成）、`failed`（执行失败）、`skipped`（已跳过）、`degraded`（降级完成）和 `needs_input`（等待用户处理）。界面文案分别为“未开始”“等待前置节点”“执行中”“已完成”“执行失败”“已跳过”“降级完成”“等待用户处理”。

任务状态和事件是唯一的运行态来源。任务处于 `submitted` 时节点保持等待或未开始，`working` 时由 `step` 事件更新，`completed` 时使用实际产物补齐节点，`failed` 或 `canceled` 时保留已知节点状态并在失败节点显示错误码和重试/修正入口。分析 `status=degraded` 映射为降级完成。没有真实输入时显示“等待数据”“暂无实时数据”或“未提供”。

## 自定义编辑

用户可以新增、编辑、删除、移动节点，创建/删除连线，设置启用状态、执行条件和失败处理方式，保存自定义流程，恢复默认，导入和导出 JSON。节点 ID 必须唯一，边不能自连、重复或连接不存在的节点。新增边前进行 DFS 循环检测。流程必须恰好有入口节点和结束节点，且每个启用节点配置完整。删除节点会移除其相关边，并在仅有单入单出的情况下尝试桥接，否则提示用户重新连接。

自定义节点可以作为可视计划保存，但只有与真实链路 ID 对应的节点会接收后端运行状态。未知节点在运行时显示“已跳过 · 当前任务接口未提供该操作”，避免伪造执行结果。提交分析前如果当前画布配置无效，阻止提交并定位到画布问题。保存失败时不覆盖内存中的当前编辑内容。

## 持久化与退出保护

显式保存后，工作流配置写入浏览器本地存储，键名带应用前缀和版本号。未保存的编辑保留在当前页面内存中。导入前校验 JSON，失败时保留当前图并显示错误。恢复默认和离开分析视图前，如果存在未保存修改，使用现有原生确认流程提示用户。运行中的流程禁止重复提交，继续使用现有任务表单的禁用与轮询锁。

## 真实数据边界

行情节点只读取 `PonyMarketFeed`/`PonyHallData` 已验证的快照状态和任务上下文，不把行情写入任务输入。图表节点只展示任务事件中的 SVG 或分析产物，数据源不可用时显示空状态。模型置信度只显示上游预测中的值，没有值时为“未提供”。所有 Mock 或 synthetic 标记沿用任务和预测字段，界面显式显示“离线模拟”或“合成数据”。

## 验证

- 构建 `memory.js` 并运行资源预算与静态检查。
- 使用现有 Mock 控制台验证默认节点、任务轮询、失败/降级、报告和邮件状态映射。
- 验证新增/编辑/删除/移动/连线、循环拒绝、导入导出、恢复默认、未保存提示和键盘焦点。
- 验证 761px 以上的窄桌面窗口、右侧节点详情面板和专业模式/小马大厅切换。
- 不修改、不截图验证手机布局。

## 全屏画布与导航折叠补充

- 桌面专业模式画布占据左侧导航与内嵌对话栏之间的全部可用空间，截图中的顶部引导内容不再显示。
- 对话栏移动到专业模式画布内部底部，继续使用现有表单、会话、取消、历史和焦点逻辑。切换到小马大厅时恢复原有工作区位置。
- 画布使用统一的平移/缩放变换。点阵在整个视窗持续平铺，节点与连线使用相同坐标。节点可移至正负坐标，拖到视窗边缘时自动平移，点击「适配」可重新定位全部节点。
- 左侧导航支持持久化折叠。折叠状态保留图标、ARIA 标签、悬浮提示和键盘焦点，不改变移动端导航。
