# 第五阶段 C：加密备份与隔离恢复（2026-11-15）

用户已授权按上一轮下一步实施。本批交付只读预演、匹配计划的显式快照、认证校验及全新目录恢复，不对真实工作区执行 create/restore，也不启动恢复后的业务。

## 设计取舍

- 选择“停止写入后的完整快照”，不实现在线跨库事务或增量备份。相比直接复制目录，复制后校验来源稳定性并合并 WAL；相比在线数据库备份，组件/业务互斥与文件清单可同时覆盖正文、报告和 SQLite。未登记写入者仍必须由操作者停止，文件前后摘要检查不能替代这一要求。
- 输出一个整体 Fernet 认证加密包，密钥由独立 BACKUP_KEY 环境变量引用提供，不自动复用或导出 MASTER_KEY。相比明文 zip，开发密钥、邮件和正文不会以明文留在最终包内。临时克隆目录包含原始资料，使用用户私有临时目录并在完成/错误时清理；强制终止仍可能留下临时文件。
- 本批设置明确容量上限：最多 10000 文件、单文件 64 MiB、总内容 128 MiB；超限拒绝，不截断。适合当前本机工作区，流式/大规模备份另行设计。

## 步骤和接口

1. `backup plan`：只读遍历应用工作区、可选采集工作区及当前 CLI TOML；拒绝包含关系和符号链接/重解析点。输出来源、清单摘要、数量、排除规则、运行阻断项和确定性 plan_id。排除 .runtime、业务锁、日志、SHM、临时文件；WAL 纳入来源指纹，但最终保存合并后的 SQLite。外部数据/模型/配置引用不自动跟随。
2. 只读预演检查登记组件、业务锁及控制台端口，不自动停止任何服务。可通过私有临时克隆验证数据库和 vault_check；源 SQLite 不打开，不产生源 WAL/SHM。开发库必须有原配套 key，正式库必须由当前外部 MASTER_KEY 验证；不读取 profiles.secrets。
3. `backup create --expected-plan ... --output ... --key-env ...`：重新核对清单，取得组件终身锁、启动锁及原业务锁，复制来源；原始文件前后 SHA/集合及配置必须一致。只在克隆目录运行 SQLite backup/quick_check，得到独立 DELETE journal 数据库，再检查配套密钥。输出路径必须在来源之外且不存在，以临时文件及不可覆盖发布保证失败不产生完整包。
4. 加密包内保留版本化 manifest、来源指纹、文件大小/SHA、vault 配套要求和原 TOML 参考；不保留运行租约、停止请求或外部主密钥。公开输出不包含正文或密钥值。原 TOML 仅作为参考，恢复不会直接使用它连接原工作区。
5. `backup verify`：先认证解密，再检查版本/平台、文件数量与尺寸、重复/越界/Windows 特殊路径、zip 类型、清单与正文完全一致及 SHA，验证 SQLite 与密钥配套。错误统一结构化，不打印解密内容或原异常。
6. `backup restore --target ...`：目标必须从未存在、位于原来源之外，校验完成后在目标旁私有暂存构建。以不覆盖的目录发布，新目录含 app/crawler、原配置参考、安全 file/Mock 配置和恢复回执。恢复中断只清理本次暂存，不碰原数据或已有目标。
7. 恢复后的队列默认隔离：mail pending/retry/sending→uncertain，旧 outbox 同样处理；采集 queued/running/cancelling→interrupted/cancelled，保留检查点和 attempts；旧研究 training_jobs queued/preparing/training/cancelling 同样暂停，清除旧 PID/心跳；知识 pending/processing→failed 待显式 retry；未完成分析→failed。完成历史保留，原始包不修改，回执记录隔离计数与恢复后摘要。不创建 Store/Worker、不自动发送或执行任务。
8. 用临时合成资料演练完整链路、WAL、缺失/错误密钥、来源漂移、运行者阻断、包篡改、zip 路径、容量、发布中断、已存在目标及队列隔离；完整/基础 wheel 回归和真实工作区只读 plan。

## 边界

- 显式 create 会写入必要的互斥锁文件，可能创建空控制目录；不更改来源业务内容或执行恢复/checkpoint。plan/verify 不写来源或输出目标。
- 来源必须停止所有写入者。新组件被租约/业务锁阻止，外部不遵守锁的写入者只通过稳定性检查发现，不能承诺跨文件在线原子快照。
- 归档加密不等于保管好密钥；独立备份密钥和外部主密钥丢失仍无法恢复。只记录配套要求，绝不把外部主密钥写入包。
- 不支持跨平台/跨应用版本自动迁移，不做目录覆盖、自动调度、清理旧包或真实备份执行。恢复只证明结构/摘要/配套校验通过，不代表模型质量、来源授权或实际收件。

## 实施与验收结果

- 实现 backup_inventory、backup_quarantine 和 backup 三模块，新增四个 CLI 子命令、加密包忽略规则及基础 CI 专项。无新增依赖和前端修改，使用见[备份恢复手册](workspace-backup.md)。
- 新增 40 项专项全部通过：覆盖完整加密往返、原 EML/私有文件与开发密钥、正式密钥外置、WAL-only 已提交数据、未决邮件/分析/知识/采集/训练隔离、原业务状态不改、来源变化、认证/摘要失败、路径/ZIP 类型、版本/容量、目标冲突、原配置丢失、发布中断及无构造器副作用。
- 全量执行 521 项，520 通过、1 项既有 Windows 符号链接权限跳过，194.828 秒。随后补充恢复目录私有权限和回执 vault/版本元数据，对最终 40 项专项复验全部通过。
- 最终 wheel 在独立 Python 3.12 基础环境执行相同 40 项，全部通过，不需要研究/采集可选依赖。包内 10 个 operations 文件，无临时/缓存数据；已安装 CLI 在源码目录外完成四命令，并在删除原 TOML 后继续 verify/restore，未启动任何组件。
- Ruff、compileall、命名、仓库卫生及 diff 空白检查通过。SQLite 预算回调和路径测试循环变量的 lint 绑定问题已修正；规范化临时文件改用独立目录，避免与真实的 `.normalized` 文件名冲突，并确保连接创建失败也关闭已有句柄。
- 真实工作区只执行 plan：38 项清单、约 2.9 MB，当前 BACKUP_PORT_UNAVAILABLE 阻断；端口已占用时不进行数据库/密钥深校验，也不停止旧服务。对来源 38 个现有文件前后 SHA/集合核对一致，未生成真实包、未恢复或更改服务。报告为 `.tmp/workspace-backup-plan.json` 与 `.tmp/workspace-backup-readonly-check.json`。
- 实际 create/restore 均仅临时合成数据。当前实现明确不覆盖原目录，不自动复用生产主密钥作备份密钥，不启动任务，不承诺在线跨库原子快照。
