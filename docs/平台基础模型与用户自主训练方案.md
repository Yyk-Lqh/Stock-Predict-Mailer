# 平台基础模型与用户自主训练方案

日期：2026 年 10 月 25 日

状态：目标设计与后续实施路线，不代表下述模型发布、多用户隔离、继续训练或生成 API 已实现。

## 1 总体决定

保留此前自有电脑运行的约束，推荐先采用平台发布基础包、用户在自己的电脑使用和训练的交付方式。平台团队在自己的电脑整理授权数据、训练、验证、签署并发布基础模型；用户安装后可以选择平台模型，个性化训练生成自己的新版本，所有预测再进入相同的报告和邮件流程。

首选算法为 LightGBM，保留 Ridge 等简单基线。个人训练默认提供同配方重新训练及冻结基础模型后的残差适配；对兼容 LightGBM 模型提供有上限的继续训练实验。界面明确显示实际训练方法，不把所有方式称为微调。不优先引入深度预测模型或大模型微调。

开箱即用必须同时具备已发布模型和新鲜的预测输入。模型权重本身不能凭空产生最新行情、股票池和特征。正式发布前必须落实合法的自动行情/特征更新渠道，或提供平台生成的最新预测服务。历史演示数据只能用于体验，不能称为实时可用产品。

## 2 与当前代码的差距

当前 0.2.0 已具备多格式接入、清洗、时点校验、研究基线、可选 LightGBM、文本检索、模板报告和邮件组件。这些能力可复用，但尚没有正式基础模型注册表、独立推理服务、用户训练队列、完整训练进度、登录及多租户权限、真实行情认证或外部生成模型调用。

现有 research 命令把训练、验证和最新数据预测放在一次实验中，并保存本地 pickle。它不能直接充当“用户无需训练”的产品入口。需要拆成 train、evaluate、release、predict、report 五个职责，预测时只能加载已选定版本，不触发重新训练。

现有 label_rows 使用当批上传股票池的等权收益作为基准。平台和个人股票池不同时，这会改变学习目标和比较口径。必须先固定标签、收益基准及历史股票池规则，才能声称个人模型与平台模型可比。仅上传一只股票不足以评价横截面选股排序；不应把单股票目标均值为零造成的低误差当成效果。

现有上传中心是可信本机单用户工具，配置里的 principal 不是认证身份；目录按用户命名也不是多租户安全边界。不能简单开放公网或把 owner 替换为用户输入就宣称实现用户隔离。

## 3 三种容易混淆的能力

### 3.1 预测模型训练

输入为时点正确的行情、财务等特征及成熟标签，输出为收益排序、概率或风险预测模型。它直接影响量化预测，是平台预训练和个人训练的必需能力。每次训练都要关联数据快照、特征和标签契约，并做时间隔离评价。

### 3.2 大模型微调

输入为高质量的指令及回答样本，目标可以是文风、结构、任务遵循等。它不是把用户 CSV 传给生成 API，也不能保证获得股票预测能力。权重微调还增加数据外发、样本治理、算力及独立评测成本。本项目 MVP 不需要；先采用外部生成 API、结构化预测输入、引用约束和模板降级。

### 3.3 私有知识库更新

解析文档、更新版本及权限、生成检索索引，用于提供及时且可追溯的资料，不改变预测模型或大模型权重。项目已有私有知识库目标，因此文档更新与撤权是必需能力；高质量语义 embedding、重排序、PDF/OCR 可分步升级。上传资料默认归用户私有知识库或私有数据集，不能自动加入平台训练集。

## 4 算法与个性化方式

### 4.1 LightGBM 首选

适合当前日频结构化特征、CPU 训练和低延迟推理。官方 train 接口允许以 init_model 继续训练。工程上应从不可变父版本创建子版本、冻结输入契约、限制新增 boosting 轮次并比较独立验证结果；继续训练不等于全量联合重新训练，也不保证适应新分布。

推荐并列三条路线：第一，基于平台的特征及训练配方，对用户授权数据重新训练；第二，保持基础模型冻结，在训练期交叉拟合或严格向前预测得到的残差上训练小型适配器；第三，在同任务和特征兼容时从基础 Booster 追加有限轮次。

残差适配同样可能过拟合。若父模型已在相同样本上训练，不能把它对该样本的训练内预测直接视为独立训练信号；优先使用父模型训练截止日之后的成熟样本，或按时间交叉拟合。用户增加平台不支持的特征时，训练独立特征版本或适配器，不强塞给原 Booster。

继续训练只用少量近期数据可能偏向局部分布。若数据分发许可允许，可使用受控的历史回放样本；否则仅在用户已获权的数据上训练，或使用适配器。不得因为基础模型可下载，就假定其原始训练数据也允许下载。

### 4.2 Ridge 与逻辑回归

当前 scikit-learn Ridge 没有 partial_fit；默认在用户数据上按已发布配方重新拟合，属于继承配方而不是继承权重。不能宣称从 Ridge 基础权重直接增量训练。

LogisticRegression 的 warm_start 可复用求解初值，但不是在线小批次学习契约，也不等价于保留历史样本作用。需要真正的在线线性更新时，另设 SGDRegressor/SGDClassifier 模型族，并从一开始就设计 partial_fit 训练及状态保存。

### 4.3 随机森林

warm_start 可以增加树，但不会把旧树改造成已用新样本重训的树。MVP 默认重新训练或改用冻结基础预测加适配器，不把增加树称为旧模型微调。个人开发者不需要同时维护森林和多个 boosting 框架。

### 4.4 SGD 在线模型

partial_fit 提供显式的小批次更新，适合后续数据流与低内存需求，但对特征尺度、顺序、学习率和漂移敏感。固定预处理或实现严格兼容的在线预处理；不能任意更新 scaler 却沿用旧系数。训练状态和样本消费水位均版本化，重复事件不能重复学习。它是后续备选，不是首版取代 LightGBM 的理由。

### 4.5 XGBoost 与神经网络

XGBoost 官方提供以 xgb_model 继续训练的示例，可作为 LightGBM 的替代，不建议 MVP 同时实现两套。两者都需固定任务、特征语义和类别编码，并通过独立测试决定是否值得继续训练。

LSTM、TCN、Transformer 等神经网络可在兼容结构上做权重微调，但需更多序列数据、正则化、算力与遗忘评测。已有 GPU 不构成升级依据。预测网络的权重微调与语言模型微调是两件不同的工作，均可以后置。

## 5 基础模型如何交付

### 5.1 平台发布流水线

使用平台持有使用权的数据快照，构建时点特征与成熟标签；按时间滚动验证并保留最终测试期；与简单基线、既有平台版本比较；生成模型卡；完成数据授权、特征一致性、加载与预测烟雾测试后，由平台管理员发布不可变版本。实验完成与允许产品使用是两个不同状态。

模型卡写明市场、股票池、适用日期与周期、训练及标签成熟截止时间、基准、验证区间、指标和不确定性、交易约束与失效条件。没有真实数据验收的合成模型只进入 demo 通道，不进入 stable 通道。

### 5.2 发布包内容

至少包含原生模型文件、特征定义、特征顺序及 dtype、缺失规则、预处理参数、标签及基准定义、适用市场、训练数据版本指纹、评估摘要、依赖锁文件、许可证与模型卡。LightGBM 使用原生文本/模型导出；线性模型可用不含对象的 NPZ 加 JSON 重建推理。用户不能上传任意 pickle 让服务端反序列化。

发布清单包含文件哈希并由平台签名；客户端验证信任的签名及哈希，再进行兼容性检查。哈希只能发现内容变化，不单独证明发布者身份。未通过校验的下载不替换当前版本。更新采用下载到临时目录、验证、原子切换指针，旧版本保留以便回滚。

公开 GitHub 仓库继续仅保存代码、配置示例、文档与非敏感评估摘要。是否分发模型权重、回放数据及特征，需要单独确认许可和隐私；不默认把它们提交到当前公开仓库。

### 5.3 开箱即用的两种实际形态

首选本机形态：平台提供基础模型包及有权分发的自动更新行情/特征包，用户应用自动检查新鲜度、构建相同特征、完成本地推理，再调用允许的生成 API 和邮件服务。用户不需训练或整理 CSV，但电脑开机、数据授权和自动更新仍是运行条件。

如果不能合法分发行情或特征，可在平台自有常开电脑上集中推理并提供有权限的预测结果接口；代价是登录、可用性、访问控制、带宽和运维。不是租云的必然要求，也不是当前上传页面直接改地址就能完成的能力。

“不训练即可用”不代表“没有新鲜输入也可预测”。MVP 发布门槛必须包括自动数据更新方案。没有新鲜数据时明确展示最后行情时间、拒绝伪装当前预测，允许查看旧报告。

## 6 用户上传后的训练流程

1. 认证并确定 owner，或在独立个人电脑中绑定本地工作区。保存私有原件及不可变数据快照，默认 platform_training_allowed=false。
2. 复用接入中心完成格式、列名、日期、重复与异常检查；补齐来源、口径、单位和实际可用时间。格式检查通过不等于有训练许可或时点认证。
3. 按所选任务验证样本、历史跨度、股票数量、标签成熟时间及缺失率。只有单只股票时不能直接按平台横截面任务评价；应补充足够股票，或创建独立的单序列任务及模型家族。
4. 选择一个固定基础版本和训练方法，生成不可变训练规格，包括父版本、数据、特征、标签、参数、切分和预算。界面仅展示该算法实际支持的方法。
5. 进入本地训练队列，用受限子进程运行。报告排队、预处理、训练迭代、验证、封装进度；不伪造整体百分比与完成时间。
6. 在与基准相同、且双方未使用的评价样本上比较；通过检查后保存个人候选版本。失败保留可解释错误类别，清理临时资源，不替换正在使用的模型。
7. 用户查看变化与适用范围后显式选择模型。默认保留平台版或上一个已选个人版；个人训练结束不自动宣称优于平台。
8. 预测、报告和邮件每次固化实际 model_version、feature_version、dataset_snapshot 和时间，不因日后切换模型改写历史结果。

个人上传数据中新增字段若与基础输入不兼容，平台给出“重新训练新特征版本”或“单独适配器”选项；不自动截断、重排或用零填充来强行兼容。跨市场、跨周期和目标改变也不算原模型微调。

## 7 模型与数据隔离

### 7.1 注册表与目录

分别维护 platform 和 personal 命名空间。每条模型至少含 model_id、version、owner_id、scope、parent_version、adaptation_method、data_snapshot、feature_contract、label_contract、train_label_end、status、artifact_hash 和评估引用。重新训练继承配方时，parent_version 表示来源关系，不宣称权重继承。

平台版本目录仅发布进程可写；个人训练只能写当前 owner 的临时区与个人模型区。基础版本只读加载，不在原对象上 fit、refit 或保存。当前选择单独存为 user_preferences，不通过移动文件或重命名平台模型实现切换。

发布状态建议为 draft、evaluated、published、deprecated、revoked；训练任务状态为 queued、preparing、training、evaluating、succeeded、failed、cancelled、interrupted。训练成功不等于已发布，也不等于被用户选中。

### 7.2 本地交付 MVP

不同客户在各自电脑运行时，用户数据天然不进入平台工作区；应用默认没有回传训练数据的逻辑。基础模型签名确保平台版本可辨认，个人模型单独保存。用户对自己电脑拥有管理员权限时，不能承诺平台能阻止其修改本地文件；应通过签名发现基础包变化，不把这一点包装成远程租户安全。

多人共享同一台可信电脑时，首版优先使用独立操作系统账户与独立工作区。配置路径分开只解决管理问题，不替代 OS 文件权限。

### 7.3 共享服务后的要求

若多用户通过同一个网页服务，改用具备认证、会话和授权的应用层，例如 FastAPI 配合适当认证方案；服务端从身份取得 owner_id，不相信请求体的 user_id。数据、任务、日志、模型、引用、报告、邮件和缓存接口都检查 owner；后台 worker 依据受信任务记录取得权限范围。

目录、模型清单和数据库行级 owner 条件是必要措施；不可执行数据与固定训练模板进一步降低风险。敏感场景还需不同 worker OS 身份、容器或独立机器的文件与资源边界。一个共享账户下的 subprocess 主要用于稳定性和资源管理，不能当作抵抗恶意用户的强安全沙箱。

不接受用户自定义训练脚本、可执行插件或任意序列化模型。请求其他用户的 ID、路径遍历、日志读取、报告下载和跨用户队列取消必须有越权测试。本地生成模型、embedding 和检索同样遵循 owner 过滤。

### 7.4 平台训练授权

默认只允许使用平台自有/已授权数据。用户授权应指明用途、范围、期限、可否转授权、可否分发衍生模型，并保留版本记录。分享报告、使用平台预测或接受生成 API 均不等于授权其资料训练平台模型。

撤回授权后，停止后续训练与回放，更新数据使用清单；是否需要重训及撤销已发布版本按事先约定的数据治理策略处理，不承诺删除原文件就能从已有权重精确消除影响。

## 8 独立比较与模型切换

训练集负责拟合，调参验证集负责选参数/早停/校准，最终比较集负责比较个人候选与固定平台版。最终比较集必须晚于双方训练所用标签的结束时间，且不参与特征选择。平台模型如果已经见过这段数据，就不能拿这段数据作为独立共同测试集；需更晚的成熟标签、历史对应的旧基础版或等待前向观察。

双方采用相同输入时点、标签定义、基准、股票池及可评价样本，报告有效交集和因缺失而剔除的数量。个人版本覆盖范围更窄时同时报告覆盖变化，不能只挑个人模型表现好的股票。

排序以逐日 Rank IC、分组稳定性和 Top-K 诊断为主，分类以 log loss、Brier 与校准为主，风险预测按对应误差指标评价。成本后组合表现需相同市场约束；当前简化成本诊断不升级宣称为可交易回测。按日期做成对区块 bootstrap，展示差值及区间；不同市场阶段、行业和流动性分段分析必需。

多次上传、反复试参数会导致对测试集的间接过拟合。保存实验次数、预算和切分，保留不参与选择的最终观察期。小样本时显示“证据不足”，不显示已改善；显著或稳定变差时不自动启用。所有模型都可归档，产品默认推荐仍以验收门槛为准。

比较结果示例（纯示意，不是实际模型效果）：平台版 Rank IC 0.018，个人版 0.020，差值 0.002，区间跨零时结论为未证明改善，而不是“提升 11%”。同分或尺度不同的排序分数不解释为上涨概率。

## 9 本地资源与成本控制

先用 SQLite 持久队列加单训练 worker，每次最多一项重训练；推理与报告使用独立轻量进程，训练不阻断已发布模型。任务有心跳、超时、取消与中断状态；进度通过轮询任务记录读取，失败不能改写 current 指针。重复提交以任务规格指纹合并，提交新候选不能覆盖旧产物。

从 n_jobs=2、一个训练任务、有限 boosting 轮次与三到五组参数实验起步，具体时限由硬件小样本基准确定。线程限制不是内存硬隔离；Windows 若需要硬限额应使用 Job Object 或受控环境，Linux 可用 cgroup。排队前估计数据展开与特征内存，超限拆分或拒绝，避免系统被交换内存拖垮。

GPU 留给确有基准收益的任务，不默认启用。缓存仅复用相同 owner 权限、数据快照和特征版本的结果，不能跨私有数据合并。训练产物设保留策略，保留已选、已发布和审计需要的版本，临时文件可清理；不能删除活动模型依赖的基础版本。

外部生成 API 只接收获准的结构化预测和最少证据片段，设置每日报告数、输入 token、重试和金额预算。训练不会调用生成 API；生成 API 不接收完整训练 CSV。价格按选定供应商当时政策另行核验，不在此给出未经确认的报价。

## 10 MVP 实施路线与验收

### 阶段 A 固定研究契约并拆分推理

固定市场、周期、基准、历史股票池和可用时点契约，替换随上传股票池改变的目标定义。实现只加载已发布模型的 predict，训练独立运行。验收同一模型、快照与契约可复现，预测不触发 fit，不允许特征错序悄悄通过。

### 阶段 B 平台模型发布

完成平台模型注册表、模型卡、原生格式、签名/完整性、稳定版指针和回滚。先发布明确标记的 demo 包测试安装，再用真实授权数据完成正式评估与 stable 发布。验收无本地训练数据也能加载模型；真实当前预测还必须通过自动新鲜数据输入验收。

### 阶段 C 用户重新训练及公平比较

复用上传中心，新增固定规格训练队列、进度、失败恢复、owner 分区、独立比较与用户版本选择。先支持同配方重新训练和残差适配，不承诺权重微调。验收任务无法写平台目录、失败后旧模型可用、比较不使用双方见过的标签。

### 阶段 D LightGBM 有限继续训练

实现算法能力声明和兼容性门禁、不可变父子版本、限制追加轮次、数据回放权利检查及漂移评价。与重新训练和适配器在同一评价集比较。没有稳定优势时保留为实验选项，而不是默认工作流。

### 阶段 E 分析和邮件产品闭环

接入确定的外部生成 API，保持结构化事实/预测/推断区分，严格引用、权限及模板降级；邮件固化所用模型版本，切换后不改旧报告。验收无证据不得补造解释，模型切换不影响其他用户，SMTP 模糊结果不盲目重发。

### 阶段 F 真实运行与共享服务升级

在真实数据、模型发布及十交易日影子运行完成后再宣传开箱即用。不同客户电脑先采用本地交付。确需共享服务才引入认证、租户测试与强隔离，不能把当前回环上传中心直接对外开放。深度模型、在线 SGD 和大模型微调均在实测收益或业务需求成立后另行规划。

首版不需要同时建设多框架 AutoML、分布式训练、独立 GPU 集群或语言模型微调平台。路线顺序不等于工期承诺；真实数据认证和共同测试标签成熟是无法靠增加算力跳过的依赖。
