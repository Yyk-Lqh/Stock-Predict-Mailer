# 数据接入中心设计

日期：2026 年 10 月 25 日

## 范围与决定

在既有本地架构中增加数据接入中心。提供独立 incoming 投放目录、命令行扫描及仅绑定回环地址的上传页面。目录便于批量采集，页面便于人工上传和查看清洗问题，两种入口复用同一处理器。暂不引入云存储、账户系统和常驻数据库服务。

## 流程

内容与扩展名辅助识别 → 原件内容寻址归档 → 读取表格或文本 → 中文英文列名映射 → 分类和确定性清洗 → 清洗结果、异常行与质量摘要 → 缺失元数据确认 → 显式发布行情快照。上传后自动执行一次处理；后续可补充元数据重新处理，不修改原件。

支持 CSV/TSV、XLSX、JSON/JSONL、Parquet、SQLite、TXT/Markdown。Excel 多工作表、SQLite 多表分别处理。旧 XLS、压缩包和 PDF/图片只归档并明确提示不支持自动解析，不声称具备 OCR。数据库只读，不执行上传 SQL 脚本。不把所有新格式承诺为无条件支持。

自动识别行情、财务、新闻、宏观、文本和未知表格。分类仅决定清洗规则，不证明业务含义正确；允许手工覆盖类别与字段映射。只有行情可对接现有训练快照，其他类型先保存规范化结果，待对应特征或知识库入口验收。

## 清洗与可靠性

安全操作包括去除表头及文本首尾空白、常见日期规范化、明确的数值分隔符处理、证券代码表示规范化、删除完全重复行、拒绝无效日期/非有限数值及异常 OHLC。矛盾的同证券同日记录全部隔离，不按文件先后覆盖。空值不填零、不前向或反向填充，缺失交易日不补价，不推断复权因子、数据商、股数单位或历史可用时间。

来源、价格口径、成交量单位与 available_at 缺失时标记待确认。历史可用时间不得以当天收盘或当前上传时间冒充；即使字段由用户提供，也仅标记 supplied，不视为独立认证。无时区时间标记待确认。无法分类的表格保留并提示映射，不丢弃原件。

## 文件与状态

workspace/intake/incoming 是投放目录；archive 存原件；jobs 存每次处理结果、规范化 JSON 与 Parquet、异常行和摘要。文件内容哈希作为上传 ID，相同文件不重复归档。处理选项参与处理版本哈希；每次重新处理保留旧版本，避免悄悄改写历史输出。私有文件和结果不进入 Git。

## 页面

页面的单一任务是上传资料并判断是否可以使用。采用白底、深蓝主操作、灰色辅助信息、橙色待确认、红色异常，标题使用微软雅黑，正文使用系统中文字体，数据使用等宽字体。上方为投放区，中部为处理记录，下方为选中文件的元数据、表格预览与问题清单；状态和问题内容形成主层级，不用装饰性图表。

设计自检：与既有 HTML 研究报告区分，本页面以文件和清洗结果为主，不展示虚构的股票收益指标。上传、重新清洗和发布快照三个动作名称固定；缺少来源等信息时直接说明补充项。移动窄屏单列，支持键盘操作与可见焦点。

## 边界与验收

网页仅本机可访问，限制 Host、Origin、请求大小并检查每次 API 访问令牌，拒绝任意路径读取。上传文件不执行，网页使用文本节点显示原文。限制文件、表格行数、XLSX 解压体积。超限或不支持文件有明确记录，不尝试危险降级。

验收包括编码和分隔符、多工作表、多格式中文映射、完全重复删除、冲突记录隔离、无可用时间不发布、类型覆盖、元数据补充、内容寻址幂等、接口安全、上传到快照完整路径及原有测试回归。浏览器 QA 使用 gstack browse；若环境限制无法运行，单独记录，不将 HTTP 测试冒充视觉验收。
