# 知识库与报告

CLI 的 `kb-*` 命令与 `/api/knowledge` 共用同一套私有知识库：原件加密保存在 `workspace/private-knowledge`，检索走 FTS5 关键词、可选 Embedding 与带有效期的关系表。命令行入口是兼容门面，只做三件事——把配置翻译成知识库身份、把入队翻译成同步、把证据还原成既有字段——不再维护第二套存储。因此 `kb-add` 支持 PDF/DOCX/TXT/Markdown/CSV/XLSX/JSON，需要 `knowledge` 可选依赖，并在命令返回前完成解析、清洗与建索引；失败时报错，不静默返回。

时间按「日」比较：`--published-at` 与 `--available-at` 的时分秒归入当天，检索按 `available_date <= 截止日期` 过滤。这是有意的精度让步，因为引擎本身按日比较；门面若改用更严格的小时比较，会出现「检索得到、校验却拒绝」的自相矛盾。需要小时级保守性的调用方，把 cutoff 前移一日再传入。

权限按 principal 隔离：同一份资料授权给 N 个 principal 时生成 N 份加密副本。`kb-revoke` 撤销该逻辑槽位下的全部副本，只停用、不删除原件，也不复活旧版本；硬删除需走 `DELETE /api/knowledge/documents/<id>`，不可恢复。principal 是受信本机命令行配置，不是可对外开放的身份认证服务，不能把当前 CLI 当作多租户安全系统。原文件、SQLite 与已导出的 HTML 仍需操作系统文件权限保护。

版本按逻辑槽位（源文件绝对路径的哈希）管理：同一槽位上传新版本时旧版本停用但保留，检索只在该槽位取「截止日可用且最新」的一个版本。因此 `--cutoff` 早于新版本可用日期时会回落到当时有效的旧版本——这是时点回放，而不是「永远只看最新版」。旧版 `state.sqlite3` 中的知识表已停用，仅作历史留档；它既不保存原件也不保存路径，无法据此重建，因此不提供迁移脚本。

报告明确区分输入事实、模型预测、资料原文、推断与未知项。所有标题和文档正文进行 HTML 转义，无网络脚本或远程资源。文档中的指令不会执行。当前未调用大模型，不能声称已实现完整生成式 RAG；后续接入需单独验收结构化输出、引用支持关系、外发白名单与失败降级。

```powershell
uv run stock-predict-mailer legacy --config config/local.toml kb-add path/to/note.md --published-at 2026-10-23T18:00:00+08:00 --available-at 2026-10-23T18:10:00+08:00 --allow owner
uv run stock-predict-mailer legacy --config config/local.toml kb-search "策略风险" --cutoff 2026-10-24T20:00:00+08:00
uv run stock-predict-mailer legacy --config config/local.toml report <experiment_id> --query "策略风险"
uv run stock-predict-mailer legacy --config config/local.toml kb-revoke <document_id>
```

`kb-*` 与 `report` 属于旧入口，须加 `legacy` 前缀（新默认入口只保留结果消费链路）；同样原因，这些命令需要 `.[research,trees]` 可选依赖。

## 批量导入

控制台一次传一份文件，种子库靠它灌不进去。批量入口在默认 CLI 上，不需要 `legacy` 前缀，也不依赖 `research/trees`：

```powershell
# 1. 按目录结构生成清单骨架，只写 CSV，不导入
uv run stock-predict-mailer --config config/local.toml knowledge-import data/inbox --write-manifest data/inbox/manifest.csv

# 2. 用表格填写来源、日期与标签（UTF-8 BOM，Excel 直接打开不乱码）

# 3. 试运行：打印计划与元数据，不写库
uv run stock-predict-mailer --config config/local.toml knowledge-import data/inbox --manifest data/inbox/manifest.csv --dry-run

# 4. 正式导入，并顺带处理队列
uv run stock-predict-mailer --config config/local.toml knowledge-import data/inbox --manifest data/inbox/manifest.csv --process
```

清单列为 `path,logical,source,document_date,available_date,valid_to,companies,industries,topics,stock_codes`，与 `metadata()` 的白名单一致；多值单元格用 `;`、`|`、`、` 或 `，` 分隔。出现未知列直接报错，不静默丢标签。

四条约定：

1. **`available_date` 不静默取当天**。取值顺序为清单 → `--available` → `document_date`，三者皆无则该文件失败并说明原因；只有显式 `--assume-available-today` 才用当天，并计入 `warnings.available_date_inferred`。这个字段事后无法修复：把历史资料标成「今天可用」，回测就会让它提前生效。
2. **有清单时以清单为准**。未登记的文件跳过（不猜元数据），清单登记但文件不存在的报失败。因此清单本身就是一份可核对的入库台账。
3. **幂等按 `(logical, 内容哈希)`**。重复执行不会产生重复版本；内容变了则成为同一槽位的新版本，检索仍按截止日期选当时最新的一个。
4. **`logical` 留空时按目录推导**（`公告/甲公司/x.txt` → `公告/甲公司/x`）。文件名里带日期的，务必在清单里改写成不含日期的稳定槽位，否则每次更新都会变成一份新资料，而不是同一份的新版本。

导入只负责入队：不加 `--process` 时，仍需 `knowledge-worker --once` 或常驻 worker 处理。命令行的 principal 与控制台会话可能落在不同 owner 上，若控制台看不到刚导入的资料，用 `STOCK_PREDICT_MAILER_KB_KEY=<控制台密钥>` 重新导入；输出末尾的 `note` 会给出该 owner 的前缀，便于比对。有文件失败时命令返回码为 2。


HTML 与 JSON 生成于本地 workspace/reports；不进入 Git。数据年龄按自然日显式展示，演示的历史数据不伪装成当前行情。无符合条件资料时不补造引用。
