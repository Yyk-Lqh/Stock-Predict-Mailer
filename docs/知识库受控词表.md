# 知识库受控词表

> 本文件是 `logical` 路径与 8 个标签键的**唯一取值来源**。词表外的写法一律视为录入错误，不视为"个人习惯"。变更需走第七节的评审流程。

适用范围：`private_knowledge` 全部写入路径（控制台上传、`knowledge-import` 批量导入、`kb-add` 门面）。三者共用 `metadata()` 白名单，因此本文件对三条路径同时生效。

---

## 一、为什么必须是受控的

### 1.1 `logical` 是版本槽位，不是分类标签

系统按 `logical` 归并版本：同一槽位重传即产生新版本，旧版本 `active=0` 但原件保留，检索按 `as_of` 选"截止日可用且最新"的那一个。这条机制决定了 `logical` 的两条硬约束：

| 约束 | 违反后的后果 | 是否可修复 |
|---|---|---|
| **不得含获取日期**（`20261028`、`_v2`、`_终版`） | 每次更新变成一份"新文档"，`as_of=2026-09-01` 会同时命中 6 月版与 9 月版，两条结论互相矛盾却都"当时有效" | ❌ 不可逆，只能整批下架重导 |
| **不得把"类型"当第三级**（`公告/600000.SH/临时公告`） | 同一公司的 N 份临时公告挤在一个槽位，后传的覆盖前传的，检索只能看到最后一份 | ❌ 前一份已 `active=0`，需逐份重设槽位 |

### 1.2 修订测试：判断该不该新建槽位

拿到一份资料，问一句：

> **它出了修订版时，应该覆盖旧版，还是应该与旧版并存？**

- 应覆盖 → 同一槽位，`logical` 不变，重传即新版本。
- 应并存 → 不同槽位，第三级必须能区分两者（用报告期、方案名、对象名，不用日期）。

这条测试同时解决"报告期算不算日期"的争议：`2026年第三季度报告` 是**身份**（同一份三季报只可能有一版，更正版才覆盖），允许；`20261028` 是**获取时间**，禁止。

### 1.3 `topics` 自由生长必然退化

不做受控时，三个月内必然出现"产能扩张 / 扩产 / 新增产能 / 产能释放"四个标签各指向一部分文档，任何单一标签的召回都只有四分之一。词表的作用不是"分类完整"，而是**让同一个概念只有一个写法**。因此宁可词少、允许留空，也不接受同义词。

### 1.4 系统侧的硬限制（写错会直接失败，不会静默降级）

| 限制 | 位置 | 表现 |
|---|---|---|
| 只接受 8 个键：`source / document_date / available_date / valid_to / companies / industries / topics / stock_codes` | `service.py` `metadata()` | 多一个键 → 整份资料 `INVALID_INPUT`，不是忽略该键 |
| `logical` 长度 1–200，文件名 ≤200 | `service.py` `upload()`、`importer.py` | 超长即失败，批量导入时该文件进 `failed` |
| 日期只能是 `YYYY-MM-DD` | `service.py` `day()` | `2026/10/28`、`2026年10月28日` 一律拒绝 |
| 每个标签列表 ≤40 项，单项 ≤100 字符 | `service.py` `metadata()` | 超限整体拒绝 |
| `stock_codes` 会被规范化 | `service.py` `stock_codes()` | `600000sh`、`600000 sh` 可识别，`600000` 无后缀也可（explicit 模式），但建议统一写 `600000.SH` |
| 单文件 1 字节–10 MiB；格式限 `.txt/.md/.csv/.json/.docx/.xlsx/.pdf` | `service.py`、`parsing.py` | `.doc/.xls` 不支持，需先另存 |

## 二、一级域（8 个，受控）

一级域**限定为以下 8 个**，新增需第七节评审。一级域同时是 `logical` 的第一段。

| 一级域 | 二级键 | 收什么 | 不收什么 | 主要来源 |
|---|---|---|---|---|
| `公告` | 证券代码 | 交易所披露原文：定期报告、临时公告、问询回复、权益变动 | 券商点评（→`研报`）、整理后的财务表（→`财报`） | 上交所/深交所/北交所/巨潮 |
| `财报` | 证券代码 | 结构化财务数据：三大表、财务指标、分部数据（xlsx/csv 为主） | 财报原文 PDF（→`公告`） | 数据商、公司披露 |
| `研报` | 机构 | 外部研究观点：深度报告、跟踪点评、行业策略 | 新闻综述（→`产业`）、内部结论（→`方法`或任务产物） | 券商研究所 |
| `产业` | 行业 | 产业链结构、产能、价格、开工率、竞争格局、调研纪要 | 单公司公告（→`公告`）、宏观总量（→`宏观`） | 内部研究、行业协会、媒体 |
| `宏观` | 指标族 | 宏观数据与政策解读：货币、财政、物价、就业、外贸 | 行业景气（→`产业`） | 统计局、央行、财政部 |
| `供应链` | 公司或行业 | 上下游关系、客户/供应商集中度、替代关系（含 `subject/predicate/object` 结构行） | 泛泛的产业链描述（→`产业`） | 内部研究、招股书摘录 |
| `制度` | 子类 | 内部规则：资料评级、引用规范、投资纪律、权限边界 | 工程规范（留 Git，不入库） | 内部制度 |
| `方法` | 子类 | 方法论与口径：估值模型、指标定义、回测约定、报告模板 | 一次性分析结论（属任务产物） | 内部研究 |

> 判定口径沿用方案原文的一句话：**"这条知识需要引用出处、且不随代码版本变化"才进库。** 49 篇工程文档一篇都不入库。

## 三、逐域命名规范

通用格式 `<一级域>/<二级键>/<稳定名称>`，三段齐全。第三段是**这份资料的稳定唯一名称**，不是"类型名"。

### 3.1 `公告/<代码>/<公告名称>`

| 示例 | 说明 |
|---|---|
| `公告/600000.SH/2026年第三季度报告` | 报告期是身份，允许 |
| `公告/600000.SH/2025年年度报告` | |
| `公告/600000.SH/关于回购股份方案的公告` | 事项名，不含日期 |
| `公告/600000.SH/2026年第一次临时股东大会决议` | 届次是身份，允许 |

反例：`公告/600000.SH/临时公告`（多份挤一个槽位）、`公告/600000.SH/20261028公告`（含获取日期）、`公告/浦发银行/三季报`（二级键必须是代码，不是公司名）。

### 3.2 `财报/<代码>/<报告期>`

| 示例 | 说明 |
|---|---|
| `财报/600000.SH/2026Q3` | 统一 `YYYYQn`；年报用 `2026A`，半年报 `2026H1` |
| `财报/600519.SH/2025A` | |

反例：`财报/600000/2026年三季度`（缺市场后缀、报告期格式不一，同一份会变成两个槽位）。

### 3.3 `研报/<机构>/<主题>`

| 示例 | 说明 |
|---|---|
| `研报/中金公司/半导体设备国产化率跟踪` | 持续跟踪型：不带年份，每期覆盖为版本 |
| `研报/中信证券/电力设备行业2026年中期策略` | 一次性专题：带年份区分不同专题 |

机构用**简称**（`中金公司`、`中信证券`、`华泰证券`），不用全称"中国国际金融股份有限公司"——二级键是枚举，不是实体名，实体名放 `companies`。

反例：`研报/中金公司/半导体`（同机构同主题的多份研报会互相覆盖）。

### 3.4 `产业/<行业>/<主题>`

| 示例 | 说明 |
|---|---|
| `产业/电力设备/动力电池产能格局` | |
| `产业/电子/晶圆代工价格月度跟踪` | 月度跟踪不带月份，覆盖为版本 |
| `产业/医药生物/集采政策影响梳理` | |

行业名必须取自第六节申万一级表，否则 `industries` 与 `logical` 会出现两套口径。

### 3.5 `宏观/<指标族>/<主题>`

指标族受控：`货币政策`、`财政政策`、`物价`、`就业`、`外贸`、`增长`、`金融稳定`。

| 示例 | 说明 |
|---|---|
| `宏观/货币政策/利率走廊机制说明` | |
| `宏观/物价/CPI分项权重调整说明` | |

反例：`宏观/2026年10月CPI`（指标名+月份当槽位 → 每月一份新资料，`as_of` 回放会同时命中全部月份）。

### 3.6 `供应链/<公司或行业>/<关系主题>`

| 示例 | 说明 |
|---|---|
| `供应链/中微公司/关键零部件供应关系` | 二级键用公司简称，与 `companies` 全称对应 |
| `供应链/动力电池/正极材料供应格局` | 行业级关系表 |

CSV 结构化关系行（`subject,predicate,object,source,as_of`）也归此域，一份文件一个关系主题，不按关系逐条建槽位。

### 3.7 `制度/<子类>/<名称>`

子类受控：`合规`、`权限`、`流程`、`模板`。

| 示例 | 说明 |
|---|---|
| `制度/合规/资料评级与引用规范` | |
| `制度/权限/知识库角色可读域清单` | |

### 3.8 `方法/<子类>/<名称>`

子类受控：`估值`、`指标`、`回测`、`报告`。

| 示例 | 说明 |
|---|---|
| `方法/估值/自由现金流折现口径` | |
| `方法/回测/时点可用性判定规则` | |
| `方法/指标/毛利率口径与调整项` | |

### 3.9 通用规则

1. 分隔符只用 `/`（半角），**不出现空格、中文括号、`#`、`?`、`*`、`|`**（`|` 是 CSV 分隔符）。
2. 全路径 ≤200 字符；Excel 里超长时按第三节的域规则缩写主题词，不要缩写一级域。
3. 同一份资料只归**一个** `logical`；多归属需求交给 `industries`/`topics`/`companies`。
4. 二级键在同一域内必须同构：`公告` 全是代码、`研报` 全是机构，不允许混用。
5. 已入库的 `logical` 不做改名。确需改名时按"下架旧槽位 + 重传新槽位"处理，并在台账注明，避免新旧槽位并存两个活动版本。

## 四、`topics` 受控词表（30 词）

30 个词分 6 组，覆盖 `公告`/`财报`/`研报`/`产业`/`供应链` 五域。**`产业` 与 `供应链` 是主要使用方**；`宏观`、`制度`、`方法` 默认留空（理由见 4.3）。

### 4.1 词表

| 组 | 词 | 含义边界（超出即不适用） | 常用域 |
|---|---|---|---|
| **A 供需与景气** | `产能扩张` | 新增产能、扩产计划、投产节奏；不含单纯产量增长 | 产业、供应链、研报 |
| | `供需缺口` | 供给与需求的量化缺口或短缺判断 | 产业、研报 |
| | `价格上行` | 产品价格/价差上行；含提价、涨价函 | 产业、研报 |
| | `库存周期` | 渠道/厂商库存的主动与被动阶段判断 | 产业、研报 |
| | `开工率` | 产能利用率、开工负荷 | 产业 |
| **B 竞争与格局** | `行业集中度` | CRn、份额变化、出清程度 | 产业、研报 |
| | `国产替代` | 进口替代、自主可控、验证导入 | 产业、研报、供应链 |
| | `竞争加剧` | 新产能涌入、份额战；不含价格战本身 | 产业 |
| | `新进入者` | 跨界进入、新玩家投产 | 产业、供应链 |
| | `价格战` | 主动降价竞争；与 `价格上行` 互斥 | 产业 |
| **C 风险与合规** | `供应链风险` | 断供、单一来源、交付连续性 | 供应链、研报 |
| | `客户集中` | 前五大客户占比、单一大客户依赖 | 财报、供应链 |
| | `商誉减值` | 商誉/长期资产减值计提 | 财报、公告 |
| | `监管处罚` | 行政处罚、监管措施、立案调查 | 公告、制度 |
| | `退市风险` | 财务类/交易类退市指标触发 | 公告、财报 |
| **D 财务与估值** | `盈利预告` | 业绩预告、业绩快报、指引 | 公告、财报 |
| | `现金流压力` | 经营性现金流恶化、应收/存货占用 | 财报 |
| | `毛利率变动` | 毛利率同比/环比变化及其归因 | 财报、研报 |
| | `估值切换` | 估值方法或可比区间切换 | 研报、方法 |
| | `分红回购` | 分红方案、回购计划与注销 | 公告、财报 |
| **E 治理与资本** | `股权变更` | 控股股东/实控人变化、协议转让 | 公告 |
| | `定增募资` | 定向增发、可转债、配股融资 | 公告 |
| | `股权激励` | 激励计划、员工持股 | 公告 |
| | `管理层变动` | 董事长/总经理/财务负责人变更 | 公告 |
| | `并购重组` | 收购、重大资产重组、分拆 | 公告、研报 |
| **F 政策与技术** | `产业政策` | 补贴、准入、规划、目录调整 | 产业、宏观 |
| | `技术路线` | 工艺/材料/架构路线之争与切换 | 产业、研报 |
| | `出口管制` | 出口许可、实体清单、技术封锁 | 产业、宏观、供应链 |
| | `关税调整` | 进出口关税、反倾销/反补贴 | 宏观、产业 |
| | `标准变更` | 国标/行标/强制认证变更 | 产业、制度 |

### 4.2 使用规则

1. **每份 0–3 个**，能用一个就不用两个。`topics` 是过滤维度，不是摘要。
2. **只用本表 30 个词**，不改写、不加后缀、不造近义词。已明确排除的同义写法：扩产→`产能扩张`、涨价→`价格上行`、降价竞争→`价格战`、卡脖子→`国产替代`、客户依赖→`客户集中`、减值→`商誉减值`、业绩预增→`盈利预告`、限售解禁→（无对应词，写正文）。
3. **互斥对不可同时出现**：`价格上行` / `价格战`；`产能扩张` / `竞争加剧` 可共存但需确有两者证据。
4. **词表外的新概念写进正文**，不要临时加词。确需加词走第七节评审，一次评审最多加 2 个。
5. 分隔符（CSV 清单）：`;` 优先，`,`/`、`/`，`/`|` 也支持，见 `importer.py` 的 `SPLIT`。

### 4.3 刻意不覆盖的内容

| 不覆盖 | 原因 | 正确落点 |
|---|---|---|
| 宏观指标名（CPI、社融、MLF、DR007） | 指标名随口径调整无限增长，且本身已是检索关键词 | `logical` 二级键 + 正文；FTS 直接命中 |
| 报告期、季度、年份 | 属身份，不是主题 | `logical` 第三段 + `document_date` |
| 公司名、机构名 | 已有专门字段，重复会导致消歧不一致 | `companies` / `source` |
| 行业名 | 已有专门字段 | `industries` |
| 单份文档的独特结论 | 无法复用，只会把词表变成摘要库 | 正文 |

`制度`、`方法` 两域默认留空 `topics`：这两域各自只有个位数文档，且主题词（评级规范、估值口径）与上表 30 词无交集，强行映射会污染过滤结果。它们的定位靠 `logical` 完成。

## 五、`industries` 受控词表

统一采用**申万一级行业**（2021 版，31 个），只用一级，不混用二级或中信/证监会分类。理由：一级数量稳定、颗粒度与"行业主题"匹配；混用多套口径会让同一行业出现两种写法，过滤时互相漏掉。

```
农林牧渔  基础化工  钢铁      有色金属  电子      家用电器  食品饮料
纺织服饰  轻工制造  医药生物  公用事业  交通运输  房地产    商贸零售
社会服务  综合      建筑材料  建筑装饰  电力设备  机械设备  国防军工
汽车      计算机    传媒      通信      银行      非银金融  煤炭
石油石化  环保      美容护理
```

规则：

1. 一份资料可填多个（如"半导体设备"填 `电子;机械设备`），但**不超过 3 个**。
2. 写一级名，不写"半导体""光伏""锂电池"等二级/主题名——它们放 `logical` 第三段或 `topics`。
3. 与 `logical` 第二段保持一致：`产业/电子/...` 的 `industries` 必须含 `电子`。
4. 申万官方若调整分类，以官方为准并同步本表，历史文档不回填（回填会改 `metadata` 产生新版本，代价大于收益），在台账注明"2026-11 前按旧版"。

## 六、`source` 词表

`source` 是单值字符串（1–1000 字符），用于回答"这条结论是谁说的"。按"类别 + 机构"写，不写文件路径、不写"网络"。

| 类别 | 取值 | 说明 |
|---|---|---|
| 交易所披露 | `上交所`、`深交所`、`北交所`、`巨潮资讯` | 定期报告、临时公告 |
| 公司自披露 | `投资者关系` | 调研纪要、业绩说明会记录（非交易所渠道） |
| 券商研究 | `<券商简称>研究所`，如 `中金公司研究所`、`中信证券研究所` | 统一"研究所"后缀，便于按机构聚合 |
| 官方统计 | `国家统计局`、`中国人民银行`、`财政部`、`海关总署` | 宏观原始数据 |
| 数据商 | `Wind`、`同花顺iFinD`、`Choice` | 结构化财务与行情 |
| 行业组织 | `<协会名>`，如 `中国汽车工业协会` | 行业产量与价格 |
| 媒体 | `财新`、`证券时报`、`上海证券报` | 仅 B 级选收，须标 `document_date` |
| 内部 | `内部研究`、`内部制度`、`专家访谈`、`客户调研` | 无对外出处，引用时须标注为内部材料 |

> `专家访谈`、`客户调研` 属 B 级：`source` 里不写被访者姓名（个人隐私），只写类别。

## 七、维护流程

| 项 | 规则 |
|---|---|
| 评审周期 | 每月一次，与"过期资料复查"同批进行 |
| 提案格式 | 拟新增词 / 现有词为何覆盖不了 / 预计影响文档数（≥3 才受理）/ 提案人 |
| 单次上限 | 新增 `topics` ≤2 个；一级域、二级键新增需单独评审，不与词条混提 |
| 生效方式 | 改本文件 + 在 `CHANGELOG` 记一行，**不回填历史文档**（回填会触发新版本） |
| 废弃词 | 标注 `（已废弃 → 新词）` 保留在原位，不删除：删掉会让历史文档的标签变成"词表外取值"，无法审计 |
| 冲突仲裁 | 同一资料两个词都像时，选**更具体**的那个；仍不确定则留空 |

变更前先跑一次 `knowledge-import --dry-run`，确认新词不会让既有清单大批失败。
