# 股票分析系统本地运行实施方案

版本：1.1

编制日期：2026 年 10 月 24 日

适用项目：Stock-Predict-Mailer

部署原则：数据处理、特征工程、算法训练、预测、回测、知识库存储及任务调度在自有电脑上运行；大模型可按保密要求选择外部 API 或本地部署。

本方案用于建设可持续运行的股票研究分析工具。首先完成可信数据、可复现实验、有引用的报告与邮件闭环，再以实验结果决定是否扩展为可交易策略系统。本文不承诺预测准确率或投资收益，也不将大模型文字视为经过验证的量化结论。

## 1 关键假设及需要确认的问题

### 1.1 已确认的边界

算法模型训练等核心计算在自己的电脑上完成，不要求租用云主机、云数据库或云训练平台。本地训练不等于完全离线：行情采集、公告下载和邮件发送通常仍需要联网。外部大模型 API 是可选依赖，不是本地计算方案的前提。

### 1.2 尚需确认的五个问题

1. 主要研究 A 股、美股还是港股，股票池多大，是否需要历史成分股与退市股票？
2. 目标是个人辅助研究还是最终连接交易账户，预测周期偏向日内、周度还是月度？
3. 电脑的操作系统、CPU、内存、可用 SSD 空间及 GPU 型号与显存分别是多少？
4. 已有何种数据授权，每月可接受的数据与 API 预算是多少，邮件发送给本人还是其他人？
5. 私有资料能否发送给外部模型，电脑每天能开机多久，是否存在多用户或不同资料权限？

这些问题不阻断规划。默认按当前项目路径推定为 Windows 本机开发；具体硬件尚未确认，不能据此宣称能够运行某个规模的本地大模型。其他默认条件为一名开发者、A 股日频、数百至约千只股票、周度预测、个人研究、不自动下单、邮件仅发本人。上述条件均可配置。

### 1.3 证据等级与核实说明

本文的“方法依据”指通行统计与工程原则；“设计建议”指适合当前约束的实现选择；“待验证”指本项目必须实测的假设。通行方法不证明策略有效，工程建议也不代表当前版本产品已经核验。

2026 年 10 月 24 日曾按项目要求使用 gstack browse 尝试联网核实，遇到 Chromium 路径缺失及启动超时。本次未取得可用网页证据。因此，数据商当前价格、接口权限、历史覆盖、模型服务能力、留存政策和交易规则细节均标为待核实；文末链接为核验入口，不作为本次已阅读的证据。成本数字仅为内部预算估算。

## 2 总体建议与首选技术路线

### 2.1 先定位为研究工具

研究工具回答“哪些股票值得关注，证据是什么，模型有哪些局限”。主要评价数据可信度、样本外预测质量、报告准确性和运行稳定性。

可交易策略系统还要解决可成交数量、交易成本、持仓、资金、风控、执行失败和紧急停止。研究排名有效不等于净收益为正。MVP 可以做受约束的模拟回测，但不连接账户下单。

### 2.2 推荐的预测对象

设计建议：以未来五个交易日的横截面超额收益排序为主任务，展示风险指标；概率输出在完成独立校准后再加入。

- 价格预测容易展示，但受价格尺度和非平稳性影响，接近昨日价格的结果也可能具有较低误差，却缺乏决策价值。暂缓作为主任务。
- 收益率预测能够连接排序与组合研究，但噪声大、尾部误差显著。可以作为模型训练目标，不强调精确点预测。
- 涨跌分类便于理解，但忽略幅度与交易成本。准确率还受类别比例影响，适合作为经过校准的辅助信息。
- 波动率预测主要服务风险提示。先使用滚动或指数加权统计，再比较 GARCH；方向预测不能由波动率替代。
- 横截面排序直接对应“优先研究哪些股票”，减少对精确收益数值的依赖，但要求历史股票池、行业暴露和退市数据可靠。

待验证：五日排序是否优于简单动量、反转与线性基线。若没有稳健增益，应保留数据、检索和报告功能，不宣称已发现有效策略。

### 2.3 本地首选路线

Python 与 uv 管理项目；授权 API 采集数据；Parquet 与 DuckDB 管理行情和特征；SQLite 管理单人运行状态；scikit-learn 建立基线；LightGBM 完成主要非线性实验；本地版本清单管理实验；本地混合检索提供证据；Jinja2 生成报告；Windows 任务计划程序调度；SMTP 推送邮件。

大模型采用可插拔适配器：资料允许外发时可选择外部 API；私密资料使用本地模型或固定模板。embedding 和重排序默认本地运行。禁止因为生成模型位于本地，就忽略 embedding 服务可能外发原文的问题。

MVP 不强制安装 Docker、Redis、Celery、Kubernetes、云数据库或 GPU，也不同时维护 Windows、WSL 和多套生产环境。单机批处理需要的是可重跑、可恢复和可追溯，而不是服务数量。

## 3 系统架构和数据流

### 3.1 部署边界

本机计算链路：采集与原始快照 → 清洗与时点对齐 → 特征与标签 → 训练和滚动验证 → 模型审核 → 每日预测 → 证据检索 → 报告校验 → 归档与邮件队列。

私有资料链路：本地文件 → 解析与 OCR → 文档版本和权限 → 关键词与向量索引 → 权限及时间过滤 → 混合召回与重排序 → 带引用的报告输入。

允许的外部连接仅按需开放：数据供应商、公开披露网站、邮件服务器，以及用户允许的生成模型 API。训练数据与模型文件默认不上传；邮件正文和附件会离开电脑，因此收件人授权同样属于数据边界。

### 3.2 每类组件的选择

- 数据采集：供应商适配器配合 httpx、有界指数退避及限流。主数据源只选一个，补充源保留独立来源信息，禁止静默混用冲突字段。
- 行情与特征：本地 Parquet 配合 DuckDB，按数据集、日期等合理分区；避免每只股票每天一个小文件。DuckDB 用于分析查询，文件采用单写者与原子替换。
- 运行元数据：SQLite 保存任务、水位、预测、报告、邮件 Outbox 和文档元数据，使用事务与短写入。多人并发或数据库级权限需求出现时替换为本机 PostgreSQL。
- 特征工程：pandas 加显式特征函数。每个特征声明窗口、数据依赖、缺失规则和可用时间；实测内存或速度不足时再评估 Polars。
- 模型训练：scikit-learn 与 LightGBM。设置线程上限，避免系统失去响应；训练按月或人工触发，预测每日运行。
- 模拟回测：轻量日频事件驱动模块，显式建模订单、成交、持仓和现金；采用现有库时检查其市场约束，不直接相信默认成交设置。
- 模型与实验管理：MVP 用本地模型文件、JSON 清单和指标文件，记录代码提交、数据快照、标签、特征、参数、切分及随机种子。实验增多后再加入本地 MLflow。
- 私有检索：SQLite FTS5 配合应用侧中文分词或可用的适当 tokenizer，另存本地向量矩阵，以余弦相似度召回。小型知识库不必先部署向量数据库；规模扩大后选本地 FAISS，或迁移到 PostgreSQL 加 pgvector。FTS 默认分词不应未经验证就用于中文效果验收。
- 报告：Pydantic 校验结构，Jinja2 渲染 HTML。数字、表格和固定提示由程序生成，大模型只生成受约束的分析文字。
- 调度：Windows 任务计划程序调用项目虚拟环境的绝对路径。替代方案为专用 Linux 本机的 systemd timer；不强制迁移操作系统。
- 邮件：SMTP 加本地 Outbox。需要丰富的退信和投递事件时才评估事务邮件服务，仍由本机发起调用。
- 监控：结构化日志、SQLite 运行表和本地状态页或摘要文件。异常时邮件通知；电脑断电期间本机无法主动告警，若未来确需离线告警，可使用另一台自有常开设备或自愿启用外部心跳服务。

### 3.3 建议目录

项目下划分 src、config、tests、docs、data、artifacts、reports 和 logs。data 内分 raw、normalized、features、metadata 和 knowledge；artifacts 内分 experiments 与 models。真实数据、私有原文、凭证、模型和大体积日志不进入 Git。

配置中保存路径、市场、时区、数据截止时间、股票池、成本情景和模型参数。凭证优先放 Windows 凭据管理器；本地环境变量或受限权限文件可作原型替代，不写进报告、日志或版本库。

### 3.4 运行节奏与资源控制

日任务可暂定北京时间 20 时启动，但只有供应商更新与完整性检查通过后才能生成“今日”报告。具体时间由数据源实测确定，不将固定时钟视为数据已经就绪。

每日依次执行增量采集、近几日修订重拉、质量检查、快照冻结、特征生成、预测、检索、报告校验、归档和邮件。历史修订保留新版本，不覆盖旧预测所依赖的快照。

训练安排在周末或空闲时段，按月重新训练。训练、回填与大模型生成尽量错峰；采用进程锁阻止重复实例，以临时文件写入后原子替换方式发布模型，只有验证通过的版本成为当前版本。

### 3.5 关机和休眠后的恢复

任务配置使用明确工作目录、绝对解释器路径、最大运行时间、适当权限，并开启“错过计划后尽快运行”；是否唤醒电脑、是否仅接通电源时运行由使用习惯决定。首次验收要测试用户未登录时能否访问凭证及数据目录。

每日入口先检查最近成功交易日、水位和未完成任务。电脑关机三天后，先补数据与必要预测归档，再生成最新报告。默认不把过期日报全部重新发送；历史补报如需发送，必须注明实际生成时间和对应数据截止日。

任务阶段保存 pending、running、succeeded、failed 或 degraded 状态；异常退出后识别过期运行锁并安全恢复。停电前未完成的文件不能成为已发布数据。错误数据不得默默替换成昨日数据。

## 4 算法选型与验证方案

### 4.1 按成本递进的模型比较

简单统计、历史均值、零超额收益、滚动波动率、动量及反转是最低成本基线。线性回归或 Ridge 可学习收益关联，逻辑回归可预测方向；数据需求和维护成本较低，便于排查特征错误，但仍需控制共线性、异常值与非平稳性。

ARIMA 适合具有稳定序列结构的场景，可以作为单序列基线；日收益未必存在可利用自相关。GARCH 适合条件波动率，主要用于风险模块。逐股票拟合两者需维护收敛失败、参数稳定性和异常处理，训练成本虽通常低于深度学习，运维也并非为零。

随机森林适合结构化数据的稳健比较，但深森林可能占用较多内存，且外推有限。XGBoost 可作为成熟替代方案；LightGBM 作为首选非线性模型，适用于股票乘日期的表格数据，限制叶子、深度与最小样本以控制过拟合。CatBoost 在类别特征较多时值得比较，但其类别处理机制不能替代时间切分。

树模型通常不要求 GPU，适合本地 CPU 训练；训练成本取决于数据规模与参数。特征重要性和 SHAP 表示模型关联，不能证明经济因果。MVP 不需要把所有树模型都跑一遍。

LSTM 与 GRU 适用于需要序列表示的任务，GRU 结构相对简化；TCN 可并行训练且感受野较明确；Transformer 可以研究长序列、多变量或多模态关系，但数据、调参、显存和维护成本更高。以上模型都需要足够独立的历史跨度，不能把大量高度相关的股票行当作同等数量的独立样本。默认暂缓。

集成先采用简单平均或固定权重，要求成员样本外误差确有互补。Stacking 的二层输入必须来自按时间生成的样本外预测。概率校准使用独立历史窗口：小样本先比较 sigmoid，数据充分再比较 isotonic；校准改善概率可信度，不保证排序提升。

实施顺序为统计与线性基线 → LightGBM → 有明确缺陷时比较其他树模型 → 简单集成与校准 → 有证据后再研究深度模型。

### 4.2 标签与预测时点

以交易日 t 晚间截止时间前可获得的信息生成预测。模拟入场参考为 t+1 开盘，退出参考为 t+6 开盘，两次开盘之间经过五个交易日；目标为股票同期总收益减去预先选定基准同期总收益。实际成交另计成本、滑点和可成交性，开盘价不是保证成交价。

标签含分红及公司行动处理。若同时使用收盘到收盘标签，必须与可交易标签分别记录，不得用生成预测之前的价格假设成交。

### 4.3 数据与股票池可靠性

供应商验收同时检查授权、字段、历史覆盖、退市数据、历史成分股、公司行动、更新与修订机制、配额、费用和邮件分发权。开源采集库的代码许可不代表上游数据可商用或可转发。没有可靠历史时点数据时，先缩小范围而不是伪造精度。

保留原始未复权行情、公司行动、复权因子和来源。特征复权、总收益计算与实际成交价分别处理；禁止把随未来公司行动改变的最新前复权绝对价格序列直接作为历史已知特征。

停牌、合法缺价和采集故障分别标记；停牌不能假设可成交。退市证券与结果保留，不能删除亏损路径。股票池按历史时点生成，不使用今天的指数成分或今天仍上市的股票替代历史股票池。流动性、上市时长和风险警示过滤同样使用当时状态。

缺失值仅在业务允许时前向填充并限制最长有效期，禁止反向填充未来信息。财务缺失同时保留缺失原因或指示变量，填补参数只在训练数据上拟合。

### 4.4 预测时点可用性

至少记录 event_time、published_at、first_seen_at、available_at、ingested_at、revision_id 和 source_id。回放以 available_at 不晚于预测截止时间为条件。

财报按照实际披露时间生效，不按报告期结束日生效；重述生成新版本。公告和新闻保留首发与更新时间，日期精度不足时保守延后。宏观数据保留发布批次和修订版本，不把最终修订值回填历史。

今天下载一份旧报告并不能证明当年何时可以获取它。缺少可靠可用时间的资料不进入严格历史预测实验；可以用于当前分析，或明确标注为近似研究。当前系统首次观察时间只证明从现在开始何时见过资料。

### 4.5 验证划分与指标

方法依据：所有股票按共同日期切分，不随机拆散股票乘日期行。可从三年训练、半年验证、三个月测试开始，逐季滚动，实际长度由历史覆盖决定。同一日期所有股票位于同一分区。

剔除标签结束时间跨越训练边界的样本，隔离根据实际标签区间判断，不简单等同于五行 gap。若采用非连续训练块等更复杂切分，再考虑测试期后的 embargo。标准化、填补、选特征、调参和校准都不能看到未来验证数据。

排序评价包括逐日 Spearman Rank IC、分组单调性、Top-K 稳定性；回归包括 MAE 与相对零预测的样本外改善；分类包括 log loss、Brier score、校准曲线和 AUC；波动率包括实现方差误差和 QLIKE。准确率仅为辅助指标。

模拟策略同时评价成本后收益、超额收益、最大回撤、Sharpe、换手、容量、集中度、行业风格暴露和成交失败率。采用按日期的区块 bootstrap 估计不确定性，不把同日股票误当作独立观测。

佣金、税费、价差、滑点和成交量限制按市场及历史日期配置。A 股还要按适用规则处理 T+1、买入数量单位、涨跌停、停牌和不可成交状态；规则细节实现前核验。多空分组统计不等于可以低成本卖空的真实收益。

### 4.6 模型升级条件

在查看最终保留集之前登记升级标准：多个滚动窗口改善，不依赖单一年份或少数股票；在合理成本、延迟与市场分段下结果仍稳健；增益及其区间支持实用价值；线上离线特征一致；额外维护成本可以接受。

记录全部主要实验与选择次数，限制参数搜索预算。最终保留集反复用于改模型后，不再是未见测试集。复杂模型没有稳定优势时继续使用基线。

## 5 大模型及私有知识库设计

### 5.1 分工与报告结构

算法模型产生数值预测与风险量；知识库提供版本化证据与权限；大模型整理证据、解释差异并提出待核实假设。大模型不负责补造预测数字，也不能将相关性描述为已证实因果。

报告明确分为事实、模型预测、大模型推断、风险和未知项。历史模型判断或旧报告中的推断，不因被再次检索就变成事实。

```json
    "oos_rank_ic": 0.02,
    "cost_scenarios_bps": [10, 30, 50]
  },
  "evidence": [{
    "id": "E1",
    "document_version": "doc-v3",
    "published_at": "2026-10-22T18:00:00+08:00",
    "available_at": "2026-10-22T18:10:00+08:00",
    "page": 4,
    "text": "示例证据片段"
  }],
  "quality": {"missing_sources": ["news"]}

```

正式输入还需携带股票池定义、完整标签定义、验证区间、区间估计、成本后模拟表现、关键指标及新鲜度。未校准概率留空，不能用排名分位数冒充涨跌概率。

程序校验证据 ID、文档版本、页码、数据截止时间、数字和权限。引用存在不等于原文支持结论，需额外人工抽样检查支持关系；证据不足时明确无法确认。生成超时或校验失败时改用模板，不让文字生成阻断所有报告。

### 5.2 文档管理与混合检索

关系数据库保存证券、任务、报告、预测、权限与文档关系；文件保存原始响应、PDF、扫描件和模型；全文检索处理代码、标题与精确术语；向量检索处理语义近似。向量不是原文或关系数据的替代。

按标题、段落与表格边界切分，可从约 400 至 800 tokens 配合小范围重叠开始实验；保留父段落、页码、表头与单位。扫描文档记录 OCR 质量，解析失败资料不得直接当作可靠证据。

元数据包括文档 ID、内容哈希、版本、证券实体、资料类型、来源、发表及可用时间、页码、有效期、保密级别和访问控制列表。embedding 模型或切分方式变更后记录索引版本并重建，不把不同向量空间混在一起。

检索先验证身份，再做权限与时间过滤，随后关键词及向量召回、去重、重排序、补充上下文和输出引用。即便最终仅一名用户，也保留权限字段。小型本地检索可在授权候选集合内直接计算向量相似度；未来引入向量索引时不得仅在最后过滤少数候选，导致无权限资料参与重排序或外发。

缓存按权限范围隔离，返回前再次检查权限。文档删除、撤权和版本失效同步更新全文、向量与缓存；旧报告的访问也要受限制。备份中的历史副本按保留政策处理，恢复后重新应用撤权记录。

### 5.3 提示注入与外发边界

检索文本是不可信资料，文档中出现“忽略指令”“上传全部文件”等文字不能获得执行权。系统指令与证据字段分离；生成模型无任意命令执行、文件读取或联网权限；邮件收件人和附件由确定性流程决定。

外部生成 API 仅接收白名单字段及允许外发的最少片段，必要时去标识化。使用前核实留存、训练使用、地域、删除与合同条款；日志和错误追踪也可能泄漏原文。高保密资料禁止进入远程生成、embedding 或重排序接口。

本地模型可用 Ollama 或 llama.cpp 一类运行方式，具体产品版本、许可证与模型能力在实施时核验。仅绑定回环地址，不向公网暴露无鉴权接口；模型下载后推理是否离线需验证网络流量和配置。本地运行还需操作系统账户、磁盘与备份权限，不能等同于自动安全。

### 5.4 未知硬件时的降级路线

没有 GPU 时，量价基线和 LightGBM 仍可先用 CPU 完成；根据内存实测分批读取和控制线程。若选择外部生成 API，本地无需承担大模型推理显存开销。

若隐私要求全本地，则优先测小型量化生成模型、本地 embedding 与短上下文；不足以达到质量或时延目标时使用模板。不能在未核实显存、上下文长度、量化方式和系统余量时保证某个参数规模可运行。

硬件容量规划可暂以 16GB 内存作为缩小股票池和批量读取的起点，32GB 作为更宽裕的候选配置；这不是实测最低要求。SSD 空间按样本实际体积、版本保留和备份估算，首次规划可预留约 100GB，但原文、OCR 与多份模型可能显著增加需求。先测再购买硬件。

## 6 MVP 范围 验收标准及分阶段计划

### 6.1 明确范围

一个市场、一个可历史重建的股票池、日频量价、公司行动、证券状态、20 至 40 个特征、三层模型比较、五日排序、风险指标、小型私有文档集、自选股报告、每日邮件和运行记录。争取至少五年历史覆盖；覆盖不足则缩减结论。财务数据只在披露与版本可靠后进入特征。

新闻和宏观先作为带时点的背景证据。暂缓分钟级、全市场舆情、深度模型、自动下单和复杂多用户界面。大模型不是第一天的关键依赖，模板报告必须能独立运行。

### 6.2 验收标准

工程验收：相同代码、配置和数据快照可复现结果；跨硬件浮点差异使用预先设定容差。回填和增量幂等；关键业务主键唯一；时点泄漏与标签跨界测试可以阻断错误。完整性目标可暂定为供应商已完成更新的有效股票日记录不少于 99.5%，合法停牌等单独统计。

运行验收：连续十个交易日影子运行，每天产生可审计的成功、降级或失败状态；验证断网、超时、关机后补跑、磁盘空间不足和进程重复启动。训练或生成模型失败时可回退已审核模型或模板，不发送未经校验的正常报告。

报告验收：引用 ID 与数字自动校验通过；至少建立 30 个检索问题，另有越权与提示注入测试；关键事实人工检查无重大错误，普通事实支持率门槛预登记，例如不低于 95%。该门槛是项目验收目标，不是模型能力承诺。

邮件验收：采用 report_id、recipient 和 report_version 唯一键及 Outbox，保存尝试次数、下次重试时间和 Message-ID。普通 SMTP 在服务端接受后本地超时的场景不能严格保证恰好一次；需要人工核查或有界重发政策，不把“已提交”写成“已送达”。

研究验收：完成预登记的样本外基线比较、成本压力测试、偏差排查、分段分析和失败记录。不设保证准确率或收益门槛；无有效预测优势也可以是合格研究结论。

### 6.3 分阶段计划

第 1 至 2 周完成数据授权验收、回填、质量检查、时点模型和基线。第 3 至 4 周完成特征、滚动验证、LightGBM、模拟交易约束和实验归档。第 5 周完成知识库、权限、检索、模板及大模型适配器。第 6 周起完成调度、邮件、故障演练和备份恢复，并启动十个交易日影子运行。

这是单人全职投入的排期估计，不是交付保证。数据许可、历史版本缺失、电脑可运行时间及 OCR 质量均可能延长周期。

## 7 运行成本 主要风险和后续扩展条件

### 7.1 本地成本结构

本方案不要求云主机、云数据库或云训练平台。已有电脑的主要新增费用为电力、备份介质、授权数据和可选生成 API。

电费按增量平均功率千瓦乘运行小时乘本地电价计算。例如增量平均功率 0.10 千瓦、每日八小时、每月三十天，约为 24 度电，再乘实际电价；这是计算示例，不是对现有电脑的测量。

数据费用待具体供应商、字段、历史范围和分发许可报价。外部模型可先设置每月 50 至 300 元内部预算上限，并按调用前 token 估算与调用后记账限制；这不是当前市场报价。SMTP 是否免费及限额取决于现有邮箱服务。全本地生成无外部 token 费，但会增加电力、内存、显存和维护成本。

备份优先使用另一块自有硬盘或自有 NAS，费用按实际采购计；同一物理盘不同目录不算可靠独立备份。重要元数据与报告每日备份，大型原始数据按恢复成本安排。SQLite 用备份接口或停写快照方式备份，不在写入中随意复制单个文件。恢复演练比仅显示“备份成功”更重要。

### 7.2 主要风险

历史可用时点不可靠时，优先补齐版本，不升级算法；模型无稳健增益时，保留研究工具而停止策略有效性表述；表现来自行业暴露时，先做暴露分析与中性化实验。

本机故障、休眠和断电会导致错过计划，依靠水位补跑与降级处理，不能承诺关机期间持续服务。邮件服务器与数据源仍是外部依赖。训练与推理争抢资源时控制线程、批量与运行窗口。磁盘满、凭证失效、模型文件损坏和数据修订都纳入监控与演练。

### 7.3 扩展条件

只有任务运行时长影响日常使用时才考虑独立自有常开电脑；只有并发写入或多用户权限成为真实需求时才迁移 PostgreSQL；只有检索延迟或文档规模经测量超标时才升级向量索引；只有多窗口实验支持收益且算力可承受时才升级深度学习或本地生成模型。

若未来进入交易阶段，另行验收资金与持仓、执行、限额、市场规则、模拟盘、紧急停止及合规要求。本地部署不减少这些义务。

## 8 第一周可以直接执行的任务清单

第 1 天：记录电脑硬件、可运行时段、磁盘空间与隐私要求；冻结市场、股票池、截止时间、标签、基准、成本和主指标。交付研究定义与本地资源清单。

第 2 天：验收数据样本与许可，选取包含分红、停牌、退市和财报修订的证券，检查历史时点。交付字段映射、权限记录及样本验收结果；未通过前不采购大套餐。

第 3 天：搭建 uv 环境、采集 CLI、原始快照、Parquet、DuckDB、SQLite 与水位；先跑小股票池再回填。交付可重跑的采集与更新入口。

第 4 天：建立重复、缺失、异常价、日历、状态和时点检查；重点测试未来公告不可见、修订不回写旧快照及标签跨界。交付质量摘要与阻断规则。

第 5 天：运行零预测、历史均值、动量、反转和线性基线，按时间滚动评价并记录失败实验。交付第一份样本外实验结果，不把训练集表现用作成果。

第 6 天：导入少量授权文档，建立版本与权限；完成模板报告、引用检查与固定数值渲染。隐私和资源允许时再接生成 API 或本地模型，接口失败时仍可输出模板。

第 7 天：配置 Windows 任务计划程序，测试工作目录、解释器、未登录权限和错过后补跑；向指定测试地址发送一封报告，演练断网、超时、重复执行、恢复备份和凭证失效。

第一周的完成标准是本地可重跑的数据、基线与报告闭环。算法是否升级由样本外证据决定；本地大模型是否部署由隐私、质量与实测资源共同决定。
