# 自采数据接入与待办

## 已确认条件

用户已确认在自有电脑运行，电脑有 GPU，可使用外部大模型 API，数据由用户自行收集。内存容量、GPU 型号和显存尚未提供；市场、股票池与数据细节尚未确认。不替用户采购数据，不默认任何已有数据许可。

当前优先提供自采 CSV 本地训练流程。GPU 不作为表格模型的必要条件，默认 CPU 路线；硬件信息确定后再评估加速。外部生成 API 的供应商、模型、接口地址和资料外发等级尚未指定，因此本次不接入或调用任何生成服务，也不发送私有原文。

## 文件准备

建议把用户自采文件存入 data/local/intake/incoming，此目录不会上传 GitHub。至少提供《数据契约》要求的九个字段。一个日期多只股票可放在同一 CSV；同一证券同日只保留一个明确版本。`import-csv` 按完整输入形成快照，适合一次性历史导入；日常增量请用 `update-bars`，它在已有快照上追加新交易日并写出**新**快照，不改动旧快照，同时拒绝三类问题：与基准快照冲突的改写、跨文件重复、超过 `--max-staleness-days` 的过期数据（除非显式 `--allow-stale`）。每次都记入 `data_updates`，包含基准快照、结果快照、文件、最新交易日、截止时间、滞后天数与判定，可用 `update-history` 复查。

训练至少需要 100 个有标签日期及特征预热和预测期，实际建议更长历史与足够横截面。默认五日标签和 21 条日线预热意味着一般需 130 个以上完整观测日期。股票数过少或同日有效证券少于三只时 Rank IC 不适用；没有足够样本时应停止实验。

available_at 必须是该条完整记录真正可用的带时区时间，不能只填财报报告期或新闻日期。若无法取得可靠时间，记录为研究限制，不虚构时点。原始价格与复权口径需另行说明；缺失公司行动会同时污染收益与特征。

## 交易日历与公司行动

契约里的 `calendar: benchmark_sessions` 表示“按基准证券实际有行情的日期定义交易日”，这在合成数据上够用，在真实数据上会把停牌日、半日市和临时休市当成正常交易日。接入真实数据前先导入认证日历与公司行动：

```powershell
uv run stock-mailer calendar-import data/local/intake/incoming/calendar.csv --market CN --source "交易所公开日历 2026-10"
uv run stock-mailer calendar-status --market CN
uv run stock-mailer actions-import data/local/intake/incoming/actions.csv --source "自行整理的除权除息记录"
```

日历按加法式导入：重复导入相同内容不产生重复行，也不会删掉“本次文件里没出现但之前已认证”的日期，缺失会被如实统计而不是悄悄补齐。导入后契约的交易日集合改由认证日历提供，股票在某个基准日没有行情时跳过该窗口，不把停牌前后两条记录压成相邻交易日。

公司行动按除权日记录 `price_factor`。契约写 `backward_adjusted` 时，本地把除权日之前的开高低收乘以累计因子、成交量除以同一因子，最新价保持不动；写 `unadjusted` 时完全忽略公司行动。`forward_adjusted` 与 `total_return` 本地不生产，遇到会直接报错要求导入已复权数据或因子文件，不做静默近似。

## 本机操作

旧的探索入口（`import-csv` → `research` → `report`）仍然可用，但它不查授权、不做日历认证、不冻结模型版本。正式路线是下面的每日流程。

```powershell
uv sync --extra trees
uv run stock-mailer import-csv data/local/intake/incoming/bars_2026.csv      # 首次全量，记下 snapshot_id
```

### 每日循环

```powershell
# 1 增量行情：在昨天快照上追加今天的数据，写出新快照
uv run stock-mailer update-bars data/local/intake/incoming/bars_20261026.csv --base <昨天快照> --cutoff 2026-10-26T20:00:00+08:00 --market CN
uv run stock-mailer update-history

# 2 授权：本人训练默认已有 personal_training；漂移与影子评分还要 replay
uv run stock-mailer dataset-auth <今天快照>
uv run stock-mailer dataset-authorize <今天快照> --replay --note "本人自采数据，允许回放做漂移诊断"

# 3 训练：整配方重训，或对 lightgbm 父模型有限续训
uv run stock-mailer train-submit <parent_version> --snapshot <今天快照> --cutoff 2026-10-26T20:00:00+08:00 --method full_retrain --priority 5
uv run stock-mailer train-submit <lgbm_parent> --snapshot <今天快照> --cutoff 2026-10-26T20:00:00+08:00 --method continue_train --rounds 60
uv run stock-mailer train-worker --workers 2

# 4 比较与残差：只在双方训练标签结束之后的日子上比
uv run stock-mailer model-compare <candidate> --baseline <parent_version> --snapshot <今天快照> --cutoff 2026-10-26T20:00:00+08:00 --segments
uv run stock-mailer residual-fit <parent_version> --snapshot <今天快照> --cutoff 2026-10-26T20:00:00+08:00 --folds 4

# 5 漂移与预测
uv run stock-mailer model-drift <model_version> --snapshot <今天快照> --cutoff 2026-10-26T20:00:00+08:00 --window-days 60
uv run stock-mailer model-predict <今天快照> --cutoff 2026-10-26T20:00:00+08:00 --allow-personal

# 6 冻结报告与登记影子
uv run stock-mailer prediction-report <prediction_id> --query "风险 策略"
uv run stock-mailer shadow-record <prediction_id>

# 7 标签成熟后回填，满足 10 个成熟日才谈 stable
uv run stock-mailer shadow-evaluate --cutoff 2026-10-31T20:00:00+08:00
uv run stock-mailer shadow-status --model <model_version>
```

```powershell
# 产物清理：先看不删，确认后再执行
uv run stock-mailer model-retention --keep 5
uv run stock-mailer model-retention --keep 5 --apply
uv run stock-mailer retention-log
```

不要把真实数据加 --synthetic 伪装成演示。整条链只做研究与本地治理，不提供经过认证的可交易回测，也不代表任何收益承诺。

## 现状与仍未完成的部分

0.5.0 把“自采数据怎么进来、怎么授权、怎么训练、怎么留痕”这一整套机制做完了：认证日历与公司行动、增量行情与新鲜度门禁、三种用途授权（平台训练/个人训练/回放）、整配方重训与 LightGBM 有限续训、残差适配、漂移评价、产物保留、预测冻结成报告、影子观察与 stable 治理、发布密钥撤销。

仍然没有完成的是需要外部输入或需要真实运行才能证明的部分：

- **真实行情还没接**。`update-bars` 是机制，不是采集端；每天的文件仍要用户自己放进 data/local/intake/incoming。没有真实数据就没有真实训练结果。
- **邮件发送未接入**。按用户要求推迟，`prediction-report` 停在本地报告，不发信。
- **生成 API 未启用**。允许清单默认为空，`--generate` 目前只会走确定性模板。
- **影子与 stable 是治理记录，不是业绩证明**。10 个成熟日是下限，不是充分条件。
- **共享服务隔离未开始**。本机 principal 仍是受信配置身份，不是网页登录。
