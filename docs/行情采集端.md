# 行情采集端

状态：第一版，只接入东方财富一个源。它把真实日线写成《数据契约》要求的九字段 CSV，并留下一份来源记录。
**它不是任务采集端**：写出的 CSV 还要经 `legacy update-bars` / `legacy import-csv` 形成快照，才进入训练链路。

## 用法

```powershell
uv run stock-predict-mailer bars-fetch --symbols sh.600519,sz.000001 `
  --start 2026-11-01 --end 2026-11-19 --output data/local/intake/incoming/bars_20261119.csv
```

不带 `--source` 时用 `market_eastmoney`。可用的 id 与能力见 `uv run stock-predict-mailer plugins-list`，源必须声明 `bars` 能力，否则直接报错。

拿到 CSV 后按[自采数据接入](自采数据接入与待办.md)的每日循环继续（注意其中命令都在 `legacy` 子命令下）。

## available_at 的两种口径

这是最容易搞错的一处，因为它决定数据能不能用于时点回测。

- **默认：真实取数时间。** 本次所有行共用一个带时区的时间戳，含义是"这些日线在那一刻到达了这台机器"。
  当日收盘（15:05）之前取当日行情会被拒绝，避免把半天数据当成完整日线。
  适用于每日收盘后增量取数——此时取数时间就是真实可用时间。
- **`--assume-session-close`：历史回补。** 写当日 18:00（收盘与结算之后），并在来源记录里标
  `available_at: "session_close"`。这是**声明的约定，不是观察到的事实**：拿它做回测时，"当时是否已经知道"
  这一条是假设前提，不是证据。

区间止于两天以前却仍用默认口径时，命令会往 stderr 打一条警告并把它写进来源记录：这样的数据只能用于
晚于取数时间的截止点，回溯历史需要显式换成 `--assume-session-close`。

## 拒绝写入的情形

任一发生都**不写文件**，也不会只写一半：

- 某标的在区间内一条日线都没有（不静默跳过该标的）
- 返回了区间外的日期
- 当日尚未收盘
- 开高低收不自洽
- 同标的同日重复
- 单次超过 200,000 行或跨度超过 3660 天
- 源没有声明 `bars` 能力，或取数抛错

## 产物

| 文件 | 内容 |
| --- | --- |
| `xxx.csv` | `date,security_id,open,high,low,close,volume,available_at,source`，`security_id` 形如 `sh.600519`；测试里用 `data.validate_rows` 断言它确实能被契约校验器接受 |
| `xxx.csv.provenance.json` | 取数时间、来源插件 id / 模块 / 模块摘要、标的、区间、行数、首末日期、`available_at` 口径、`price_basis` |

## 端到端已验证

2026-11-20 在隔离工作区用真实接口跑通了整条入链（不是合成数据）：

1. `bars-fetch --symbols sh.600519,sz.000001 --start 2026-10-20 --end 2026-11-06` → 28 行（两标的各 14 个交易日）。
2. `legacy import-csv bars_1.csv` → 快照 `50ba8d50…`：28 行、2 个标的、`sources: ["market_eastmoney"]`。
   清单同时如实写着两条限制："CSV 可用时间由导入方声明，未独立核实"、"无公司行动与存活偏差认证"。
3. 再取 11-09 至 11-13 后执行 `legacy update-bars --cutoff 2026-11-13T20:00:00+08:00 --market CN`
   → 新快照 `4edf16ca…`：38 行（新增 10 行），旧快照未被改写。
4. 新快照的授权默认只有个人训练，回放未开；要用于漂移诊断仍需显式 `legacy dataset-authorize --replay`。

`import-csv` 用 pyarrow 写 Parquet，所以需要 `uv sync --extra research`（只装 `trees` 会在这一步失败）。

## 边界

- **只取不复权（`fqt=0`）。** 前复权会让历史值随每次分红被重写，而契约的 `backward_adjusted` 是用
  `actions-import` 的因子在本地换算的；采集端再取一次复权价就是二次复权。图表用的 `candles` 仍是前复权，
  因为它只用于显示。
- 没有公司行动校验，也没有停牌、半日市、临时休市的特殊处理；这些仍依赖 `calendar-import` /
  `actions-import` 与后续核对。
- 公开行情页无授权、无 SLA、可能限流或改版。只验证过单次连通、返回结构与一次区间取数，未验证长期稳定性、
  盘中延迟与大面积缺失。
- 一次调用一个文件，不做断点续采，也不直接写快照。
- 腾讯与新浪只声明了 `quotes`（腾讯另有 `candles`），不能用于 `bars-fetch`；新增源要实现 `bars` 才会被接受。
