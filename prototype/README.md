# 分析台 · 静态原型

这是控制台前端的**设计原型**，独立于 `src/stock_predict_mailer/control/web/`，不连接任何后端，所有数据来自 `js/mock.js`。目的是先确认信息结构、视觉与状态表达，再往真实控制台里搬。

三个视图：**分析台**（表单 → 执行计划 → 报告）、**办公区**（谁在做什么的实时画面）、会话记录与设置（占位）。

视觉为**深空科技风**：`#0A0E17` 主背景 + 青蓝 `#16D3E6` 强调 + 半透明毛玻璃卡片。

## 运行

```powershell
cd prototype
python -m http.server 8791
# 打开 http://127.0.0.1:8791
```

直接双击 `index.html` 也能跑：脚本是普通 `<script src>`，没有 ES module，没有构建步骤。

- `?scenario=degraded` 直接进入某个场景（见下表），`?view=office` 直接打开办公区
- `?instant=1` 让走位瞬时完成，便于截图核对终态
- `?notify=1` 勾上通知，队列里才有投递这一步（办公区的邮筒才有东西可做）
- `?open=main|sub` 打开某个角色的抽屉
- `?confidence=0.72&horizon=20` 预填置信度与周期，用来核对环形仪表与进度条

右下（窄屏为左下）的「原型控制」面板可以切换 6 种场景，也可以清空后自己提交一次。

## 一个运行，两个视图

办公区**不是第二个模拟器**。`app.js` 的 `play()` 只管跑一遍 `mock.buildRun()` 的队列，同时把每条事件广播出去（`window.StockPredictMailerApp.on("start" | "item" | "finish" | "reset")`），办公区订阅后翻译成画面：

| 运行事件 | 办公区的反应 |
|---|---|
| `step: plan/context/analysis/charts/summary` | 小鲸在 P1 打字，看板对应阶段点亮，两块屏幕的百分比同步推进 |
| `step: prediction/risk/advice` `running` | 小鱼起身 → 从待命区走到 P2 → 落座 → 开始打字 |
| 同上 `completed` | 气泡报结论、屏幕转「已完成」，人留在 P2 等下一步 |
| 同上 `failed/degraded` | 降饱和、气泡报错误码 |
| `step: charts` | 出图台的纸卷展开、扫描线来回走 |
| `step: mail` | 信封沿贝塞尔曲线飞向邮筒 → 回执徽标（已提交 / 结果未知 / 模拟投递…） |
| `finish` | 两只手同时停下、屏幕不再滚动，小鱼走回待命区，看板落 100% |
| `event`（如「小鱼 20 秒内未返回」） | 小鲸头顶气泡报这句话 |

所以在分析台点「提交分析」，切到办公区能看到同一轮任务在跑；在办公区点「开始分析」，跑完切回分析台，报告也在。看板的阶段点是按 `run.steps` 现画的，简单任务 4 步、复杂任务 8 步都排得下——它显示的是这一轮真实的执行计划，不是预先画死的七个格子。

**进度只有一个来源。** `office.js` 维护 `done / total` 两个数（运行中的那一步记半格），由它同时推导：看板上的大号百分比、进度轨填充、两块工位屏幕里的百分比与进度条、桌面铭牌下的细条。四者永远不会对不上，因为它们读的是同一个函数。

## 办公区：深色科技风 + 双角色

这一轮把办公区从「暖色插画房间 + 位图角色」整体重做成深空科技风，**左侧导航、顶栏、场景选择器、开始/重置、事件面板、原型面板的布局与功能都没动**，只换了场景内部。

### 场景

一张 1600×900 的 SVG，从下往上叠：深空渐变墙 → 低饱和 44px 网格（`mask` 向下渐隐）→ 看板往下洒的一团柔光 → 地面（透视收敛线 + 地平线灯带）→ 工位 → 角色 → 前景摆件与暗角。

家具全部改成低多边形：桌面是一块带青蓝灯条的深灰板，桌裙是带细刻线的金属面板，显示器是带发光顶边的深色壳，出图台与邮筒只剩几何体加一点冷光。暖米色一点没留。

每一台工位背后有一片屏幕溢光（`deskGlow` 径向渐变），地面有一圈投影与倒影——这两样是「不靠加亮整体画面也能让人物立住」的关键，比把背景调亮有效得多。

### 角色

两位都是**蓝发女仆**，按 `docs/character-sheet.jpg`（05 CHIBI BLUE MAID 正面图）逐部件复刻，只换发色与点缀色区分身份：**小鲸**原画的靛蓝（`#16D3E6`）、**小鱼**夜潮紫（`#8A7BFF`）。

复刻到的部件：深蓝→浅天蓝的渐变长发（外缘做波浪、两根侧发垂到腰）、**白色荷叶边发带 + 浅蓝蝴蝶结**（在画面右侧）、**两侧鳍状耳**（三瓣扇形、带鳍条）、呆毛、大眼 + 腮红、**白色圆领 + 藏青领结**、白门襟与三颗扣、**藏青长袖连衣裙 + 白色蕾丝袖口**、**白色荷叶边围裙**（裙摆上有一枚小鲸刺绣）、腰带、下摆印花样饰带、白色蕾丝裙边、白袜 + 藏青玛丽珍鞋、一条从身后偏右伸出的**鲸尾**。

从位图换成**矢量分层骨骼**，是因为位图只能整体平移，做不出「手在键盘上敲」，而需求明确禁止平面贴图位移。结构是：

```
.actor
  .a-body
    .a-hair-back       后发（最后面）
    .a-tail            鲸尾（压在后发之上、身体之下）
    .a-legs            站姿双腿（落座时淡出，藏在桌裙后）
    .a-torso           以骨盆为轴的呼吸 / 打字微晃
      <上衣 / 裙 / 围裙 / 领结>
      .a-hair-side     侧发（压在肩前，垂到腰）
      .a-arm × 2       绕肩旋转 = 打字
        .a-arm-art
          <肩山 + 上臂>
          .a-fore      绕肘折叠（落座时把前臂折到桌面）
            <前臂 + 蕾丝袖口 + 手>
            .a-hand    腕为轴 = 手指点击
      .a-head          脸 / 眼 / 刘海 / 发带 / 蝴蝶结 / 鳍耳
```

**旋转原点**是这套东西唯一的技术坑，有两处必须处理：

1. 给 SVG `<g>` 写 CSS `rotate`，默认原点不是骨骼点。做法是往每个旋转组里塞一个**透明「bbox 栓」矩形**，让组的包围盒完全被这个矩形决定、且关于骨骼点对称，再用 `transform-box: fill-box` + `transform-origin: 50% 50%` 把原点锁死在肩 / 肘 / 髋上。矩形要给得比所有可见图形都大，否则圆形袖山会把包围盒顶出去，原点偏移。
2. CSS 的 `transform` 会**覆盖** SVG 的 `transform` 属性。所以肘、髋、肩这些既要平移又要旋转的节点必须拆成两层：外层 `<g transform="translate(…)">` 只做定位，内层 `.a-fore` / `.a-leg` 只做旋转。两层合在一层上的话，动画一跑，手臂和腿会跳回原点。

### 动效与触发条件

| 动效 | 触发 | 实现 |
|---|---|---|
| 打字（两臂绕肩摆 + 手指点击） | `.actor.is-typing` | `steps(3, end)` 的 `rotate` 关键帧，左右臂周期 0.46s / 0.54s 故意错拍，看起来像两只手在敲不同的键 |
| 上半身微晃 | 同上 | `is-typing` 时把 5.4s 的呼吸换成 1.05s 的 `typeSway`（`steps(2)`） |
| 屏幕数据滚动 | `.desk[data-typing="1"]` | 6 行方块在裁剪窗内以 1.8s 匀速上移；停下来时 `animation-play-state: paused` |
| 走位 | `.actor.is-walking` | 双腿绕髋交替摆 ±13°、整体 0.27s 上下起伏；位置由 `scene.walk()` 的 rAF 按缓动插值 |
| 落座 | `.actor.is-seated` | 双腿 `opacity: 0`，由桌裙挡住下半身——不是把人物裁掉；同时 `.a-fore` 绕肘折 75°，双手落到桌面，整体再抬 12px 让手压在桌沿之上 |
| 呼吸待命 | 常驻 | `.a-torso` 5.4s 的 ±0.4° 摆动 |
| 当前节点呼吸 | `.stage[data-stage-status="running"]` | 外圈光斑 `scale(.75→1.35)` + 透明度 1.6s 循环 |
| 失败降饱和 | `.actor[data-status="failed"]` | `grayscale(.55) brightness(.78)` |

`prefers-reduced-motion` 下以上全部停掉。

### 看板

看板是场景的主角：780×268，占画面近一半宽，四角有科技括号，标题左侧写标的 / 方向 / 周期，右侧一枚 40px 的百分比数字带辉光。阶段点按 `run.steps` 现画（4~8 个自适应间距），四种状态各有配色：待办灰、进行中青蓝 + 呼吸光斑、完成实心青蓝 + 连接线点亮、降级琥珀、失败红。下方一条进度轨按下标同步填充。

## 深色重构（分析台）

这一轮只换皮、加图形，**布局结构、控件位置、文案与功能逻辑一处没动**。所有改动落在 CSS 与几个新增图形上，`readInput()` / `buildRequest()` / 提交流程一行未改。

**变量层换血。** `tokens.css` 保留原变量名（`--paper` / `--ink` / `--rule` …）只换取值，`layout/form/report/office` 里已有的 token 引用自动跟随，需要手改的只剩各文件里少量写死的浅色值。以后要再换一次主题，仍然只动这一个文件。

| 角色 | 取值 |
|---|---|
| 底色 | `#0A0E17` 主背景 / `#111823` 卡片 / `#080B12` 凹陷 |
| 文字 | `#F2F7FA` 标题 / `#9AA9B8` 正文 / `#5D6B7A` 占位 |
| 强调 | `#16D3E6`（选中态、高亮、数据图形） |
| 状态 | `#22E08A` 涨 / `#D2453A` 跌 / `#E8B23C` 降级 |
| 描边 | `rgba(255,255,255,.07)` 常规、`.14` 强 |

涨跌沿用设计稿给定的语义（**涨绿、跌红**），与 A 股「红涨绿跌」相反；接真实控制台前需要再确认一次。

**质感三件套。** 卡片是 `rgba(17,24,35,.72)` + `backdrop-filter: blur(18px)` + 1px 内描边的玻璃面板；选中控件用内阴影 + 外发光而不是描边加粗；深色底上不用纯黑，靠三层径向渐变撑出纵深。

**新增的五个图形**（都在 `css/viz.css`，数据来自已有控件，不参与提交）：

1. **方向迷你折线** — 「上涨 / 下跌 / 持平」三个选项卡内各有一条 34×11 的 SVG 折线，未选中时 50% 透明，选中时按方向取色并 `drop-shadow` 发光。
2. **置信度环形仪表** — 22px 圆环绝对定位在输入框内右侧，输入框留 34px 右内边距。`pathLength="100"` 让 `stroke-dashoffset` 直接等于百分比，空值时不画弧，有值才淡入青蓝弧并带辉光。
3. **周期进度条** — 3px，按 `交易日 / 250`、`自然日 / 365`、`小时 / 720` 归一化，最小可见宽度 6% 保证「1 个交易日」也看得见。
4. **时间跨度轴** — 贯通两列的横线，两端刻度对齐输入框内缘，中间一枚 `跨度 24h` 标签把线压断。有效期早于生成时间时标签转红。
5. **右侧背景装饰** — 两条正弦化波形 + 渐变面积 + 散点，压在毛玻璃卡片**下面**靠半透明透出来，不浮在内容上。

## 设计决定

**表单优先。** 分析台是左侧输入、右侧结果。预测与事实都是结构化字段，原来的 17 行 JSON 文本框收进「高级」折叠，仍可双向同步。

**三组状态从不合并。** 任务状态、分析状态、邮件状态各占一个胶囊，颜色语义固定：绿=正常、琥珀=降级或待重试、红=失败、灰=模拟或未通知。`simulated` 用灰色而不是绿色，因为模拟投递不代表邮箱收到。

**结论与依据可对照。** 推断条目上的 `F-01` 是按钮：点它高亮对应事实卡，点事实卡反向高亮引用它的推断。

**置信度缺失用空槽位。** 虚线框里写「上游未提供」，不填 0、不做进度条、不折算成概率。

**事实永远标来源。** 卡片上写「上游行情快照」而不是「已核实」——`source` 是上游声明，系统没有独立核实能力。

**只有两个人、两台电脑。** 小鲸常驻 P1 负责规划 / 补数 / 汇总 / 出图 / 投递，小鱼在 P2 做三条分支分析，没有分支任务时回待命区。把六张桌子并排画出来会让人以为有六个独立工位，两个人反而能把「主导 + 协作」讲清楚。

**进度不编造。** 看板百分比是按「已完成步骤数 / 总步骤数」算出来的，运行中的那一步记半格。不写「预计还需 XX 秒」这种后端没有的字段。

**角色是矢量，不是位图。** 位图能还原原画的质感，但装不了骨骼动画；这一版明确要求「手在打字、禁止平面贴图位移」，所以改用分层矢量重新画。原画设定图留在 `docs/character-sheet.jpg`，位图版本留在 `docs/legacy/` 备查。

**任务结束后执行计划自动收起**，报告立刻出现在视野里；任务失败时保持展开，方便看到断在哪一步。

## 搬进真实控制台的约束

后端**不能改**，这意味着只能交付 `index.html`、`style.css`、`app.js`、`memory.js` 四个文件：

- **CSS 直接拼接。** 七个 css 文件按 tokens → base → layout → form → viz → report → office 顺序合并成 `style.css`，无 `@import`、无嵌套。`viz.css` 必须排在 `form.css` 之后（它覆盖分段控件的内边距）。办公区的所有选择器都挂在 `#view-office` 下，`--of-*` 这些场景色板也只在视图内生效，不会污染控制台其余部分。
- **JS 也要合并成一个 `app.js`。** 六个脚本用 `window.StockPredictMailerMock` / `StockPredictMailerRender` / `Actors` / `Scene` / `Office` 命名空间通信，没有 import/export，去掉外层 IIFE 顺序拼接即可。**顺序有依赖**：mock → render → actors → scene → office → app。
- **不能有内联脚本或样式。** 现有 CSP 是 `script-src 'self'; style-src 'self'`。角色现在全是矢量，连 `img-src data:` 都不再需要——比上一版少一条依赖。
- **静态路由是白名单。** `server.py` 只放行那四个路径，所以不能新增 `/assets/*`，也不能用字体或图标 CDN。
- **体积。** 全部源码约 260 KB（去掉位图后比上一版少了 190 KB），合并后可压到 120 KB 左右。零依赖、零构建换来的就是这个体积和「不需要后端放行任何资源」。
- **动效性能。** 打字动效是纯 CSS `transform`，不吃主线程；走位是 rAF + `setAttribute("transform")`，每条 ≤1.5s。`backdrop-filter` 用得较多（卡片、抽屉、原型面板），接真控制台要留意滚动性能。

## 与后端的字段对应

| 界面 | 真实来源 |
|---|---|
| 表单 → 请求体 | `POST /api/tasks` 的 `prediction` / `context.facts` / `complexity` / `notify` |
| 执行计划 / 看板阶段 | `GET /api/tasks/{id}/events?after=N` 的 `step` 事件（`step` + `status` + `child_id`） |
| 报告的 `analysis` | `task.artifacts[0].parts[0].data.analysis` |
| 分支结论 | `analysis.children[].{role,status,depth,result,error}` |
| 冲突 | `analysis.conflicts[]` |
| 费用 | `analysis.usage.{calls,reserved_usd,budget_usd}` |
| 投递回执 | `analysis.mail.{id,status,attempts,next_attempt,error}` |

办公区只认 `step` / `status` / `child_id` 三个字段，所以接真后端时这块不用重写——把 `app.js` 里的定时队列换成 SSE 订阅即可。
