## 1. 业务背景（给开发者的最小上下文）

### 1.1 系统做什么

用户提交一份**上游模型的行情预测**（方向、周期、目标价、置信度可空）与若干条**客观事实**，系统按固定管线完成分析并邮件推送：

```
校验预测 → 补齐行情事实 → 主 Agent 分析（可委派子角色）→ 复核汇总
      → 生成图表 → 校验并保存报告 → 交付邮件
```

### 1.2 真实执行阶段（7 个）

来自 `orchestrator.py` 的 `progress.step()`，**顺序固定**：

| # | `step` 值 | 中文名 | 归属工位 |
|---|---|---|---|
| 1 | `validate` | 校验预测 | 主 Agent |
| 2 | `tools` | 补齐行情与事实 | 主 Agent + 预测 |
| 3 | `main` | 主 Agent 分析 | 主 Agent（派发子角色） |
| 4 | `merge` | 复核汇总 | 主 Agent |
| 5 | `charts` | 生成图表 | 出图台 |
| 6 | `report` | 校验并保存报告 | 主 Agent |
| 7 | `mail` | 交付邮件 | 邮筒 |

> 注意：`merge` 只在**确实产生了子角色结果**时出现。简单任务（`complexity=simple`，或 `auto` 下事实 ≤1 且无 metrics）不会委派，此时场景中 3 个子角色**必须保持待命状态**，不得假装工作。

### 1.3 真实子角色（3 个，加上主 Agent 共 4 个）

| `role` | 中文名 | 职责 |
|---|---|---|
| `main` | 主 Agent | 分析、决策、委派、汇总、成文 |
| `prediction` | 预测分析 | 动能、量价、区间判断 |
| `risk` | 风险分析 | 回撤、市场风险、数据不足 |
| `advice` | 建议生成 | 操作建议、仓位与止损 |

### 1.4 真实接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/tasks` | 创建任务，返回 `task_id` |
| GET | `/api/tasks/{id}` | 任务快照 |
| GET | `/api/tasks/{id}/events?after=N` | **游标事件流**，每批 100 条，`after` 传已消费的最大序号 |

事件对象字段（`execution.py`）：

```json
{
  "kind": "step | tool | model | plan | memory | adjustment",
  "timestamp": "2026-11-08T14:02:11.312+00:00",
  "step": "main",
  "status": "running | completed | failed",
  "label": "主 Agent 分析预测、风险与建议",
  "code": "可选，错误码",
  "child_id": "可选，子 Agent 任务 id",
  "role": "可选，模型调用所属角色",
  "summary": "可选，子角色结论码数组",
  "steps": "可选，将要派发的子角色清单"
}
```

**子角色派发是实时的**，共有三次事件：

1. `kind="adjustment"`，`steps=[{id:"risk",label:"risk"},…]` → 预告将派发
2. `kind="step"`，`step="risk"`，`status="running"`，`child_id=…` → 子角色开工
3. `kind="step"`，`step="risk"`，`status="completed"`（或 `failed` + `code`）→ 收工

### 1.5 静态资源硬约束

后端 `server.py` 只放行四个路径：`/`、`/app.js`、`/memory.js`、`/style.css`。
CSP：

```
default-src 'self'; script-src 'self'; style-src 'self';
img-src 'self' data:; connect-src 'self'; frame-ancestors 'none'; base-uri 'none'
```

**推论（必须写进实现）**：

- 不能加载任何外部图片、字体、CDN、雪碧图 —— 场景与角色**必须全部为纯矢量（内联 SVG），零图片请求**。
- 不能使用 `<style>` 内联块、不能使用 `style="…"` 属性字面量。
  （通过 CSSOM `el.style.setProperty('--x', …)` 动态写入是**允许**的，不受 CSP 限制。）
- 不能用 `<script type="module">` 引入额外文件 —— 只有 `app.js` 一个脚本入口。

## 2. 视觉主题：纸感办公区间

### 2.1 定位

不是「游戏」，也不是「监控大屏」。是一间**用纸和墨画出的小办公室**：暖米色墙面、木地板、深青桌面，人是从纸片里剪出来的 Q 版鲸鱼少女，动作克制、循环周期长。

关键词：**纸片感 / 静物画 / 有光的办公室 / 慢动作 / 不喧哗**。

### 2.2 视角与构图 【硬约束】

- **正面平视（flat front view）**，不做等距 2.5D、不做透视变形。
- 场景容器 `.office` 固定 `aspect-ratio: 16 / 9`，`min-height: 420px`，`max-height: 62vh`，超出部分用场景内滚动而非压缩。
- 三层纵深：**后墙（z:0）→ 家具与人物（z:1）→ 前景遮挡物（z:2，如过道边的绿植/纸箱）**。
- 地面线（floor line）在容器高度 **78%** 处，所有工位、沙发、邮筒都落在这一条线上。

### 2.3 平面布局 【硬约束】

```
┌──────────────────────────────────────────────────────────────────────┐
│  ░░░ 后墙 ░░░  [中控看板 7 阶段]  ░░░░░░░  [出图台(墙挂)]  ░░░        │
│                                                                      │
│   ✉            ╭────╮    ╭────╮   ╭────╮   ╭────╮   ╭────╮          │
│  邮筒          │ P1 │    │ P2 │   │ P3 │   │ P4 │                   │
│                ╰────╯    ╰────╯   ╰────╯   ╰────╯                   │
│            [沙发 待命区]                                              │
│ ═══════════════════════════ 地面线 ═══════════════════════════════    │
│      🌿(前景绿植)                                  📦(前景纸箱)      │
└──────────────────────────────────────────────────────────────────────┘
```

横向坐标（以容器宽度百分比计，`--x` 变量）：

| 元素 | `--x` | 宽度 | 说明 |
|---|---|---|---|
| 邮筒 `Mailbox` | 3% | 5% | 靠门左侧，落地 |
| 待命区 `Lounge` | 13% | 13% | 双人沙发 + 小圆几，子角色起点 |
| **P1 主 Agent** | 34% | 15% | 队伍首位，背板加高，桌面最大 |
| **P2 预测** | 51% | 14% | |
| **P3 风险** | 68% | 14% | |
| **P4 建议** | 85% | 14% | |
| 中控看板 `Board` | 50% | 30% | 挂在后墙，垂直居中偏上 |
| 出图台 `Plotter` | 76% | 12% | 墙挂式绘图仪，在 P3/P4 之间上方 |

> 主 Agent 不放在几何正中，而放在**工位排头**——这是真实办公室的座位逻辑（组长坐第一个位子），比强行居中更可信。视觉权重由「背板更高 + 桌面更宽 + 头顶悬浮中控台」来建立。

### 2.4 色彩

沿用既有设计令牌（`prototype/css/tokens.css`），**办公区新增以下变量**：

```css
--wall:        #F1E9D9;  /* 墙面，比 paper 稍暖 */
--wall-shade:  #E6DCC7;  /* 墙面阴影 / 洞洞板底 */
--floor:       #E0D3B9;  /* 木地板 */
--floor-line:  #D3C3A4;  /* 地板缝 */
--desk:        #CBAE86;  /* 桌板 */
--desk-edge:   #A98B63;  /* 桌沿 */
--chair:       #17323C;  /* 座椅（沿用 deep） */
--screen:      #1B3B47;  /* 显示器 */
--screen-glow: #A9CDF0;  /* 屏幕荧光 */
--cork:        #D9BE94;  /* 软木板 */
--plant:       #4E7A5E;  /* 绿植（压灰的绿） */
```

**光照**：单一光源从左上方来。所有家具的投影为 `rgba(90, 74, 50, 0.10)`，偏移 `x+2px / y+3px`，`blur 6px`，**不使用多重阴影**。
**材质**：墙面用 6px 间距的极淡横向条纹模拟纸纹（`repeating-linear-gradient`，透明度 0.35）；地板只画 3 条地板缝，不画木纹细节。

### 2.5 禁止事项

- ❌ 深色背景、霓虹、发光边框、玻璃拟态、渐变炫光。
- ❌ 冒数字、飘英文代码雨的「黑客感」装饰。
- ❌ 人物做夸张综艺动作（举手欢呼、跳跃、转圈）。
- ❌ 场景内文案出现「正在为您努力分析中…」这类空话，必须是真实阶段名。

### 3.4 动作状态机（单个角色）

| 状态 | 视觉 | 触发 |
|---|---|---|
| `idle` | 站/坐在待命区，呼吸循环 3.4s，偶尔眨眼（随机 4–7s） | 初始 |
| `dispatched` | 头顶弹出气泡「收到指令」，身体上抬 2px | 收到派发事件 |
| `walking` | 沿地面线平移，内层 0.3s 上下 bob，尾巴反向摆 | 前往工位 |
| `seated` | 落座，椅子轻微下沉 1px | 到达 |
| `working` | 坐在工位，双手交替敲键盘（0.42s/次），光环出现 | `status=running` |
| `thinking` | 单手托腮，头顶 3 个气泡点依次亮（1.2s 循环） | `kind=model` 事件 |
| `done` | 双手离开键盘，抬头，头顶 ✓ 气泡 1.2s 后消散，椅子回正 | `status=completed` |
| `degraded` | 整体 opacity 0.75，气泡为灰底「部分结果」 | 子角色 `failed` 但任务继续 |
| `failed` | 低头 8deg，气泡砖红底显示错误码 | `status=failed` |
| `away` | 起身走回待命区 | 任务结束 8s 后 |

```
         │ 桌板     │  ← 马克杯 / 笔筒 / 便签
         ╰─────────╯
            [ 椅 ]
```

- **状态灯**：桌面右上角直径 6px 圆点。`idle` 灰 `#B9B0A0`；`walking` 蓝 `#2A5C8A` 缓慢呼吸；`working` 蓝常亮；`done` 绿 `#2C6E49`；`degraded` 黄 `#8A6410`；`failed` 砖红 `#A32D2D`。
- **角色进度条**：贴在显示器下沿，宽 88px、高 3px、圆角 2px，底 `--rule`，填充用 `transform: scaleX()`。
- **桌面气味物**：主工位一只马克杯（热气 2 缕，仅 `working` 时），预测工位一叠便签，风险工位一个放大镜，建议工位一个笔筒 + 小提灯。
- **姓名铭牌**：桌沿居中，`--mono` 字体，`鲸长 · P1`。

### 4.2 中控看板（`Board`）

挂在后墙，木质边框，深青底。内容为**全局 7 阶段**：

```
┌──────────────────────────────────────┐

│  ● 校验  ● 补数  ● 分析  ○ 汇总      │
│  ○ 出图  ○ 成文  ○ 投递              │
│  ────────────────────────────────    │
│  已用 00:42 / 预算 $0.031            │
└──────────────────────────────────────┘
```

- 每个阶段一枚 8px 菱形：`pending` 空心、`running` 实心蓝 + 1.2s 呼吸、`completed` 实心绿、`failed` 实心红 + 叉。
- 顶部标的文字为 `任务名 · direction · horizon`，超出 24 字符截断加省略号。
- 阶段中文名严格用 §1.2 的表，不自行改写。

### 4.3 出图台（`Plotter`）

墙挂式绘图仪，右侧有出纸口。**这是「生图」能力的载体**。

- `idle`：待机小灯缓慢呼吸。
- `generating`：出纸口缓慢吐出白色纸卷（`clip-path: inset(0 0 100% 0)` → `inset(0 0 0 0)`，2.4s），同时一条 1px 扫描线自上而下扫过，扫描线颜色 `--screen-glow`。
- `done`：纸面显示缩略图矩阵（2×2 小图：历史观测 / 预测 / 回测 / 区间），依次淡入，间隔 120ms。
- 组件下方一行说明文字，`--mono` 11px：**「图表由已校验数据确定性渲染」**。

> **【硬约束】文案诚实性**：当前系统产出的是**确定性渲染的 SVG/PNG 图表**，不是生成式 AI 画图。
> 组件标题写「生成图表」，**不得**写「AI 作画 / AI 生图完成」。
> 预留 `mode: "chart" | "ai-image"` 开关：未来接入真实生图 Provider 时，`ai-image` 模式显示「参数摘要 + 步进进度 + 占位图渐进显影」，此时才允许出现 AI 生图字样。同一组件、两套文案，不新增组件。

### 4.4 邮筒（`Mailbox`）

- 落地式，深青邮筒，投信口上沿加一块小铜牌。
- **发信动画**：信封从主工位桌面上方生成（12×8px 白色矩形 + 两条折线），沿二次贝塞尔曲线飞向邮筒，1.1s，`cubic-bezier(.4,.1,.3,1)`；飞行中顺时针旋转 8deg，落地时投信口闪一下。
- **发送中**：投信口上方 3 圈同心波纹，每圈 0.9s，错开 0.3s 循环。
- **状态反馈**（必须同时有图标形状 + 颜色 + 文字，三重编码）：

| 邮件状态 | 图形 | 颜色 | 文案 | 备注 |
|---|---|---|---|---|
| `sending` | 波纹 | 蓝 `#2A5C8A` | 投递中 | |
| `submitted` | ✓ | 绿 `#2C6E49` | 已提交至邮件服务器（未确认送达） | **不可写「已送达」** |
| `uncertain` | ? | 灰 `#8B959B` | 投递结果未知，需人工确认 | 附 `mail-resolve` 提示 |
| `simulated` | ◇ | 灰 `#8B959B` | 模拟投递，未真实发送 | 不用绿色 |
| `retry` | ↻ | 黄 `#8A6410` | 第 N 次重试 | |
| `failed` | ✕ | 砖红 `#A32D2D` | 投递失败，附错误码 | |
| `skipped` | — | 灰 | 未选择通知 | 安静态，不播放动画 |

## 5. 交互逻辑

### 5.1 主 Agent 状态机

```
idle ──提交任务──> planning ──plan 事件──> working
                                              │
              ┌───────────────────────────────┤
              ▼                               ▼
        dispatching（派发）              reviewing（merge）
              │                               │
              └──────────> writing ───────────┘
                              │
                              ▼
                          mailing ──> done | failed | cancelled
```

### 5.2 调度联动时序 【核心体验】

```
t=0.0s  用户点击「开始分析」
        → P1 鲸长 从 idle 变 working，推进椅子，屏幕亮起
        → 中控看板 第 1 格（校验）亮起

t=1.2s  events 到达 kind=step step=validate status=completed
        → 看板第 1 格转绿，第 2 格（补数）呼吸

t=2.6s  events 到达 kind=adjustment steps=[prediction,risk,advice]
        → 三个子角色头顶同时弹出「收到指令」气泡
        → 中控看板右下角浮出「已派发 3 个协作位」小标签

t=2.9s  events 到达 kind=step step=prediction status=running child_id=...
        → P2 涨潮 从沙发起身 → walking（1.6s）→ 到达 P2 工位 → seated → working
        → 路径：沙发中心 → P2 工位中心，先水平后微调，全程 1.6s
        ※ 三个子角色可能先后到达，允许 0~0.4s 随机错峰，避免机械同步

t=3.4s  events 到达 kind=model role=risk
        → P3 暗流 切 thinking，气泡点闪

t=6.1s  events 到达 kind=step step=risk status=completed summary=["DRAWDOWN_RISK"]
        → P3 变 done，✓ 气泡，1.2s 后回到坐姿
        → 头顶小卡片显示「回撤风险 · 依据 F-03」

t=7.8s  events 到达 step=merge status=running
        → 看板第 4 格亮；主角色切 reviewing（摘下眼镜擦一下，2s）

t=9.4s  events 到达 step=charts status=running
        → 出图台开始吐纸 2.4s，扫描线自上而下

t=11.0s events 到达 step=report status=running
        → 主角色回到 working，桌面便签叠高一张

t=13.2s events 到达 step=mail status=running
        → 信封从 P1 桌面飞出 → 邮筒，1.1s；波纹启动

t=14.5s events 到达 step=mail status=completed
        → 波纹停止，绿勾 + 「已提交至邮件服务器（未确认送达）」
        → 主角色 done，抬头，椅子回正

t=22.0s 场景进入静态陈列：所有循环动画降为 0（仅保留眨眼）
        → 三个子角色若仍坐在工位，8s 后依次起身走回沙发
```

**时序必须由事件驱动，不得用定时器串联。** 上面每个 `t=` 只是便于理解的估计值；实现里只允许「收到事件 → 触发动画」，禁止「动画结束 → 假装收到下一个事件」。

### 5.3 事件 → 视觉映射表

| 事件 | 条件 | 视觉响应 |
|---|---|---|
| `kind=plan` | 任意 | 看板顶部标的一次性淡入；主角色切 `planning` 2s |
| `kind=step` | `status=running`，`step` ∈ {validate, tools, main, merge, report} | 主角色 `working`；看板对应格呼吸 |
| `kind=step` | `status=running`，`step` ∈ {prediction, risk, advice} | **对应子角色 `walking` → `working`** |
| `kind=step` | `status=running`，`step=charts` | 出图台 `generating` |
| `kind=step` | `status=running`，`step=mail` | 信封动画 + 波纹 |
| `kind=step` | `status=completed` | 对应角色 `done`；看板格转绿 |
| `kind=step` | `status=failed` | 对应角色 `failed`；看板格红；顶部窄条显示 `code` |
| `kind=tool` | `status=running` | 主角色桌面的「工具托盘」出现一枚小图标（最多 3 枚，超出按计数） |
| `kind=model` | 带 `role` | 该 `role` 对应角色切 `thinking` 0.9s 后回 `working` |
| `kind=memory` | 任意 | 主角色桌角便签堆加一层（最多 5 层，超出显示 `+N`） |
| `kind=adjustment` | 带 `steps` | 子角色预起身（`dispatched`）；正文文案走滚动条，不进场景 |

### 5.4 人物点击与抽屉

- **点击角色** → 从右侧滑出 320px 抽屉（不影响场景布局，`position: fixed`）：
  - 头部：头像缩略（同款 SVG，48px）+ 代号 + 中文名 + 当前状态胶囊
  - 中段：该角色最近 3 条事件的 `label` + `timestamp`（`HH:mm:ss`）
  - 底部：若角色有 `result`，展示 `conclusions` / `evidence_ids` / `uncertainty` 三行；`evidence_ids` 中的编号可点击，跳转到报告页对应事实卡（`#fact-F-01`）
- **点击工位空白处** → 高亮该角色对应的报告章节（预测→01、风险→05、建议→06），并在抽屉里给一行「查看报告 §05 风险」链接。
- **点击中控看板** → 展开执行时间线（既有 `prototype/` 里的 plan-block），默认收起。
- **键盘**：`Tab` 依次聚焦四个工位（`tabindex=0`），`Enter` 打开抽屉，`Esc` 关闭。抽屉打开时焦点圈闭在抽屉内。
- **悬浮**：`hover` 时角色上浮 1px + 地面投影加深（`opacity 0.10 → 0.16`），不做放大。

### 5.5 空闲与退出

- 无任务时：四个角色都坐在沙发上，主角色偶尔翻一页纸（6s 循环），其余两个眨眼。**不要预演工作动画**。
- 页面 `visibilitychange` 隐藏 → 暂停事件轮询与所有 CSS 动画（给 `.office` 加 `paused` 类，`animation-play-state: paused`）。
- 任务结束后 8s，场景回落为静态陈列；用户再次提交时重置全部状态。

## 6. 进度可视化三件套（统一规格）

### 6.1 统一原则

1. **两级进度**：全局 7 阶段（看板，离散）+ 单角色阶段内进度（工位条，连续）。
2. 单角色进度**不由后端提供百分比**（后端只给 `running/completed`）→ 因此工位条采用**不确定进度条**：一条 30% 宽的亮块在轨道内往复 1.6s，`completed` 时才 `scaleX(1)` 满格并转绿。**严禁显示编造的 `62%`**。
3. 所有进度组件都必须有 `role="progressbar"` 语义与 `aria-valuetext`（例：「预测分析 进行中」）。
4. 动效只改 `transform` / `opacity` / `clip-path`，不改 `width` / `height` / `top` / `left`。

### 6.2 组件清单

| 组件 | 位置 | 形态 | 数据源 |
|---|---|---|---|
| 全局阶段条 | 中控看板 | 7 枚菱形 + 连接线 | `kind=step` 的 `step` 字段 |
| 角色进度条 | 每个工位显示器下沿 | 不确定进度 / 满格 | 该角色 `status` |
| 角色状态气泡 | 角色头顶 | 8px 圆角小气泡，最多 1 个 | `label` 截断 12 字 |
| 出图进度 | 出图台 | 吐纸 + 扫描线 + 缩略图 | `step=charts` |
| 邮件进度 | 邮筒 | 飞信 + 波纹 + 状态图标 | `step=mail` 的 `status` + 任务 `mail` 字段 |
| 预算计数器 | 看板底部 | `00:42 / $0.031` | 任务快照 `usage` |

## 7. 技术实现要点 【硬约束】

### 7.1 文件与构建

| 项 | 要求 |
|---|---|
| 文件数 | 后端不改的前提下只能是 4 个：`index.html`、`style.css`、`app.js`、`memory.js` |
| 构建 | **零构建**。无 npm、无打包、无压缩步骤 |
| 模块 | 不用 `import/export`；用 IIFE + 全局命名空间：`window.Scene`、`window.Actors`、`window.Board`、`window.Stream` |
| 拆分 | 源码阶段可拆多文件开发，交付前按顺序拼接为一个 `app.js`；每个模块首行写 `/* ===== 模块名 ===== */` 分隔注释 |
| 体积 | 交付 `app.js` ≤ 380KB、`style.css` ≤ 120KB（未压缩）。超出则砍装饰、不砍功能 |

### 7.2 SVG 与 CSP

```js
// ✅ 正确：createElementNS 构建
const NS = "http://www.w3.org/2000/svg";
const path = document.createElementNS(NS, "path");
path.setAttribute("d", "M0,0 …");
path.setAttribute("class", "hair-back");   // 样式只走 class

// ✅ 正确：动态位移用 CSS 变量（CSSOM 不受 CSP 限制）
actorEl.style.setProperty("--x", "51%");

// ❌ 禁止：内联样式属性
el.setAttribute("style", "left: 51%");   // CSP 会拦

// ❌ 禁止：含 style 属性的 HTML 字符串
container.innerHTML = '<div style="left:51%">…</div>';
```

- 角色 SVG **一次性构建、常驻 DOM**，切换状态只改 `class` 与 CSS 变量，**不重建 DOM**。
- 四个角色节点挂在同一个 `<svg>` 里（一个 viewBox `0 0 1600 900`），便于共享滤镜与阴影定义；**不要**每人一个 `<svg>`（阴影滤镜会重复计算）。
- 复用 `<defs>` 里的渐变与阴影：`feDropShadow` 每帧开销高，改用「半透明椭圆 + blur」静态阴影，**不做实时滤镜**。

### 7.3 动画性能

| 项 | 要求 |
|---|---|
| 可动画属性 | 只允许 `transform`、`opacity`、`clip-path` |
| `will-change` | 仅加在 4 个角色外层 `<g>` 与出图台纸卷上，**不超过 6 个节点** |
| 帧率 | 场景静止时静止（无 rAF 空转）；有动画时保证 50fps 以上（1500×850 视口、中端集显） |
| 计时器 | 全局**一个** `requestAnimationFrame` 循环，仅用于移动路径插值与节流；其余全部 CSS animation |
| 清理 | 任务结束必须 `cancelAnimationFrame` 并移除临时节点（信封、气泡），不得堆积 |
| 降级 | `prefers-reduced-motion: reduce` → 走路改为瞬移（0ms）、波纹改为静态圆点、扫描线改为静态进度、保留所有文字状态 |

### 7.4 数据层

```js
// 事件消费：游标 + 去重
let after = 0;
async function pump() {
  const r = await fetch(`/api/tasks/${tid}/events?after=${after}`, { headers: { "X-Memory-Key": key } });
  const { events } = await r.json();
  for (const e of events) { after = Math.max(after, e.seq ?? after + 1); Scene.apply(e); }
}
```

- 轮询间隔：任务进行中 **600ms**；空闲 **3000ms**；页面隐藏时**停止**。
- 每个事件必须**幂等**：同 `step + status` 重复到达只生效一次（用 `Set` 记录已消费的 `step:status`）。
- **mock 层必须与真实接口同形**：`prototype/js/mock.js` 已实现 `M.buildTask()`，扩展它产出符合 §1.4 字段的事件序列，保证「换真接口只改 `pump()` 一处」。
- 断线重连：连续 3 次失败 → 场景顶部显示窄条「连接中断，正在重试」，人物保持最后状态不重置；恢复后从 `after` 续拉。

### 7.5 响应式

| 断点 | 行为 |
|---|---|
| ≥ 1280px | 完整场景，人物 100% 尺寸 |
| 1080–1279px | 场景缩放至 88%，隐藏前景绿植与纸箱 |
| 768–1079px | 场景改为**上下两排**：主 Agent 单独一行（居中），三个子角色一行；仍保留走动动画（简化为垂直位移） |
| < 768px | **场景折叠为「值班表」**：每行一个角色 = 40px 头像 + 名字 + 状态胶囊 + 细进度条；不渲染办公室背景与家具。走动动画改为头像左侧的滑动指示条 |

> 窄屏折叠不是「降级偷懒」，是因为 4 个 Q 版角色在 390px 宽度下必然重叠成一团。折叠后信息密度反而更高。

## 9. 可访问性与体验标准

1. **图形不是唯一信息载体**：每个状态都有文字（胶囊/气泡/窄条）。仅靠颜色传达状态视为不通过。
2. **色盲友好**：状态色 + 形状双重编码（✓ / ? / ✕ / ◇ 均为不同轮廓）。
3. **对比度**：场景内文字对背景 ≥ 4.5:1；`#8B959B` 仅用于 ≥ 14px 的次要文字。
4. **焦点可见**：工位聚焦时，桌面出现 2px `--accent` 描边框，`outline-offset: 3px`。
5. **键盘可达**：四个工位 + 看板 + 抽屉关闭按钮均在 Tab 序列内；抽屉内焦点圈闭。
6. **首屏**：≤ 1.2s 出现静态办公区（家具与空工位），人物 SVG 随后 300ms 内淡入；**不允许**首屏空白等待。
7. **不阻塞**：任何动画都不可阻塞表单提交或报告阅读；用户切到报告页时场景可继续在后台跑，但停止渲染（`display: none` + 暂停）。
8. **文案规范（禁止词）**：
   - ❌「已送达」→ ✅「已提交至邮件服务器」
   - ❌「AI 智能预测，准确率 92%」→ 系统无此数据，禁止出现
   - ❌「实时」用于 600ms 轮询 → 用「准实时」或省略
   - ❌「置信度 85%」当上游 `confidence` 为 `null` → 显示「上游未提供」
   - ❌「正在努力生成中」→ 用真实阶段名

## 附录 C · 精简版提示词（可直接投喂）

> 在一个零后端改动、CSP 仅 `'self'`、只允许 `index.html/style.css/app.js/memory.js` 四个文件的原生前端里，实现一个「纸感办公区」主工作台。
> 场景为正面平视的办公室：后墙挂中控看板（7 个离散阶段）、墙挂出图台，地面线上一字排开四个工位（P1 主 34%、P2 预测 51%、P3 风险 68%、P4 建议 85%），左端有沙发待命区和邮筒。
> 只做 4 个人物，全部为同一 Q 版鲸鱼少女家族的拟人化 Agent（深蓝渐变长发、白色蕾丝头饰、鲸鳍耳饰、深蓝连衣裙配白围裙绣小鲸鱼、鲸鱼尾、深蓝小皮鞋），仅以配色与配饰区分：鲸长（金饰、眼镜、P1）、涨潮（青绿、折线发夹）、暗流（砖红、警戒纹）、灯塔（暖金、小圆帽、提灯）。人物坐在工位上敲键盘，双臂、尾巴、眼睑可动。
> 交互按真实事件流驱动：收到 `step=running` 且 `step` 等于某角色名时，该角色从沙发走到自己工位（1.6s 平移 + 上下 bob），落座后开始打字；`completed` 后抬头显示 ✓；`failed` 低头显示错误码；任务结束 8s 后起身回沙发。简单任务不委派时三个子角色保持待命，不得假装工作。
> 进度可视化三件事：每个工位显示器下沿一条**不确定进度条**（后端不给百分比，禁止编造数字），完成后转绿满格；出图台吐纸 + 扫描线 + 4 张缩略图依次显现（文案为「图表由已校验数据确定性渲染」，不是 AI 生图）；邮件从主工位飞出到邮筒，波纹表示投递中，六种状态各有独立图标与文案（`submitted` 只能写「已提交至邮件服务器」，`simulated` 用灰不用绿）。
> 技术：全部矢量内联 SVG，用 `createElementNS` 构建，只用 class 控制样式，动态位移用 `style.setProperty('--x',…)`；动画只改 transform/opacity/clip-path；全局一个 rAF；支持 `prefers-reduced-motion`；页面隐藏停止轮询；窄屏 <768px 折叠为「值班表」行式布局。色彩沿用 `#faf7f0/#16232b/#b44d32` 纸墨体系，暖米墙、木地板、深青桌椅，单一左上光源、单层柔和阴影，禁止霓虹与玻璃拟态。
